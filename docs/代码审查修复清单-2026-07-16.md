### A3. OTA 升级传输中可一键返回、静默中断 DFU ✅
- 问题：升级进度页左上角返回随时可点，点了立即中断升级退出，事后无任何提示；用户误触一下几分钟的升级悄悄作废。
- 已改：`ota.js` 真实升级（非干跑）开始时调用 `wx.enableAlertBeforeUnload`（拦截左上角返回、安卓物理键、侧滑，弹系统确认「正在升级固件，退出将中断本次升级」），`finally` 里（成功/失败/中断）解除拦截。
- 效果：误触返回会先弹确认；主动退出是知情决策。
- 风险/说明：`enableAlertBeforeUnload` 需基础库 ≥2.12.0，已做能力判断（低版本行为同旧版）；切后台（onHide）中断的既有逻辑未动。

### A3b. 投屏传输中同样可一键返回静默中断 ✅
- 已改：`result.js` 传输开始时启用同款返回拦截（「正在投屏，退出将中断本次投屏」），`finally` 解除。
- 效果：批量投屏传一半不会被误触返回悄悄打断。

### A4. 图库/投屏记录列表图片无 lazy-load ✅
- 问题：两页 `<image>` 不加 lazy-load 时进页面即并发加载全部（最多 100 张）图片并解码，低端机卡顿/白块。
- 已改：`album/list.wxml` photo-img、`records.wxml` thumb-img 各加 `lazy-load`。
- 效果：只加载视口内及邻近的图片，滚动时增量加载；首屏请求数从最多 100 降到十几个。
- 风险：≈0（组件原生能力）。「无缩略图回退原图」与分页需后端配合 → 见 D4。

### A5. OTA 连接失败路径不释放 BLE 连接 ✅
- 问题：`ota-ble.js` 连接建立后若 FF10 服务发现/开通知失败直接抛错，连接未关闭也未登记进会话，无人能清理；设备是单连接、被占后不广播——表现为「OTA 失败一次后设备再也搜不到」，需重启蓝牙恢复。device-ble.js 同款问题此前已修，OTA 侧漏了。
- 已改：与 device-ble 对齐——① `createConnectionWithRetry` 每次失败后 best-effort `closeBLEConnection`；② `ensureOtaConnection` 把「服务发现→会话落表」整段抽为 `buildOtaSession` 并 try/catch，失败即关连接再抛。
- 效果：OTA 失败后设备立即恢复广播、可直接重试。
- 风险：低。若失败时该连接同时被 FF00（图传）会话持有，会被一并断开——onBLEConnectionStateChange 会让 device-ble 正常清理，状态一致，属可接受的保守行为。

## B 组 · 中优先（待确认）

### B1. 401/406 登录过期处理不彻底
- 位置：`utils/request.js:291-294`（现只 `removeStorageSync('token'/'userInfo')`）。
- 为什么：`globalData.token/userInfo` 未清，`requireLogin()` 判的是 globalData（app.js:157/174），过期后依然放行，每个请求反复弹「登录已过期」，用户卡死在假登录态；失效身份数据仍驻留内存被页面展示。
- 怎么改：改调 `getApp().clearSession()`（app.js:209 已有，同时清 globalData/selectedDevice/Storage）+ 节流跳转登录页（当前已在登录页则跳过，防循环；多请求并发 401 需去重）。
- 效果：过期即整体登出、引导重登。风险：低。

### B2. 并发扫描互相打断 + 监听器永久泄漏
- 位置：`utils/bluetooth.js:5`（模块级单例 `foundHandler`）、`:144-154`、`:259`。
- 为什么：两路扫描并发时第二次覆盖单例，先结束的一路 `offBluetoothDeviceFound` 解绑的是对方的回调，自己的永久残留（闭包持有页面实例，随扫描次数累积泄漏）；同时 `stopBluetoothDevicesDiscovery` 会停掉共享硬件扫描把另一路饿死，表现为偶发「未搜索到该设备」。`isDiscovering()` 全仓无调用方，注释里说的互斥实际不存在。
- 怎么改：① handler 局部化，finish/fail 时解绑自己的局部引用；② 入口检查扫描中则复用在途扫描（返回同一 Promise）。
- 效果：并发扫描不再互相打断、回调不泄漏。风险：低，纯内部重构。

### B3. 「点连接反而断连」竞态（verifyReuse 误杀健康连接）
- 位置：`utils/active-device.js:254-266`；根因 `utils/device-ble.js:462-463`（同 cmd 并发直接抛「指令 0x… 正在等待应答」）；触发点 `detail.js:350`（onShow 无重入保护地 readDeviceInfo）。
- 为什么：详情页 onShow 的 BLE 0x01 读在途时用户点「连接」，复用校验读不动就当死会话断开——但「正在等待应答」恰恰证明连接活着且正忙；被误杀后设备恢复广播需要时间，6s 窗口内可能扫不到，体验倒退。
- 怎么改：device-ble 抛该错误时附 `error.code = 'CMD_PENDING'`（避免字符串匹配脆弱），verifyReuse catch 里识别到即按「会话活着」直接复用返回；顺带给 `detail.js loadDetail` 加在途去重标志。
- 效果：消除「点连接反而断连再重扫」。风险：低。

### B4. 三个列表页把「加载失败」伪装成空态、无重试入口
- 位置：`subpackages/device/list/list.js:57-60`、`subpackages/projection/records/records.js:62-65`、`subpackages/album/list/list.js:135-139`（catch 后只 `loading:false`，落到「暂无 XX」文案）。
- 为什么：弱网时用户看到「暂无照片/暂无设备」以为数据被清空；除退出重进无任何重试手段。详情页/轮播页已有 `loadError` + 「重新加载」现成样式（detail.wxml:384、slideshow.wxml:44）。
- 怎么改：三页照搬 loadError 分支：失败时空态卡片显示「加载失败 + 重新加载按钮」。
- 效果：失败与真空态区分清晰、一键重试、全站体验统一。风险：低。

### B5. 操作前自动重连失败一律提示「请先连接设备」
- 位置：`utils/active-device.js:294-309`（`ensureConnectedForAction` 的 catch）。
- 为什么：用户点轮播设置/继续投屏 → 看着「连接设备中」转 6 秒 → 弹「请先连接设备」，与用户行为矛盾且不可操作；真实原因（未搜到/超时/权限被拒）已生成却被吞。同链路 `showConnectError`（:284-290）就是如实展示的。
- 怎么改：catch 里复用 `showConnectError(error)`，保留 PERMISSION_DENIED 的系统设置引导。
- 效果：失败原因具体可执行，三处连接入口口径统一。风险：低。

### B6. 报错 toast 停留时长不符合约定（3s vs 约定 5s）

### B8. 密码强度零校验

### B10. onShow 全量重拉（含详情页每次 BLE 读）

## D 组 · 需后端/多端/产品配合，确认后再动（勿单方面修改）

### D1. 密码无盐 MD5（安全上最重要，需立项）
- 位置：`api.js:669-670`（`md5(password)` 32 位小写无盐）；md5.js 注释确认是后端约定。
- 为什么：MD5 无盐可被彩虹表秒破；若后端按值比对，md5 值本身即等价密码（pass-the-hash），日志/拖库泄露即可直接登录。
- 怎么改：后端改 bcrypt/argon2 存储（传输靠 TLS），Flutter 登录链路同步，存量密码迁移策略；小程序端只改 api.js 一处。
- 风险：高（多端协同+存量迁移），端上改动极小。

### D2. token 明文拼进所有 /Client/ 接口 URL
- 位置：`request.js:137-139`（query.userToken）+ `:351`、上传 `:466/:501`；同一 token 同时走 header.userToken 和 Authorization Bearer，一令牌三路。
- 为什么：URL 会进服务端/网关/CDN 访问日志，能读日志即可劫持会话（HTTPS 不保护落盘日志）。
- 怎么改：与后端确认鉴权只读 header 后，删 `getClientQuery` 里的 query.userToken。**贸然删可能全站 401，必须先确认、建议灰度。**

### D3. sendEmail 免鉴权（`api.js:287` `auth: false`）
- 为什么：发码接口可被脚本刷（邮件轰炸），前端 30s 倒计时不构成防线；绑定/修改邮箱场景用户已登录，无必要免鉴权。
- 怎么改：确认后端带 token 行为不变后去掉 `auth: false`；推动后端按用户+邮箱限流。

### D4. 图库禁止回退原图 + 分页
- 位置：`api.js:174`（imgThumb 缺失回退原图 img）、`api.js:821-828`（pageSize:100 一次拉完）。

### D5. preview 导出 2000px 与结果页再压 720px 重复压缩
