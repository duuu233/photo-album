  ### 1 · 微信同声传译插件（语音转文字）
  `app.json` 声明插件 `WechatSI`（`provider: wx069ba97219f66d99`, `version: 0.3.5`），

  ### 2 · 下载/投屏一律提示「图片过期」——真正原因不是过期
  两条独立原因叠加，与图片有没有过期无关：
  1. **接口回的是 `http://` 地址**（见 API 文档 §四 images 示例），而 `wx.downloadFile` **只认 https**。
     聊天里图片看得见是因为 `<image>` 组件能显示 http 图，`downloadFile` 不能 —— 症状「能看不能下」正对应这个。
     → 新增 `toHttpsUrl()` 自动升级协议。
  2. **`downloadFile` 的 `success` 只代表请求完成**，404/403 也会走 success。原代码不看 `statusCode`，
     会把一份错误页当图片存进相册 / 送去投屏。→ 统一走新的 `downloadAiImage()`，校验 `statusCode === 200`。
  - 顺带把错误文案分清楚（`describeDownloadFail`）：域名没配 / 超时 / 真过期(403,404) 各说各的，
    原先两处都硬写「图片过期」，把配置问题误报成过期，排查会被带偏。
  - 下载与投屏现在共用 `downloadAiImage()` 一处实现（原先两处各写一遍 `wx.downloadFile`）。
  - 🔴 **另一半必须在小程序后台配**：「开发管理 → 服务器域名 → **downloadFile 合法域名**」加上图片所在
    OSS 域名（`https://inkstar.oss-ap-southeast-1.aliyuncs.com`）。⚠️ 开发者工具勾了
    「不校验合法域名」时**看不出这个问题**，真机才暴露 —— 很可能就是本次报障的现场。
  - 投屏流程本身**无需改**：需求文档「已连接直接进 / 未连接弹已绑定设备列表选择后自动连接」
    与现有实现一致，坏的只是取图这一步。下载保存相册也已是原有行为，同样只是取图坏了。

  ### 4 · 按住说话（仿微信）
  需求文档原文是「支持长按输入框区域**或**专属语音按钮」，两个入口都做了，共用同一套 `onVoice*`：
  - **🎤 专属按钮** → 切到「按住说话」条，按住录音；
  - **长按输入框区域** → `onInputTouch*` 挂在输入框**外层 view** 上，用 `bind`（不是 `catch`）：
    短按照常穿透给 `<input>` 聚焦打字，按住超过 `INPUT_HOLD_MS(350ms)` 且位移 < 10px 才起录音。
  - 手势与微信一致：**上滑超过 `VOICE_CANCEL_DY(80px)` → 浮层转红「松开取消」**，松手丢弃；
    否则松手把识别结果**直接发送**（文档 §5.1.2「按住说话，松手直接发送」）。
  - 浮层实时显示 `onRecognize` 的**中间识别结果**，用户能确认「确实听到了」（主流 AI APP 的做法）。
  - ⚠️ `.voice-overlay` 必须 `pointer-events: none` —— 它铺满全屏，不让出触摸的话浮层一出现就把
    `touchmove/touchend` 抢走，松手事件收不到，会**永远卡在录音态**。
  - `sendVoiceText` 发不出去时（未建成会话/正在发送/图片还在传）把识别文字**回填输入框**，
    不让用户白说一遍——重说一遍的代价比重打一遍高得多。
  - `toggleVoice` / `onUnload` 都会把在途录音按取消收掉，避免麦克风一直占着、回调打在已销毁页面上。

     `createNew()`（真·点新建）仍发 `{newSession:true}` 不变。
