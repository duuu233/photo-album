# 星币不足弹窗：显示当前余额 + 「去充值」

> 日期：2026-09-18
> 范围：`subpackages/ai/chat`（弹窗）、`utils/ai-token` 的读取口径
> 相关：`docs/architecture/ai-client.md` §星币闸；App 侧同日同口径已改

## 需求

产品原话：「『星币不足…』这个弹框要优化一下，**先在合适的位置显示一下当前用户剩余的星币**，
再就是在『我知道了』按钮的右边加一个按钮『去充值』，点击跳转充值页面。」

## 改了什么

1. **弹窗里多一条「当前余额 N 星币」**（`.confirm-balance`，跨两列通栏摆在说明文字下面、按钮上面）。
   数字绑 `tokenBalanceText`——WXML 里调不了函数，所以在 `data` 里备一份现成文案，
   与 `tokenBalance` **一起 setData**，读不到时是 `--`。
2. **右边那颗按钮文案 `去购买` → `去充值`**。⚠️ 这一颗**本来就在**（2026-08-12 那轮加的），
   去处也没变（`/subpackages/token/index/index` 星币管理页，套餐购买就在那一页上）；
   改的只有文案，为的是和 App 端新加的那颗对齐。
3. **余额读不到时不再把数字抹掉**（`refreshTokenBalance`）：`aiToken.refreshBalance()` 在接口失败时
   返回 `UNKNOWN_BALANCE`，原来照写不误。以前没人看见这个字段，现在它摆在弹窗上，
   抹掉的代价从「没人看见」变成「用户以为自己一分不剩」。

## 为什么是这个位置

弹窗本来就是「图标 + 标题/说明 + 两颗按钮」的两列网格。余额条跨两列（`grid-column: 1 / 3`）
摆在说明下面：和说明文字左沿对不齐反而更显眼，也不会把两颗按钮挤到第二屏。
底色取品牌橙 6%、数字 28rpx/700 橙色——它是这张弹窗里用户唯一要「读数」的地方。

## 追加：「去充值」直达套餐确认（同日，产品追加口径）

产品看完第一版后定：**跳到套餐确认**，别让用户在星币管理页再点一次「立即购买」。

改法是**两跳**，不是直接跳确认页：

```
AI 聊天页 → /subpackages/token/index/index?buy=1 → （拉完套餐）→ /subpackages/token/confirm/confirm?id=…
```

- ⚠️ **确认页要一个具体的 `id`**：`confirm.js` 的 `loadPackage` 找不到那一档就当场
  「套餐已失效，请重新选择」+ `navigateBack`。套餐列表在星币管理页拉，所以由它来推。
- ⚠️ **返回栈里留着星币管理页**：用户想换一档，退一步就能换；直接跳确认页的话退出去就是聊天页，
  换档没有入口。
- ⚠️ **标记只认一次**（`_autoConfirm`，在 `onLoad` 里读 `buy=1`）：本页是 **onShow** 重拉的，
  不消费掉的话用户从确认页退回来会被又一次推进去，退不出这一页。拉套餐失败也要消费掉。
- 拉不到套餐就停在星币管理页：余额和消耗规则照样看得见，比推进一个没有套餐可确认的页面强。

跳的是**默认选中那一档**（`selectedId`，没选过时是设计稿高亮的第二档／有赠送的主推档）。

## 与 App 端的一致性

App 侧同日同口径已改（弹窗正文下面同样一条余额带、右键「去充值」直达星币管理页）。
🔶 有意差异：**iOS 不画那颗按钮**——那一端整块星币模块是藏起来的
（`StarPayType.moduleHiddenOnThisApp`，2026-09-18 用户口径），跳过去是一片空白。
小程序不分平台，两颗按钮都在。

## 验证

`node tests/*.test.js` **60 个文件全过**（真跑）。`tests/ai-dialogue-guard.test.js` 新增两条：

- 弹窗弹出来时 `tokenBalanceText` 跟着账户接口走（桩给 0 → 显示 `0`，而不是初始的 `--`）；
- 账户接口失败时 `tokenBalance` / `tokenBalanceText` **保持上一次的数字**。

新增 `tests/token-auto-confirm.test.js`（4 条）：带 `buy=1` 加载完套餐就跳确认页且带默认档的 id、
重拉不再跳第二次、没带标记不自己跳走、套餐拉不到时停在本页且标记已消费。

⚠️ 未在开发者工具 / 真机上看过版式（余额条与按钮行的间距按 rpx 直接换算），
也没真机走过「去充值 → 确认页 → 退回」这条动线。
