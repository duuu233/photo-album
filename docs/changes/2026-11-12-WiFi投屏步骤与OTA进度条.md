# 2026-11-12 WiFi 投屏进度页加步骤、去掉投屏日志面板；WiFi 固件升级页加进度条

> 分支：`main`｜依据：产品需求（投屏进度页按进度文案加四步，样式与交互同配网步骤；去掉投屏页下方的黑底投屏日志）；服务端 OTA 进度口径（`GET /api/device/ota/status` 与 WS `ota.result` 新增 `progress`）

## 一、WiFi 投屏结果页（`subpackages/projection/wifi-result`）

### 投屏步骤

进度条卡片下方新增一张步骤卡，四步对应进度文案：

| 步骤 | 何时进行中 | 何时打勾 |
|---|---|---|
| 1 准备投屏 | 进页 / 重试开始，取产品屏幕方向、渲染模式 | 开始上传第一张 |
| 2 图片上传中 | `projectOne` 报 `UPLOADING` | 进入处理阶段 |
| 3 图片处理中 | 报 `PROCESSING`（上传完、接口未返回） | 接口返回 `SENT` / `UPLOADED` |
| 4 已发送，屏幕即将刷新 | — | 接口返回 `SENT` / `UPLOADED` 即打勾（写相册记录不另占一步） |

- 样式与交互同配网状态页：未开始白圈序号、进行中橙色转圈、通过橙色实心勾、失败红色实心叉，失败后后续步骤不再执行。不同分包不能互相 `@import`，样式在 `wifi-result.wxss` 照搬一份（`.cast-steps` / `.cast-step`，转圈动画 `castStepSpin`）。
- 失败：在当时那一步打叉（上传失败第 2 步、处理 / 下发失败第 3 步；投屏信息失效第 1 步）；逐张记下 `failStep`。
- 多张：步骤跟着正在投的那一张走，每张从「图片上传中」重新开始；结束后全部成功四步全勾，有失败按最后一张失败的那一步打叉。

### 去掉投屏日志面板

页面下方的黑底「投屏日志」（开发版 / 体验版显示、可复制）整块去掉，连同 `copyLogs`、`logs` / `showLog` / `logAnchor` 与 `.projection-log*` 样式。页面自己记的设备尺寸 / 旋转字段、每张图信息、相册记录过程改打控制台 `[WiFi投屏]`，`projectOne` 不再传 `onLog`（它本身就打控制台）；开发版 / 体验版用左下角「日志」浮窗查看、复制。每张图像素与大小仍只在开发版 / 体验版读取。

## 二、WiFi 固件升级页（`subpackages/device/wifi-ota`）

步骤卡上方新增进度条卡：左边是当前那一步的步骤文案（已下发，等待设备响应 / 设备下载固件中 / 设备写入固件中 / 升级完成），右边百分比。

接口：`GET /api/device/ota/status` 与 WS `ota.result` 新增可选 `progress`（0~100）——设备私有进度回执 182 / 184 / 186 / 188 换算为 20 / 40 / 60 / 80，WS 每收到一条回执推一次；进入 `VERIFYING` 后为 100；固件不上报进度时为 `null`。

显示规则（`utils/wifi-ota.js` 的 `progressCap`）：显示值只增不减、匀速前进（每 200ms 走 1%，一档 20% 约 4 秒），服务端进度只抬「上限」，走到上限就停住：

| 情况 | 上限 |
|---|---|
| 还没收到任何进度（SENT，等设备响应） | 19 |
| 收到 20 / 40 / 60 / 80 | 39 / 59 / 79 / 98（下一档减 1；例：走到 39 没收到 40 停住，收到 40 继续） |
| 已进入下载（DOWNLOADING）但一直没进度值（固件不上报，`null`） | 98 |
| 已进入写入（FLASHING） | 98 |
| VERIFYING（SUCCESS 同） | 100 |
| FAILED / TIMEOUT | 停在当时的位置，进度条转红 |

- 只认收到过的最大进度：收到过数值后偶发的 `null` 不会把上限放到 98。
- WS 只带 `progress`、没带 `status` 时沿用最近一次状态。
- 收到过的最大进度写进本地记录 `ota_inflight:{deviceNo}` 的 `progress`（`refreshInflight` 与页面都写），重进页面从那里接着走。
