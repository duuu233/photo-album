# 2026-10-28 WiFi版投屏带产品渲染模式 renderMode

> 分支：`main-wifi`｜依据：产品口径——后台产品配置新增必选「渲染模式」`renderMode`（`esp32` / `fpga16`，仅 wifi 版），小程序从产品接口取该字段，原样传给 `POST /api/device/play`

## 做了什么

- `api.resolveRenderMode(device)`（新增）：取当前设备所属产品的 `renderMode`，不抛错。
  - 设备记录自带就用（`getUserProductDetail` 下发，WiFi 详情 / 轮播设置页的设备来自它）；
  - 设备列表接口（`getUserProductList`）不带该字段，首页、图库、AI 对话、投屏记录等入口交来的设备按 `productId` 查产品列表（`getProductList`，会话缓存，最多等 3 秒）；
  - 仍没有再按设备ID（去冒号）查 `getProductByDevice`；
  - 都取不到返回空串。
- `iot-api.play`：新增 `renderMode` 选项，有值才在 multipart 里带 `renderMode`，原样传；空不带。
- `wifi-projection.projectOne`：透传 `renderMode`，投屏日志的概要行与参数行有值时记上。
- WiFi 投屏结果页：首轮投屏前按设备取一次，日志记「渲染模式 renderMode=…」（取不到记「产品未配置，不传」），每张（含只上传的）都带，重试复用不再查。
- 轮播设置页：保存后立即投第一张时同样带上。

## 需注意

- 取不到 `renderMode` 时不传，由服务端按默认处理；没有在前端拦截投屏。
- 产品列表是会话缓存：后台中途改了某产品的渲染模式，小程序重进后才拿到新值（设备记录自带的值除外）。
