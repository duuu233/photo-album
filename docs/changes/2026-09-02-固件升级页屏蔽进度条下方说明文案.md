## 一、需求

固件升级进行中这一屏，进度条下面那行文案屏蔽掉 —— 就是形如
`传输中：1234/56789 字节（12/345 包）` 的那一行。

## 二、那行是什么

它是 `ota-ble.js` 在每个协议节点 `emit(onProgress, { …, message })` 带上来的**诊断说明**，
共 11 处，除了传输中的字节/包数，还包括「准备固件包」「连接 OTA 服务(FF10)」
「握手中（MTU 247）」「发送 128 字节头信息，等待电子纸设备校验头部」
「头信息未通过，重发第 N 次…」「数据已发完，发送结束包(0xF3)…」等。

页面把它接到 `data.progressText`，由 wxml 的 `.progress-note` 渲染在百分比进度条与
两条升级规则之间。**本次连整行一起屏蔽**（不是只挡「字节」那一种）：这些说明都是同一类
排查用信息，留一半反而让用户在「传输中」和「握手中」之间猜。

## 三、改法

| 文件 | 改动 |
| --- | --- |
| `subpackages/device/ota/ota.wxml` | 摘掉 `<view class="progress-note">`，原位留注释说明屏蔽原因与恢复方式 |
| `subpackages/device/ota/ota.wxss` | `.progress-note` 规则**整块注释保留**（间距 24rpx 等值不用重新试） |
| `subpackages/device/ota/ota.js` | `progressText` 退出 `data`：`data` 声明 + 5 处 `setData`（检测版本/自动开始/连接中/升级中/结论画面）里的该字段一并删掉 |
| `tests/ota-screen-rules.test.js` | 新增第 ③ 节按结构锁住 |

**底层一字未动**：`ota-ble.js` 照旧 emit `message`，`onUpgradeProgress` 照旧把它算出来并打进
阶段日志（`[OTA页] 进度阶段 → transferring（固件传输中）{ 百分比, 说明 }`）——
真机排查「卡在哪一段」全靠这条，界面不给看不等于日志也不留。

⚠️ 顺带的一个好处：`progressText` 同时退出了进度回调的**去重条件**。原来三个展示值
（百分比/标题/说明）任一变就 setData，而说明里带着字节数、**每个窗口 ACK 都在变**，
于是「百分比没动、只有字节数在动」的那些回调会白刷一次 setData；现在只比百分比与标题，
这类回调直接被挡在 `return` 上，进行中这一屏的 setData 次数只少不多。

⚠️ 版式上这行没了之后，两条升级规则会**上移约 60rpx**（原说明的 24rpx 上边距 + 一行文字）。
`.progress-rules` 自己的 `margin-top: 40rpx` 与安全区留白没动，视觉上是「百分比 + 进度条 +
两条规则」更紧凑，不会出现空档。

## 四、回归
