# 2026-11-13 WiFi 投屏幂等键 Idempotency-Key

> 分支：`main`｜依据：服务端投屏去重幂等口径（Header `Idempotency-Key`，按 deviceNo + 键去重 10 分钟，失败不缓存；新增错误码 4090）

## 现状结论（改之前确认）

`POST /api/device/play`（`wx.uploadFile`）没有自动网络重试，只有 GET 会静默重试 2 次；唯一会再次发送的是结果页「重试未成功的」（用户手动）。弱网超时、服务端其实已处理时，重试会重复投屏——幂等键就是为这个场景。

## 规则

- **批量投屏每张图各生成一个新键，绝不整批共用一个**（一次请求一张，服务端按 deviceNo + 键隔离）。
- 「重试未成功的」：同一张图、同样的刷屏方式复用原键（服务端失败不缓存，原键重试会重新处理；已处理过的拿回旧结果、不重复投屏）。
- 同一张图刷屏方式变了（原本只上传 `refresh=false`，重试时成了本轮最后一张要刷屏）换新键，否则会拿回「只上传未刷屏」的旧结果。
- 新进入结果页（含「继续投屏」重定向回来）是新操作，键全部重新生成。
- 4090 = 同一键的首次请求还在处理中：提示「处理中，请稍后重试」，再点重试复用原键。

## 改动

- `utils/wifi-projection.js`：`newPlayKey()`（UUID v4 形状，随机 + 毫秒时间戳，36 字符；小程序没有 `crypto.randomUUID`）；`projectOne` 透传 `idempotencyKey` 并记日志。
- `utils/iot-api.js`：`play` 有键才带 Header `Idempotency-Key`，不放进表单字段。
- `utils/iot-errors.js`：登记 4090「处理中，请稍后重试」（可重试）。
- `subpackages/projection/wifi-result/wifi-result.js`：本页按 `序号:refresh` 记键（`_playKeys`），每张图取或生成自己的键。
