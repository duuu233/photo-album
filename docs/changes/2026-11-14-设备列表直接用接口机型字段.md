# 2026-11-14 设备列表直接用接口的 productId / broadcastId

> 分支：`main`｜依据：后端 `/Client/UserProduct/getUserProductList` 每条记录已补 `productId`（同详情接口）与 `broadcastId`（同产品列表 `getProductList` 里该产品的值，如 `EF6-370`、`EC-370`、`IJ_*`）。

- 原来：列表不带这两个字段，`getDevices` 要先等产品列表（最多 3 秒），再给每台设备调一次详情接口拿 productId 查机型（最多再等 3 秒），首页 / 我的设备 loading 跟着变长。
- 现在：`api.getDevices` 只调列表接口，设备图（EB-169 圆屏、EC-370 长方屏）、蓝牙版照片容量、WiFi 投屏取渲染模式用的 productId 都直接用记录自带的字段。
- 删掉的逻辑：
  - 设备列表等产品列表、按 productId 回填 broadcastId；
  - 认不出机型时逐台调详情接口补（`withDetailBroadcastId`）；
  - 同日加的产品列表本地缓存（`product_catalog_cache`）与详情补机型本地缓存（`device_broadcast_id_cache`），产品列表回到会话内缓存。
- 保留：设备详情接口不带 `broadcastId`，`getDeviceDetail` 仍按 productId 回查产品列表补（记录自带就不动）；投屏渲染模式 / 屏幕方向、绑定选产品照旧用产品列表。
- WiFi版 / 蓝牙版仍只按 `versionType`，见《按 versionType 认 WiFi 版》。
- `tests/device-thumb.test.js` 改为锁新口径（列表不调产品列表 / 详情；详情按 productId 回查）；删除 `tests/product-catalog-cache.test.js`（缓存逻辑已撤）。本机无 node，未运行、未在开发者工具或真机核对。
