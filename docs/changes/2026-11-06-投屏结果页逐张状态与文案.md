# 2026-11-06 投屏结果页：蓝牙版批量逐张状态、图传卡住文案、WiFi 版列表文案与缩略图

> 分支：`main-wifi`

## 1. 图传卡住的提示

蓝牙图传卡住时，`device-ble` 抛出的原文是「图传中断：电子纸设备停在已接收第 N 包不再前进（已自动退让到窗口 … / 每包间隔 …ms 仍无推进）。可能电子纸设备忙或处理不过来。当前 MTU=…、每包 … 字节」，原样显示在失败页 / 部分成功说明里，用户看不懂。

蓝牙版结果页 `classifyFailureMessage` 新增一条：命中「图传中断 / 不再前进 / 处理不过来」就提示 **「电子纸设备忙或处理不过来，请重新尝试」**。排在「未连接」判断之后（此时链路已断就仍提示未连接）。原文照旧打在 console 的「原始错误」里；`device-ble` 的报错内容不变。

## 2. 蓝牙版批量投屏逐张状态

仿 WiFi 版结果页，在蓝牙版结果页（`subpackages/projection/result`）加逐张列表，**只在多张时显示**，单张界面不变：

| 状态 | 文案 | 时机 |
| --- | --- | --- |
| pending | 等待投屏 | 初始 |
| processing | 处理中 | 开始出帧 + 建记录（含与上一张图传并行的预取） |
| sent | 已发送 | 帧已就绪，排队等蓝牙 |
| transferring | 传输中 | 蓝牙图传 |
| done | 投屏完成 | 本张写入设备成功 |
| failed / aborted | 投屏失败 / 已中断 | 出错 / 中断的那一张 |
| skipped | 未投屏 | 出错后没再投的 |

- 状态只往前走，作废重取的旧预取不会误标「已发送」。
- 进度条与原来一致（标题「图片处理中」→「图片传输中」、每张 0→100）；列表在进度条下方，结束后留在结果卡片下方。
- 缩略图用原图 `_origSrc`（预览页没处理过的就是图片本身），与「我的上传」同方位；投屏用图已按设备旋转角转过，竖向 180° 的机型直接显示会是倒的。
- 行样式同 WiFi 版（缩略图 + 第 N 张 + 状态）：进行中橙色、完成绿色、失败 / 中断红色、未投屏灰色。
- 投屏逻辑（取帧、预取、槽位、回滚、收尾刷屏、成功 / 失败判定）不变。
