# 2026-11-13 固件强制升级 / 强提醒升级判断

> 分支：`main`｜依据：产品口径（WiFi 版在线时判断、蓝牙版已连接时判断；详情页判强制与强提醒，设备列表页、首页只判强制）

## 规则

| 场景 | WiFi 版（在线才判） | 蓝牙版（已连接才判） |
|---|---|---|
| 设备详情页 | 进入后判断一次；点功能按钮再判断（强制 + 强提醒） | 同左 |
| 设备列表页 | 「投屏」「轮播设置」（只判强制） | 「投屏」（只判强制） |
| 首页 | 「拍照投屏」「相册投屏」（只判强制） | 同左 |

- **强制升级**：弹框「立即升级 / 取消」。可以取消，但这次操作不继续；再次点击或再次进入触发判断的场景会再弹。
- **强提醒升级**（只在详情页）：弹框「立即升级 / 取消」，取消后操作照常继续。
- 立即升级都跳升级页：蓝牙版进 `subpackages/device/ota`（`auto=1` 自动开始，先把这台连同当下连接设为选中设备），WiFi 版进 `subpackages/device/wifi-ota`。这次操作不再继续。
- 升级方式：`api.normalizeDevice` 归一后的 `updateType`——先认详情出参 `compulsory`（swagger 字段名，与 App 版本接口同名：1 强制 / 2 强提示），再兜底原来猜测的 `updateType` / `upgradeType` / `forceType`；`1` = 强制升级，其它 = 强提醒升级。
- 有没有新版本与详情页「固件升级」行红点同一套判定：WiFi 版为 IoT `firmwareVersion` 对比 `newVersionNo`（`wifiOta.evaluate` 为 available），本地有进行中的升级记录不弹；蓝牙版为 0x03 当前版本对比 `newVersionNo` 且下载地址是有效 `.bin`，读不到版本时退回后端 `isUpdate`。
- 查询失败（接口 / 网络 / 蓝牙读不到）一律放行。

## 实现

- 新增 `utils/firmware-gate.js`：`decide`（判定）、`prompt`（弹框，返回这次操作是否继续）、`wrapActions`（详情页按钮先判断再执行；不用弹时同步执行原方法）、`guardAction`（列表页 / 首页现查：WiFi 查 IoT 设备信息，蓝牙用本次连接登记的版本、没有再读 0x03，再静默查一次详情接口拿 `newVersionNo` / `updateType`）。
- 蓝牙详情 `subpackages/device/detail`：重命名、轮播设置、一键清空先判断；投屏在连上之后、弹拍照 / 相册之前判断；加载完（已连接）判断一次，进页未连接则在本页连上后判断一次，回到本页不再弹。判定用红点结果 `firmwareHasUpdate`。
- WiFi 详情 `subpackages/device/wifi-detail`：投屏、轮播设置、设备信息、消息中心、TF卡、共享设备、一键清空先判断；第一次拿到设备状态时判断一次（在线才弹）。判定用红点结果 `otaHasUpdate`。
- 详情页不判断的按钮：连接 / 断开、固件升级行、解除绑定、删除设备、重新加载。
- 设备列表 `subpackages/device/list`：蓝牙「投屏」在连上之后判断（未连接时自动连上后照样判）；WiFi「投屏」在离线等拦截之后判断；WiFi「轮播设置」在本地模式提示之后判断。
- 首页 `pages/home`：`ensureCanProject` 最后一步——WiFi 版确认在线之后、蓝牙版连上之后判断。
- `api.normalizeDevice` 升级方式先读 `compulsory`；`api.getDeviceDetail` / `getUserProductDetail` 新增可选 `options` 透传请求层（判断时用 `showError: false` 静默查询）。
- 撤掉 `app.js` 启动时的强制升级弹窗（原「稍后 = 关闭小程序」，且不看设备在线 / 已连接，与新口径冲突）。
