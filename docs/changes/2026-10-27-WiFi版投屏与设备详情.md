# 2026-10-27 WiFi 版投屏（STEP 3）与 WiFi 设备详情

> 分支：`main-wifi`；修改前：20b688e。依据：[前端对接文档_草稿.md](../前端对接文档_草稿.md) 第一、二节（v0.27 正文）+ [前端评审回复.md](../wifi/前端评审回复.md)（v0.32 已落实：投屏去掉 `userNo`、初始状态统一 `SENT`、`play.result` 带 `result`/`reason`、TIMEOUT 60 秒）。

## 投屏链路

```text
我的设备 / WiFi 详情「投屏」→ 拍照 / 相册 → 预览页构图（同蓝牙版，按设备 width/height 导出物理分辨率）
  → 预览页认出 WiFi 版（broadcast-match.isWifiDevice）：不预热、不要蓝牙句柄，redirectTo WiFi 投屏结果页
  → 逐张 utils/wifi-projection.projectOne
```

`projectOne` 一张图：

1. `POST /api/device/play`（multipart：`deviceNo` 12 位不带冒号、`type`、`file`；`userNo` 由服务端从 token 解析，不传），`wx.uploadFile` 超时 60 秒（文档要求 ≥30 秒），不重试（避免重复投屏）。进度条 = 真实上传进度。
2. 上传到 100% 未返回：「图片处理中」；返回 `SENT`（兼容旧版 `DOWNLOADING`）→「指令已下发，等待设备」；返回 `FAILED` → 直接失败。
3. 上传前就订阅设备 WS 并按 `msgid` 缓存 `play.result`（事件可能早于 HTTP 响应）；之后每 3 秒查 `GET /api/device/play/status` 兜底，WS 到事件提前醒；WS 重连成功立即补查。阶段只进不退：DOWNLOADING「屏幕即将刷新」→ FLASHING「设备刷屏中」→ 终态。
4. TIMEOUT 先等 3 秒修正窗口，再查一次；迟到的成功（`corrected=true`）直接算成功、不提示变更。
5. 客户端兜底 90 秒（服务端 60 秒）仍无终态 → 最后查一次，仍无则「结果未知」；`4044` 为「任务已过期，结果未知」。
6. 失败原因按 `reason` 翻译（下载失败 / 存储异常 / 设备处理失败）；接口错误码文案沿用 `utils/iot-errors.js`（4130 图片过大、4041 离线、429、503、5001~5003 等）。
7. 只退订本次自己订阅的设备。

`type` 与蓝牙版抖动出帧同口径（`dithering.typeForDevice`：480×720 为 1，其余 0；评审回复 8.1）。

WiFi 投屏结果页（`subpackages/projection/wifi-result`）：当前图、阶段文案、上传进度条与百分比（运行中）、多张时「第 n / N 张」与逐张结果列表；多张按顺序一张走完再投下一张。结束：全部成功只给「完成」；否则「重试未成功的」（主按钮）+「完成」（橙色文字），重试只投未成功的那几张。投屏期间保持亮屏。

## WiFi 设备详情

新增 `subpackages/device/wifi-detail`：

- 头部：设备图、名称、WiFi版角标、设备 ID、屏幕尺寸（`sizeModel`）、在线状态（在线 / 离线 / 状态未知 / 查询中）。
- 信息行（IoT `GET /api/device/info`）：电量、WiFi 信号（信号格 + dBm）、WiFi 名称、固件版本、TF 卡（已用 / 共 MB 或未插卡）、国家码（1/01 显示世界通用模式）、最后上线、最后心跳；缺的显示「--」，离线不显示电量与信号。
- 订阅 WS `device.status`，上下线时重查；离开页面退订（本页订阅的才退）。
- 操作：「投屏」（离线先拦「设备已离线，请检查设备网络」，在线 / 未知照常进入，离线由接口 4041 兜底）、「刷新状态」。
- 不做：轮播、刷新屏幕、TF、休眠、OTA（STEP 5/6）；删除 / 重新配网（设备入网流程：App 无此操作）；改名在「我的设备」卡片上。

入口：我的设备点 WiFi 卡片直接进；蓝牙版详情页 `detail` 拿到记录后若是 WiFi 版 `redirectTo` 过来（覆盖首页等其它入口）。
