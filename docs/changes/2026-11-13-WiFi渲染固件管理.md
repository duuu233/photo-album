# 2026-11-13 WiFi 版渲染固件管理（FPGA 版本安装）

> 分支：`main`｜依据：产品需求（只有渲染模式 = FPGA16 的设备，设备信息页新增「渲染固件管理」；列出后台启用的 FPGA 版本，点安装进同 OTA 样式的步骤页并带出简介；复用 `POST /api/device/ota`，`type=fpga`、`version` = FPGA 目标版本，其余与固件升级一致）

## 入口

WiFi 详情 → 设备信息（`subpackages/device/wifi-info`）：`api.resolveRenderMode(device)` 为 `fpga16`（不区分大小写）时，信息行多一行「FPGA版本」（影子 `fpgaVersion`），下方多一个「渲染固件管理」入口；其他设备不显示。

## 渲染固件管理（新页 `subpackages/device/wifi-fpga`）

- 顶部「当前 FPGA 版本」（IoT 影子 `fpgaVersion`，读不到 `--`）。
- 版本列表：版本号、简介、安装按钮；与当前版本相同的标「当前版本」、按钮为「重新安装」。只显示启用的版本（`verify` 明确为 0 的去掉），按权重从大到小。
- 不是 fpga16 的设备直接打开时提示不支持。
- ⚠️ **用户端列表接口后端还没提供**（2026-11-13 核对 Swagger 只有后台 `/ZoneAdmin/ProductVersionFpga/*`）。接口路径集中在 `utils/fpga-firmware.js` 的 `LIST_API`（目前为空），为空时页面显示「版本列表暂未开放」、不发请求；后端给出后填上路径即可（入参按 `productId`）。简介字段后台也还没有，按 `INTRO_FIELDS` 依次兜底，字段名定了放到第一个。

## 安装步骤页（复用 `subpackages/device/wifi-ota`，`mode=fpga`）

- 安装目标（版本号、简介、固件地址）由列表页经本地存储 `fpga_install_target:{设备记录 id}` 带过去，不比对版本，直接显示「安装渲染固件 vX」、当前版本 / 安装版本、版本简介，按钮「立即安装」。
- 下发 `POST /api/device/ota`：`type=fpga`、`version` = 目标版本、`url` = 该版本固件地址；返回值、`ota/status` 与 WS `ota.result`、进度条、四步、失败 / 超时、本地进行中记录 `ota_inflight:{deviceNo}` 全部沿用固件升级，不单独判断状态。
- 只换文字：导航「渲染固件安装」、「设备正在安装渲染固件」、第 4 步与完成标题「安装完成」、「安装失败 / 安装超时」、「重新安装」；简介在确认页和进度页都显示。
- 本地进行中记录多存 `otaType: 'fpga'` 与简介；从「固件升级」入口重进时也按记录里的类型显示安装文字。固件升级入口的文字与行为不变。
