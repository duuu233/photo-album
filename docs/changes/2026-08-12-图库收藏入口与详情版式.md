# 官方图库三项：收藏入口移到分类条右端、顶部导航收紧、图片详情让大图占更多（2026-08-12）

> 状态：current
> 最后核对：2026-08-12
> 适用范围：微信小程序（官方图库列表 / 图片详情、「我的」页、公共组件 `page-nav`）
> 权威来源：产品需求（本轮三条）
> 相关：[2026-08-06 支付体系与官方图库接入](2026-08-06-支付体系与官方图库接入.md)
>

## Problem

1. 「我的收藏」入口在「我的」页，而收藏的内容全部来自官方图库 —— 用户看完图想去收藏夹，
   要退出图库、切到「我的」、再往下找一行。
2. 官方图库顶部（导航栏 + 分类条）占得太高，瀑布流第一屏露出的图明显偏少。
3. 图片详情页下半部分的白卡里有一块「适用设备尺寸」，把白卡撑得很高、大图被挤到只剩 46vh；
   而用户并不按分辨率挑图。

## Solution

### 1. 收藏入口从「我的」页搬到官方图库分类条右端

- `pages/mine/mine.wxml` 删掉「我的收藏」整行；`pages/mine/mine.js` 同步删掉 `favoriteCount`、
  `goFavorites` 与那次 `galleryApi.getFavoriteCount()`（本页每次进入少一个请求）。
- `subpackages/gallery/list` 的分类行改成一条 flex：**左边是原来的横滑分类，右端是固定的「收藏」**
  （图标 + 「收藏」二字）。跳转逻辑（含 `requireLogin` 闸）搬到 `list.js goFavorites`。
  ⚠️ 首版做成了「与分类同款、底色深一点」的胶囊，产品复看后判为「太像分类」，
  **样式已在二轮改掉**（见下「二轮补充 A」，图标也换成红心）。

⚠️ 两处结构约束，改坏了不会报错、只有肉眼能看出来（已由 `tests/gallery-layout.test.js` 锁住）：

- 收藏按钮必须是 `scroll-view` 的**兄弟节点**。写进横滑区里，它就跟着分类一起被滑走了。
- `.category-scroll` 必须写 `min-width: 0`。flex 子项默认 `min-width: auto`（按内容撑开），
  分类一多就会把右边的收藏按钮挤出屏幕，而不是自己滚起来。

### 2. 顶部导航收紧

`components/page-nav` 新增 `compact` 属性（默认 false，其余页面一行样式都不受影响）：
标题 34rpx → 30rpx，且**导航行下方那段留白不再计入高度**（`navHeight` 少算一个 `rowTop`）。
官方图库页用它，分类胶囊 68rpx → 60rpx。
⚠️ 当时把分类行的上下外边距也一并收到了 8/18rpx —— **二轮已放回 24/30rpx**：
产品要收的是导航栏，不是分类条（见「二轮补充 A」）。

⚠️ **能省的只有「行下那段留白」**：导航行本身的高度与纵向位置取自
`getMenuButtonBoundingClientRect()`，必须与微信原生胶囊同高同轴，压它就会和胶囊错位 ——
这是端上改不了的几何约束，别再往下调。

### 3. 图片详情：去掉「适用设备尺寸」，大图 46vh → 58vh

- 删掉分隔线 + 「适用设备尺寸」标题 + 尺寸标签整块，以及它们的样式
  （`.detail-divider` / `.detail-section-title` / `.detail-sizes` / `.detail-size-tag`）。
  接口/mock 仍下发 `photo.sizes`，端上不再取（页面 data 里也去掉了）。
- 大图 `.detail-hero` 46vh → 58vh、白卡起点 `.detail-spacer` 43vh → 55vh（两个数必须一起改：
  图比留白高 3vh，白卡圆角才压在图上）；白卡 `padding-top` 44rpx → 32rpx。

⚠️ 让开贴底「开始投屏」按钮的那段 `padding-bottom: calc(196rpx + safe-bottom)` **原本挂在
`.detail-sizes` 上**，删区块时最容易跟着一起没掉 —— 已移到 `.detail-card`。丢了它的表现是：
简介长一点，末尾几行就从按钮底下穿过去。

## 二轮补充（同日，产品复看后两条）

### A. 分类条上下留出间距，收藏入口与分类**在样式上分家**（需求 3）

- 上一轮为了「顶部太大」把分类条的上下留白一起收到了 8/18rpx —— 产品的意思是**收导航栏、不是收分类条**，
  这轮把它放回 24/30rpx（导航栏的 `compact` 保持不变）。
- 收藏入口首版是「底色深一点的同款胶囊」，和分类挤在一行里像是「最后一个分类」。
  现改成 **竖分隔线 + 红心（`heart-solid.png`）+ 橙字**、不画胶囊底：形状、底色、文字色三处都与分类不同，
  扫一眼就分得开。

### B. 图库列表卡片右上角加红心，按收藏态变化（需求 4）

把「我的收藏」页那套角标与逻辑搬到图库列表：`.photo-fav`（共用 `shared.wxss`）+ `catchtap` 切收藏，
`heart-solid.png` = 已收藏、`heart-outline.png` = 未收藏。

⚠️ 图标口径同时统一了（三页一致）：**半透明白圆底由 CSS 画**（`.photo-fav`），图里只有心。
原先「已收藏」用的是 `gallery-fav-badge.png`（60×60 的另一张实心心），与详情页的心不同源、
大小也对不上；现在图库列表、我的收藏、图片详情一律用 `heart-solid` / `heart-outline`
这两张 32×28 的纯心形，`gallery-fav-badge.png` 已无引用。分类条右端那颗「收藏」入口也换成 `heart-solid`。

⚠️ 与收藏页**唯一但关键**的差别：收藏页取消后那张图要消失，必须重拉列表；
**图库列表不能重拉** —— 收藏与否那张图都还在，重拉会让瀑布流按新数据重排，把用户正在看的卡片挪走。
所以这里带 `data-col`/`data-index`，只 `setData` 那一张的 `favorited`。

另两点：先请求成功再改 UI（乐观改再回滚的话，失败时红心会闪一下弹回去，比慢 200ms 更难受）；
入口过 `requireLogin`（收藏是账号数据）。

## Technical Decisions

- **收藏按钮不做成「第一个分类」**：它是跳转入口，跟分类不是一类东西，混在一起用户会以为
  点了会筛选出「收藏」分类。所以放在滑动区外、样式刻意与分类胶囊区分。
- **`compact` 做成组件属性而不是页面覆盖**：`page-nav` 是隔离样式的自定义组件，页面 wxss 够不到
  它内部的 `.nav-title`；而 `--nav-height` 这些变量是写在行内 style 上的，外部类也压不过。
  加一个 opt-in 属性是唯一既干净又不影响其它 14 个页面的做法。
- **`photo.sizes` 只从页面摘掉、不动 `gallery-api`**：那是数据层（后端接口就绪后仍会下发），
  端上不渲染即可，删掉字段反而会在接真实接口时被当成「漏接」。

## Risks

- 「我的」页现在只剩星币管理 / 操作指南 / 设置三行，若产品后续想恢复收藏入口，
  请**只保留一处**：两个入口指同一个页面只会让人犹豫点哪个。
- 大图 58vh 是按常见 16:9 手机屏定的。极扁的折叠屏展开态下白卡剩余高度会变小，
  简介很长时需要滚一点才能看全（不影响贴底按钮，它本就在滚动区外）。
- `page-nav` 的 `compact` 只有官方图库页在用；其余页面（含收藏页）保持原高度，
  两页并排看会有一点点差异，这是产品只点名了图库页的结果。
