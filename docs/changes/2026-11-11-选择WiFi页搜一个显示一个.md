# 2026-11-11 选择 WiFi 页：搜一个显示一个，列表出来后头部不再转圈

> 分支：`main-wifi`｜依据：产品反馈 ① WiFi 列表已经出来了，头部还在显示搜索中；② 搜索 WiFi 很慢，是否设备原因；③ 希望像搜索蓝牙设备一样搜一个显示一个

## 原因

- ① 列表本来就是每收到一批就显示，但转圈（`scanning`）要等设备**最后一批之后再静默 5 秒**才收（`blufi.scanWifi` 的 `WIFI_LIST_QUIET_MS`，设备不发「列表结束」标记，只能靠静默判断），所以列表出来后头部至少还要转 5 秒。
- ② 等待由三段组成：设备扫描附近 WiFi（双频芯片 2.4G + 5G 逐信道扫完才回结果，乐鑫扫描只在整轮扫完后给列表，本身约数秒，属于设备侧耗时，前端无法加快）+ 蓝牙回传文本 + 上面那 5 秒的静默等待。第三段是前端造成的「慢感」，本次已从界面上去掉；前两段需看真机日志确认（本次加了耗时日志）。
- ③ 设备按批回结果，一批里可能有几十条，整批一次性出现。

## 做了什么

| 位置 | 改动 |
|---|---|
| 选择 WiFi 页 `wifi-list` 头部 | 「正在连接设备... / 正在搜索网络...」只在一条都还没收到时显示；列表一出来头部即换成「重新搜索」，底部「手动输入WiFi名称」同时出现。后台照旧收设备后续批次（静默 5 秒判结束不变，只用于空列表 / 未返回的提示） |
| 搜一个显示一个 | 每收到一批，没显示过的网络按信号从强到弱逐条亮出（间隔 100ms，第一条立即出），新行淡入下滑；已显示的行按 `ssid` 复用节点，刷新信号 / 排序时不重播；同名去重、信号强在前、隐藏网络不列的口径不变。扫描结束时还没亮完的一次补齐 |
| 重新搜索 | 列表出来后不等收尾即可点；每轮搜索带序号，旧一轮之后回来的批次 / 结果作废，重搜时先清空列表 |
| 耗时日志 | 控制台 `[WiFi列表]` 打出发出扫描指令到每一批回来的毫秒数、总批数与含收尾等待的总耗时，真机据此区分慢在设备扫描还是别处 |

逐条亮出的实际速度取决于设备：设备一批回完时 3 秒内逐条出完；设备若本身就一条一条回，页面就跟着一条一条出。真正「设备扫到一个就回一个」需要固件改成按信道分段扫描并逐段上报，前端已能直接接住。
