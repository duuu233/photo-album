# 2026-11-02 抖动出帧基地址改由 download-endpoint 下发 / 设备列表连接后回顶

> 分支：`main`（`main-wifi` 经合入 main 同步）｜依据：产品口径

## 一、抖动出帧：基地址由 download-endpoint 下发

- 先 `GET https://iot.boltfox.cn/api/device/download-endpoint`（Header 带 `userToken`，与其它 IoT 接口同一登录 token），返回结构与 IoT 接口一致：`{ code: 0, msg, data }`，`data` 为 `{ region, endpoint }`，**取 `data.endpoint` 作出帧服务基地址**（联调实测 `{"region":"CN","endpoint":"https://apirp.boltstar.net"}`；最初按 `data` 直接是地址字符串实现，同日更正，字符串形式仍兼容）。
- 再请求 **基地址（去掉末尾 `/`）+ `/Client/Basic/imageDitheringBinDownload`**，例如最终为 `https://api.boltfox.cn/Client/Basic/imageDitheringBinDownload`。参数全部不变：公共参数 device / terminal / language / userToken（query + header）、鉴权头、form-data `color=BWRYGB` / `imageDitheringModes=2` / `type` / `file`、二进制响应、业务报错与 401/406 登出、网络失败重试 3 次。
- 取基地址失败（网络失败、`code≠0`、`data.endpoint` 缺失或不是 http(s) 地址）时回落 `config.baseURL`（`https://api.boltfox.cn`），失败不缓存，下次投屏重新取；成功结果内存缓存 10 分钟。
- 同日两版理解有误的改动（把 download-endpoint 当出帧接口 / 当帧下载前缀）均已撤回；不再写死 `api.yikaltd.com`。
- ⚠️ 小程序后台「request 合法域名」需包含 `https://iot.boltfox.cn` 以及下发的基地址域名（目前实测为 `https://apirp.boltstar.net`，其它反代域名也要加）。
