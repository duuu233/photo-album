# 详情页「固件升级」右侧改为版本比对结论：有版本可更新 / 已是最新版本（2026-08-12）

> 状态：current
> 最后核对：2026-08-12
> 适用范围：微信小程序设备详情页与 OTA 页（`subpackages/device/detail`、`subpackages/device/ota`）
> 相关协议：[OTA / DFU 协议](../protocols/ota-dfu.md)
>
> ⚠️ 仅小程序，Flutter APP 待同步（App 侧详情页同一行需核对是否也在直接展示版本号）。

## 一、产品要求

进入设备详情页后：先读设备**实际在跑的固件版本**——就是调试台「读固件版本」按钮读的那个值——
用它和设备详情接口返回的 `newVersionNo` 比对；**不一样**且 `downloadPath` 是有效的下载地址时，
「固件升级」右边提示**「有版本可更新」**，反之显示**「已是最新版本」**。

## 二、改动前的行为

右侧显示的是**版本号本身**（`版本V1.0.2`），取值 `device.newVersionNo || device.firmwareVersion`：

- 这两个字段一个是「云端最新版本」、一个是「设备当前版本」，谁有值显示谁，用户看到一个数字
  却无从判断该不该升级；
- 是否有更新的判断只在**点击**那一刻做，且只看后端 `isUpdate` 标志。

## 三、改法

### 1. 判定收敛到一个函数

`detail.js` 新增 `evaluateFirmwareUpdate(device, currentVersion)`，右侧文案与点击流程共用，
避免出现「右边写着有版本可更新、点进去弹已是最新版本」这种自相矛盾：

| state | 条件 | 右侧文案 | 点击「固件升级」 |
| --- | --- | --- | --- |
| `update` | 版本号不同 + `downloadPath` 有效 `.bin` | 有版本可更新 | 二次确认「检测到新版本：X，是否升级」 |
| `latest` | 版本号相同，或接口没给 `newVersionNo` | 已是最新版本 | 弹「当前固件已是最新版本」 |
| `invalid` | 版本号不同但缺号/缺地址/不是 `.bin` | 已是最新版本 | 如实说明原因（缺地址 / 不是 .bin） |
| `unknown` | 读不到设备当前固件版本 | `--` | 退回后端 `isUpdate` 标志判断 |

版本号比较去空格 + 不区分大小写（与 `ota.js sameVersion` 同口径）。

### 2. 「设备当前固件版本」的来源

只认 `0x03 GET_SW_VER`——调试台 `cmdGetVersion` 走的就是它，详情页由
`utils/device-ble.js readDeviceInfo` 在 `0x01` 之后一并读回，落在 `device.firmwareVersion`。
**后端不下发设备真正在跑的版本**，所以未连接时这个值必然为空。

### 3. 读不到当前版本时显示 `--`，不显示「已是最新版本」

未连接 / `0x03` 读失败时无从比较，回落 `--`，与本页设备ID、最大照片数量、轮播设置同一套占位约定。
写「已是最新版本」等于在不知情时给用户一个可能是假的结论——而这恰恰是最危险的一种假值：
用户会因此**不去升级**。

### 4. 点击流程不再以后端 `isUpdate` 为准

`goOtaUpgrade` 改用同一套判定；只有 `state==='unknown'`（读不到设备版本）时才退回 `isUpdate`，
以保住 2026-08-11 定下的「版本检测走接口、不连蓝牙也能查」能力。这一分支下右侧文案是 `--`，
不会与点击结论互相打架。顺带把刚拉到的接口数据回写并刷新右侧文案（进页面时拉的那份可能已过期）。

### 5. OTA 页判定同步

`ota.js buildFirmwareFromDevice` 原本是 `isUpdate===1 && !已是最新`。若不改，详情页判定
「有版本可更新」→ 点「立刻更新」→ 升级页却因后端 `isUpdate=0` 显示「已是最新版本」，
**用户永远升不了级**。现同样改为：读得到设备版本就以版本号比较为准，读不到才退回 `isUpdate`。

## 四、涉及文件

| 文件 | 改动 |
| --- | --- |
| `subpackages/device/detail/detail.js` | 新增 `sameVersion`/`firmwarePackageError`/`evaluateFirmwareUpdate`/`firmwareUpdateText`（替换 `getOtaValidationError`）；data 字段 `newVersionNo` → `firmwareUpdateText`；`goOtaUpgrade` 改用新判定 |
| `subpackages/device/detail/detail.wxml` | 右侧由 `版本{{newVersionNo}}` 改为 `{{firmwareUpdateText}}` |
| `subpackages/device/ota/ota.js` | `buildFirmwareFromDevice` 的 `hasUpdate` 与详情页同源 |
| `tests/firmware-update-hint.test.js` | 新增：九个用例覆盖右侧文案与点击结论（含大小写/空格、非 `.bin`、未连接回退） |

## 五、验证

```bash
node tests/firmware-update-hint.test.js
node tests/ota-device-identity.test.js
node tests/ota-dfu-transfer.test.js
```

⚠️ 真机未验：需连上设备确认 `0x03` 读回的版本号写法与后端 `newVersionNo` **可比**
（例如一边 `V1.0.1`、一边 `1.0.1`，就会被判成「有版本可更新」且永远消不掉）。这是本次改动
最大的落地风险，上线前必须拿一台已是最新版本的设备实测一次。
