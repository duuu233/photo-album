## Technical Decisions

1. **贴底 CTA 按钮放主包公共样式**（`styles/cta-button.wxss`，由 `app.wxss` 统一 `@import`）。
   Token 管理 / 确认购买 / 图片详情三页用同一枚按钮，但分属 `token`、`gallery` **两个不同分包**，
   分包之间不能互相引用，公共部分只能落在主包 —— 与 `styles/fold-adapt.wxss` 同一套做法。
   底图 `primary-btn-bg.png` 是 726×184 整图，实心胶囊实测只占 654×112（alpha 边界 x[36,689] y[30,141]），
   按 726×184rpx 铺 + `-36/-30` 负偏移，胶囊正好落满 654×112rpx 的按钮盒（654rpx 正是全站内容宽度，1:1 不拉伸）。

2. **左右留白一律用 `padding-left/right` 长写法，禁止 `padding: 0 48rpx` 简写。**
   `app.wxss` 先于页面 wxss 生效、两者又都是单类选择器（同优先级），简写会把公共类
   `.cta-button-gap` 的 `padding-bottom` 一并重置成 0，贴底按钮就压住最后一块内容。

3. **瀑布流分列按累计高度，不按奇偶下标**（`utils/gallery-api.js` 的 `splitColumns`）：
   图片高宽比不一，奇偶分列会让某一列明显长出一截。
   每张图的渲染高度在**渲染前**由 `ratio` 算好写进 style，不交给 `mode="widthFix"` 加载后再撑开
   —— 后者会在图陆续到达时把下方卡片一路顶走。与 AI 聊天页「图片按已知比例预占空间」同口径。

4. **`page-nav` 的 `immersive` 属性第一次真正启用**：属性和 `page-nav--immersive` 类此前就在组件里、
   但一直没有配套样式。本次补上「标题改白字 + 弱投影」——图片详情页背景是任意照片，
   纯白字遇到浅色天空会糊掉。

## 折叠屏适配

全部新页面按 [`styles/fold-adapt.wxss`](../../styles/fold-adapt.wxss) 的公共方案（模式 B · 容器滚动）实现：

- 根容器 `.fold-viewport`（高度只用 `100vh`，不用 `wx.getWindowInfo().windowHeight`）；
- 导航栏、Tab 条、分类 chips、计数行、底栏、贴底按钮、弹层一律留在 `.fold-scroll` **外**；
- 留在滚动区外**又与滚动区重叠**的可点元素显式 `z-index ≥ 2`（`.cta-button`、`.tab-bar`、
  `.category-scroll`、`.fav-count`）—— `.fold-scroll` 是 z-index:1 的透明层，
  层级缺省会导致「看得见、点不动」（2026-08-05 设置页线上故障）；
- 滚动内容块套 `.fold-scroll-body`（自带 `display: flow-root`，防外边距合并造成的假滚动条）；
- 页面 JS 统一用 `fold.adapt()` 包装，`onResize` 自动重测状态栏高度与底部安全区。

图片详情页是唯一例外：它要「留白 + 白卡吃掉剩余高度」，用 flex 列比 `.fold-scroll-body` 直接
（flex 容器本来就不与子元素合并外边距），已把 `.detail-body` 登记进
`tests/fold-scroll-phantom.test.js` 的 `viewportFillers` 清单，约束同样被锁住。

## Risks / Follow-up

⚠️ **两个模块的后端接口都还不存在**，`docs/reference/client-api-matrix.md` 里没有任何
余额、套餐、订单、图库、收藏端点。本轮只固定了**客户端契约**，数据由两个新模块的 mock 提供：

- `utils/token-api.js` —— `getAccount` / `getPackages` / `getRecords` / `createOrder`
- `utils/gallery-api.js` —— `getCategories` / `getPhotos` / `getPhotoDetail` / `getFavorites` / `toggleFavorite`

每个方法体内都标了 `TODO(后端)`，接口就位后只改这一层，页面不用动。具体待办：

1. **支付通道未接**。`createOrder` 目前是本地 mock 结算（直接加余额）。真实实现必须是
   「服务端下单 → `wx.requestPayment` → **服务端回调**确认 → 重新拉余额」，
   绝不能拿客户端 success 回调直接加余额。PayPal 当前直接 reject：小程序内无原生 SDK，
   需 H5/webview 承载，合规性与跳转方式要先与后端和微信审核确认。iOS Apple IAP 属 APP 端。
2. **收藏关系落在本机 Storage**，换设备即丢、不跨端同步。真实实现必须是服务端账号维度。
3. **图库图片 URL 是占位路径**（`https://oss.boltfox.cn/prodFile/gallery/*.jpg`），当前不可访问，
   模拟器里会显示为灰底卡片（`.photo-image` 有兜底底色，瀑布流几何仍可核对）。
   接入真实图库后替换即可。
4. **`subpackages/ai/chat/chat.js` 的 `TOKEN_LIMIT_ENABLED` 仍是 `false`**
   （2026-08-03 因余额是假数据而临时关闭）。余额接口接上后应连同该开关一起改回 `true`，
   并把 `readTokenBalance`/`spendToken` 换成接口调用，与本模块共用同一个余额口径。
5. **未真机验证**：本轮只跑了 Node 单元测试（15/15 通过）与静态检查，
   瀑布流滚动、横滑套餐、沉浸式详情页、投屏链路、折叠屏展开/分屏均需真机回归。
6. **Flutter APP 未同步**，两个模块的 APP 端待补。
