# 2026-10-27 我的设备按 WiFi 版 / 蓝牙版分组

> 分支：`main-wifi`；修改前：e93bae2。背景：WiFi 版设备配网成功、绑定后已出现在「我的设备」，原列表全按蓝牙版展示（连接 / 断开按钮对 WiFi 版无意义）。

## 改动

- 识别：`utils/broadcast-match.js` 新增 `isWifiBroadcastId`——已绑定记录所属产品的 `broadcastId` 是带 `*` 的模板（如 `IJ_*`）或 `IJ_` 前缀即 WiFi 版，其余（含认不出广播 ID 的记录）按蓝牙版，原行为不变。
- 分组：`subpackages/device/list` 分「WiFi版」「蓝牙版」两组，WiFi 版在前，标题图标沿用搜索列表的通信类型角标；某组没有设备不出标题。两组遍历同一份 `devices`（按 `isWifi` 过滤），原有按 id 找设备的逻辑不变；组内排序沿用原规则。
- 蓝牙版卡片：内容、按钮（投屏 / 连接·断开）完全不变。
- WiFi 版卡片：
  - 状态来自 IoT `GET /api/device/info`（STEP 4，一次拿在线与影子）：「在线」（青绿）/「离线」/「状态未知」（403 未绑定、503、网络失败）/ 查询中转圈；在线时显示信号格（`wifiRssi` → `signal-bars`）和电量（`shadow.battery`）。静默查询不弹错误；每台各自带序号，旧请求晚到不覆盖；重新进页面先沿用上次状态，不闪「查询中」。
  - 按钮：「投屏」——WiFi 投屏走 IoT 上传（STEP 3）尚未接入，点了提示「WiFi版投屏即将上线」，不进蓝牙投屏流程；「刷新状态」——只重查这一台。没有连接 / 断开：WiFi 版不经手机蓝牙连接，在线与否由云端判断；重新配网只能设备端重置，App 无对应操作。
  - 设备图、改名、设备 ID 显示同蓝牙版。
- 选相框模式（从投屏进来选设备）：WiFi 版点了提示「WiFi版投屏即将上线，请选择蓝牙版设备」，不选中，避免进入蓝牙投屏链路。
