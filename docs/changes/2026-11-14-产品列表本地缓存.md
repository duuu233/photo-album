# 2026-11-14 产品列表本地缓存：WiFi 设备不再先显示成蓝牙版

> 分支：`main`｜依据：用户反馈首页设备卡、我的设备列表把 WiFi 版设备先显示成蓝牙版，过 1~2 秒才变成 WiFi 版；首页 loading 偏久。

> 更正（同日）：设备列表 / 详情接口其实下发 `versionType`（1=蓝牙版，2=wifi版），WiFi 版判断已改为先认它，见 [按 versionType 认 WiFi 版](2026-11-14-按versionType认WiFi版.md)。下文「不带类型」的说法有误；本篇的本地缓存仍保留，用于不再等产品列表（设备图 / 机型）。

- 原因：
  - 当时前端没读 `versionType`，卡片是不是 WiFi 版只看所属产品的 `broadcastId`（`IJ_*`），要先拿到产品列表（`getProductList`）才认得出；
  - 产品列表只在内存缓存，每次冷启动都要重新拉。`getDevices` 最多等它 3 秒，没回来就把 WiFi 设备当蓝牙版（卡片也带 `tab=ble` 进我的设备），之后拿到了才变对；
  - 首页 loading 要等设备列表，也就跟着白等这 3 秒。
- 改法（`utils/api.js`）：
  - 产品列表拉到后存本地（`product_catalog_cache`）。下次启动直接用存的那份，不等接口，同时后台拉一次最新的，成功后覆盖内存和本地；
  - 存的那份里找不到某台设备的 productId（后台新加了产品）时，设备列表照旧最多等 3 秒拿最新的那份；
  - 详情补机型认出来的 `broadcastId` 也存本地（`device_broadcast_id_cache`），下次启动不再调详情；认不出的仍只记本次会话；用的是旧产品列表、又没认出来时不记；
  - 绑定设备时拉到的产品列表同样写本地；
  - 存储不可用时照旧，不报错。
- 首页、我的设备、投屏选设备等走 `api.getDevices` 的入口一起生效；页面逻辑不改。
- 仍有的情况：装好后第一次启动（本地还没有存的那份），产品列表 3 秒内没回来仍会先显示成蓝牙版，之后从第二次启动起正常。
