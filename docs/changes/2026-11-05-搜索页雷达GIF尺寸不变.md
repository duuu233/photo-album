# 2026-11-05 搜索设备页：搜到设备后雷达 GIF 尺寸不变

> 分支：`main-wifi`｜依据：产品反馈搜索页上方的搜索 GIF 在搜出结果后变小，要求尺寸不变

## 原因

2026-09-16（`docs/changes/2026-09-16-搜索设备列表改4.5张弹性高度.md`）为了让设备列表露出 4.5 张，`radar-wrap--found` 按 `devices.length` 挂上：搜到第一台设备就把雷达从 500rpx 缩到 340rpx。搜索中是边搜边显示，GIF 还在转，于是看到它一下变小；雷达还带 `flex-shrink: 40`，列表变长时会继续被压小。

## 做了什么

| 位置 | 改动 |
|---|---|
| 搜索设备页 `bind` | 已发现态 `radar-wrap--found` 改为「搜到设备且搜索已结束」才挂；搜索中挂 `radar-wrap--scanning`（`flex-shrink: 0`），GIF 一直保持 500rpx，不随搜到设备缩小，也不随列表变长被压。这时屏幕不够由设备列表让（列表可滚动）；搜索结束后换成「已搜到」静态图，仍按原来的 340rpx 让位给列表 |

## 涉及文件

`subpackages/device/bind/bind.{wxml,wxss}`、`tests/bind-device-list-layout.test.js`。

## 验证

- `tests/bind-device-list-layout.test.js`：「`radar-wrap--found` 按 `devices.length` 挂」的断言按新条件改写为 `devices.length && !scanning`（注明原因），补「搜索中挂 `radar-wrap--scanning`、不参与收缩、不另设宽高」；已发现态的 4.5 张版式推算不变。
- 本机无 node，测试未运行；改了 wxml / wxss，需本地跑全量。未开发者工具 / 真机；小屏（如 SE）搜索中列表可见张数会比原来少（约 1.5 张，可滚动）。
