# 2026-11-04 投屏按钮防重复点击

> 分支：`main-wifi`｜依据：产品要求点击投屏要防重复点击（先只做投屏相关按钮，其它按钮之后再说）

## 做了什么

新增 `utils/tap-guard.js`，在页面注册处按方法名加锁，方法体不改：

```js
Page(fold.adapt(tapGuard.wrap({ ...页面定义 }, { startProjection: 'projection', chooseCamera: 'pick' })))
```

- 同一页面、同一个 key：上一次还没执行完（方法返回的 Promise 未结束：连接设备、选图、下载、准备进预览）时，再点直接忽略，不提示；
- 执行完后冷却 500ms，挡住 `navigateTo` / `redirectTo` 转场期间的连点；
- 一次执行超过 60 秒还没结束（异常挂住）就不再拦，避免按钮永久失灵；
- 按钮用「执行中加锁 + 结束后短冷却」（前沿触发），不用防抖：防抖要等停手才响应，按钮会显得迟钝。

key 分两类：`projection` 是「投屏」入口本身，`pick` 是投屏弹层里的「拍照 / 相册」（弹层刚弹出就点选图不会被入口的冷却挡掉）。

| 页面 | 加锁的方法 | 原来的问题 |
|---|---|---|
| 首页 | 拍照 / 相册投屏入口 `tapCameraEntry`、`tapAlbumEntry` | 无锁；连接设备期间连点会再连一次、选图弹两次 |
| 我的设备 | 蓝牙卡「投屏」`startProjection`、WiFi 卡「投屏」`startWifiProjection`、弹层拍照 / 相册 | 无锁；蓝牙版连接期间连点会重复连接 |
| 蓝牙设备详情 | 「投屏」、弹层拍照 / 相册 | 同上 |
| WiFi 设备详情 | 「投屏」、弹层拍照 / 相册 | 选图无锁 |
| 官方图库详情 | 「投屏」`onProject`、选设备弹层「连接并投屏」`onDevicePickerConfirm` | `onProject` 有 `projecting` 锁，但弹层确认直接调 `startProjection`，连点会开两次投屏 |
| AI 对话 | 图片下「投屏」`projectImage`、选设备弹层「连接并投屏」 | 无锁 |
| 我的相册 | 底部「再次投屏」 | 原有 `_retrying` 锁，加冷却 |
| 投屏记录 | 「再次投屏 / 重新投屏」 | 原有 `_retrying` 锁，加冷却 |
| 投屏预览 | 「开始投屏」`confirmProjection` | 原有 `projecting` 锁，再加一层 |
| 投屏结果（蓝牙） | 「继续投屏」「重新投屏」、弹层拍照 / 相册 | 「重新投屏」直接 `redirectTo`，连点会跳两次 |
| WiFi 投屏结果 | 「重试」`retryFailed` | 原有 phase 判断，再加一层 |

锁只覆盖方法自己返回的 Promise，所以把调用链上漏掉的 `return` 补上了：首页入口 `return this.chooseCamera()` / `chooseAlbum()`；我的设备、两个详情页、结果页的拍照 / 相册 `return this.pickAndProject(...)` / `pickAndContinue(...)`；官方图库、AI 对话里 `return this.startProjection(...)`、AI 对话 `return this.openProjectionPreview(...)`。原来这些调用不等结果，流程本身不变，只是锁能持续到进入预览页为止。
