# 2026-10-22 设备图按机型区分

> 分支：`main`。原 main（e04198d）已另存为 `main-backup-20261022`，main 快进到 main-test（3f91803，含两张新设备图）后在其上修改。

## 需求

后台新增两种产品，各配一张设备图：

| 机型（产品 broadcastId） | 设备图 |
| --- | --- |
| EB-169（圆屏，400×400，shapeType=1） | `assets/images/home-device-circle-thumb.png` |
| EC-370 | `assets/images/home-device-rectangle-thumb.png` |
| 其余机型（EF6-370 / EF6-589 等）与认不出的 | `assets/images/home-device-thumb.png`（原图） |

展示设备图的六处全部按机型区分：首页设备卡、我的设备、设备详情、搜索设备、命名弹窗、投屏选设备弹层。

## 改动

- 新增 `utils/device-thumb.js`，六处唯一出口 `thumbOf(device)`，判断顺序：
  1. 设备上的 `broadcastId`；
  2. 搜索结果（`realBluetooth`）的蓝牙广播名 `name` / `localName`——与扫描白名单同口径，大小写不敏感的包含匹配；
  3. 都取不到时 `shapeType === 1`（后台产品「形状类型」圆形）按 EB-169 圆屏处理；
  4. 其余返回原图。

  已绑定记录的 `name` 是用户起的名字，**不参与判断**，否则改名后图会跟着变。
- `utils/api.js`：
  - 设备列表接口（`getUserProductList`）直接下发 `productId` 与 `broadcastId`（后端确认），优先用记录自带的 `broadcastId`；
    没带的记录（如详情接口、旧缓存）由 `getDevices` / `getDeviceDetail` 按 `productId` 回查产品列表（`/Client/Product/getProductList`）补上。
    初版曾在没有 `productId` 时按唯一 `productImg` 猜产品，确认列表带字段后已去掉。
  - 产品列表整次会话缓存，失败不缓存、不弹错误提示；设备列表/详情最多为它多等 3 秒，超时先按已有信息出图。
  - `bindDevice` 把匹配到的产品 `broadcastId` 写进新绑定记录，并用这次拉到的产品列表刷新缓存。
  - `bindDevice` 匹配产品（`productScore`）新增：蓝牙广播名 `name` / `localName` 包含产品列表的 `broadcastId`
    （去首尾空白、大小写不敏感）加 10 分，压过名称/型号的零散命中。原打分只比产品名，EC-370 的屏型若按 3.7 寸上报，
    型号会同时命中 EF6-370 而平分，谁排在列表前面绑谁；广播名带后缀时所有产品 0 分，落到列表第一个（EB-169）。
  - `normalizeDevice` 统一算出 `thumb` 字段。
- 页面与组件：六处模板改为 `{{… thumb || '/assets/images/home-device-thumb.png'}}`；首页归一化透传 `broadcastId` 并计算 `thumb`；
  搜索结果按广播名算 `thumb`；`device-name-dialog` 新增 `thumb` 属性，列表/详情/绑定三处调用方传入。

- `withProductBroadcastId`：记录自带、且等于产品列表中某个产品的 `broadcastId`（去空白、不区分大小写）才不动；
  缺失或认不出时按 `productId` 回查产品列表覆盖。产品列表本来就与设备列表并行拉取，无额外请求。
- `tests/device-thumb.test.js` 新增 `r-foreign`（broadcastId 带成设备ID、productId 指向 EC-370）→ 矩形图；原有断言不变。

- 设备当初绑定到了错误的产品（10-22 加权前 EC-370 可能与 EF6-370 平分、广播名缺失时落到列表第一个），
  记录的 `productId` / 尺寸 / 形状都会是别的产品，设备图也跟着错。需在后台核对这两台设备所属产品，错的删除后重新绑定。
