# 2026-11-03「我的上传」投屏记录按设备ID查询

> 分支：`main-wifi`｜依据：后端口径（`getUserProductImgRecordList` 新增可选参数 `deviceId`）

## 做了什么

- `getUserProductImgRecordList` 新增可选参数 `deviceId`（设备完整 6 字节 ID，即前端的 `productDeviceId`）：传了后端按设备 ID 查，不再按用户 ID；不传维持原逻辑按用户 ID 查。
- `api.getProjectionRecords` 只在调用方给了 `deviceId` 时带上该参数，原有 `userProductId`、`deviceUploadState` 等参数不变。
- 「我的上传」页（`subpackages/album/list`）选了具体设备时，带上该设备的 `productDeviceId`；选「全部」、设备列表里找不到这台、或设备没有完整 ID 时不带，仍按用户查。
- WiFi 轮播设置「轮播照片」的选图列表（`subpackages/device/wifi-slideshow`）同样规则（当日追加）：设备详情有 `productDeviceId` 就带上，没有不带；`userProductId` 照旧一起传。控制台打一行以 `★★★【轮播选图·deviceId】` 开头的日志：已传（`console.log`，带 deviceId / userProductId）或未传（`console.warn`，原因：没有设备 ID / 历史短 ID 不完整）；接口返回后再打一行返回条数、按设备还是按用户查、可轮播张数，便于测试核对。
- 投屏记录页和「我的」页的投屏成功条数这次不传，行为不变。
