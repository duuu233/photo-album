## 第 1 项 · 预览页在折叠屏展开态「被锁住」

### 现象

选相册 → 选图 → 跳到「照片预览」。展开态下页面看着正常（导航栏 + 一张大图），
但**点什么都没反应**：竖向/横向/原图切不了，「开始投屏」也按不动。

### 根因：根容器是 `min-height`，flex 永远没有剩余空间可分

2026-08-05 那轮给本页加的适配是这一条：

```css
@media (min-aspect-ratio: 3/4) {
  .preview-stage { flex: 1 1 auto; min-height: 40vh; }   /* ← 等于没写 */
}
```

但页面根容器当时写的是 `min-height: 100vh`：

- 块级盒的 `min-height` 只保证「不低于」，**高度仍按内容撑开**；
- 于是 flex 容器的内容高 = 各项高度之和，**剩余空间恒为 0**，
  `flex-shrink` 一次都不会触发 —— 舞台一寸不让；
- 而本页 `"disableScroll": true`（自定义导航 + 贴底按钮的常规配置），
  超出视口的部分既没有滚动容器接管、也滚不动。

叠加 rpx 放大（`rpx = 屏宽/750`，展开态舞台的 `680rpx` ≈ 640px，窗口反而更矮更方），
结果就是**导航栏 + 计数条 + 舞台正好铺满甚至超出一屏**，圆点/分段控制器/手势提示/「开始投屏」
全被顶到视口以外。屏幕上剩下的可点区域只有铺满舞台的常驻编辑层，
而它 `catch` 掉了全部 touch 事件（长按拖拽/双指缩放都在它上面分流），
不长按不双指就什么都不发生 —— 观感正是「页面被锁住了」。

### 改法

**正确性不再依赖媒体查询**，一屏之内由 flex 兜死：

| 位置 | 改动 |
| --- | --- |
| `.preview-page` | `min-height: 100vh` → **`height: 100vh` + `overflow: hidden`**（确定高度，flex 才算得出负剩余空间） |
| `.preview-stage` | `flex: 1 0 680rpx; min-height: 680rpx` → **`flex: 1 1 0; min-height: 0`**（剩多少给多少） |
| 其余各块 | `.preview-nav`（page-nav 宿主节点）/计数条/圆点/分段/提示/按钮统一 `flex: 0 0 auto`，只有舞台让高度 |
| `@media (min-aspect-ratio: 3/4)` | 不再管高度分配，只收紧纵向留白（舞台外边距、分段内边距、提示外边距、按钮高度与贴底距离），把省下的高度让回舞台 |
| `preview.wxml` | `<page-nav>` 加 `class="preview-nav"`（class 落在**宿主节点**上，即根 flex 的第一项） |

要点：

- **基准必须是 0**（`flex: 1 1 0`）。写 `auto` 或 `680rpx` 时该项基准参与「内容总高」，
  窗口一矮就产生负剩余空间，flex 会把导航栏等固定块一起按比例压扁——
  与 `styles/fold-adapt.wxss` 里 `.fold-scroll` 那条约束同源。
- **不要再给舞台写 `min-height: 680rpx`**：rpx 随屏宽放大，展开态它比整块可用高度还大，
  舞台就会拒绝收缩，正是本次故障的直接成因。短屏下限交给 flex：宁可舞台小一点，
  也不能有块够不着（本页禁滚，够不着就等于没有）。
  `preview.js` 的 `STAGE_MIN_H_RPX = 680` 保留，但它只是**实测完成前**的临时换算基准，不是布局下限。
- **媒体查询必须放在 wxss 文件最后**：媒体查询不提升优先级，同为单类选择器时后写的赢；
  它现在要覆盖 `.segmented` / `.segmented-item` / `.gesture-tip` / `.preview-submit`，
  放在这些基础规则前面等于白写（首版只覆盖上方的 `.preview-stage`，才没暴露这个坑）。
- 普通手机竖屏（宽高比约 0.46）**不命中**媒体查询，且改动前后舞台都是「占满剩余高度」，
  观感一像素不变。

### 顺带修掉：折叠/展开后取景框不重算

`onResize` 原本是 `this._stageRect = null; this.enterEdit()`，但 `enterEdit` 对
「正在编辑同一张图」有一条**直接返回**的快路径（只把 `editReady` 置真），
于是形态一变根本不会重量舞台，取景框仍停在折叠前的位置和尺寸，
**导出的构图会和用户所见对不上**（这正是上一份文档想避免、但没真正生效的那一条）。

改为：

```js
onResize() {
  this._stageRect = null
  if (!this.data.imageCount) return
  this._saveEditState()                 // 先快照实时构图，重进编辑态按 src 原样恢复
  this.enterEdit({ remeasure: true })   // 强制重走「量舞台 → 重算取景框」
}
```

`enterEdit(options)` 新增 `options.remeasure`，只有 `onResize` 传；其余调用方（`onReady`、
切图、还原原图）行为一字不变。图片源没换，`editReady` 保持真，重进编辑态不会闪。

## 第 2 项 · 「我的相册」默认选中连接中的设备

### 为什么丢的

2026-08-04 把「设备照片」+「投屏管理」合并成「我的相册」时，页面沿用的是**设备照片页**的
默认选中规则（保留当前选中 → 第一台有照片的设备 → 第一台），
而「连接中的设备优先」是**投屏管理页**（`subpackages/projection/records/records.js`）那边的规则：

```js
filters.find(item => item.value === old) || filters.find(item => item.connected) || filters[0]
```

合并时没把它一起搬过来，于是「在首页/设备页连好设备 → 进我的相册」看到的可能是另一台的照片。

### 实现

`list.js` 新增 `firstConnectedFilterValue()`，并把两处重复的默认值计算收成一个方法
`pickDefaultFilter(filters, photos, devices)`（首屏 `loadPhotos` 与下拉刷新 `toggleFilterMenu` 共用，
两处必须同一套规则）：

1. **保留用户当前选中的那台**（仍在列表里）——本页 `onShow` 每次都会重跑 `loadPhotos`，
   不保留的话「点进照片再返回」就会把用户手动切过的设备冲掉；
2. 否则 **第一台连接中的设备**（新）；
3. 否则第一台「有照片」的设备（避免默认打开空设备，维持原设备照片页观感）；
4. 再否则第一台。

连接态**一律现算**：设备接口不返回它，只能按当下真实 BLE 会话判定 ——
`activeDevice.findConnectedDeviceId(device)`（deviceId 直连 + 设备ID×广播ID 序列号交叉匹配），
与投屏管理页、设备列表页同一个判据。单连接下最多命中一台；真出现多台就取设备接口顺序里第一台
（需求即「第一个找到的连接中的设备」）。

取值口径与 `buildDeviceFiltersFromDevices` 一致（`userProductId` 兜底 `id`），并限定
「仍在筛选项里」——取不到设备ID 的设备根本不成项，默认值不能落到下拉里没有的项上。

回归用例锁在 `tests/album-default-device.test.js`（无连接走原规则、连接中优先、多台取第一台、
用户手动选过不被覆盖、原选中已解绑、连接设备无设备ID 五种情况）。

### 保持不变

- 下拉里的**排序**没动（仍按设备接口返回顺序），只改默认值；投屏管理页那边的「连接中排最前」
  是那一页自己的行为，本页不跟。
- 切换设备、再次投屏、删除三条链路一字未动。

## Risks

- **折叠屏改动未真机验证**：展开态/分屏/横屏下舞台还剩多少高度、构图够不够施展，只能真机看。
  极端窄高比（如横屏手机）下固定块本身就可能超过一屏，此时舞台会被压到接近 0 —— 图看不清，
  但所有按钮仍在视口内可点（这是刻意的取舍：本页禁滚，够不着的块等于不存在）。
- **`@media (min-aspect-ratio: 3/4)` 若某些基础库不支持**：只影响留白松紧，页面照样装得下、能操作。
- **`class` 落在自定义组件宿主节点**（`.preview-nav`）：这是页面作用域的样式，不越界改组件内部；
  若某天 page-nav 改成 `virtualHost`，宿主节点消失，这条会失效（届时导航栏可能被压扁）。
- **默认选中改变了首屏落点**：多设备账号下，连着 B 时进「我的相册」直接看到 B 的照片，
  与改动前（第一台有照片的设备）不同——这是需求本身，但要留意用户是否会误以为「A 的照片没了」。
- 连接态依赖 BLE 会话在跨页面时仍活着（`deviceBle.getActiveConnections()`）；
  会话被系统回收后判定为未连接，默认值退回原规则。
