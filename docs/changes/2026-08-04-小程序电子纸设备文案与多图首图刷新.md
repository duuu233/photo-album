## Device ID Display

绑定页扫描阶段展示的是广播中的 4 字节短 ID；“我的设备”展示的是连接/后端确认后的完整 6 字节 ID。两者身份用途保持不变，只统一显示格式：每两个十六进制字符之间都带冒号。

示例：

- 绑定页短 ID：`C2:1E:D4:28`
- 我的设备完整 ID：`E9:48:C2:1E:D4:28`

`utils/device-id.js` 新增的 `formatBytes` 只负责显示任意完整字节序列；稳定身份校验仍使用 `canonical` / `isComplete`，仍严格要求 6 字节，不能用广播短 ID 放宽绑定或重连校验。

## Multi-image Projection

多图投屏继续沿用现有顺序上传、空闲槽位选择、失败即停止、后端记账和最终仅刷新一次的流程。变化仅限最终刷新索引：

1. 第一张成功写入电子纸设备时记录其真实槽位 `firstSuccessfulIndex`；槽位 `0` 是合法值，因此以 `null` 表示尚未成功。
2. 全部图片上传完成后，仍只调用一次 `deviceBle.refreshScreen`。
3. 刷新参数由最后一张成功图片的槽位改为 `firstSuccessfulIndex`，使电子纸设备最终显示本批次第一张成功上传的图片。
4. 异步刷新、错误吞吐、连接间隔回落及投屏成功判定保持不变。

## Orientation Export

- 竖向 `portrait` 构图固定顺时针旋转 `180°` 后导出，不读取任何设备的 `rotationDegree`。
- 横向 `landscape` 维持现有逻辑：读取目标设备 `rotationDegree`，缺失或异常时回退 `270°`。
- 编辑图的 `_bakeToFile` 与未编辑图的 `coverCropOne` 都执行竖向 `180°`，避免只改一条路径造成方向不一致。
- 手机端对烘焙文件使用相反角度显示，用户预览仍保持构图时的正向画面；缓存指纹包含实际导出角，旧方向缓存不会被误复用。
- 输出尺寸始终是设备物理分辨率，不改变 seekink 出帧参数或 BLE 帧长度。
