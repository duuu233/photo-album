## Background

官方图库三个页面 2026-08-06 就上线了，但**数据一直是 `utils/gallery-api.js` 里的本地 mock**
（8 张写死的图 + 收藏关系存 Storage，换手机即丢）。本轮后端给出五个接口，按清单逐条对接。

## Solution

| 功能 | 接口 | 端上方法 |
| --- | --- | --- |
| 公共图库分类列表 | `GET /Client/Product/getImgCategory` | `getCategories` |
| 公共图库列表 | `GET /Client/Product/getProductImgList` | `getPhotos` |
| 公共图库详情 | `GET /Client/Product/getProductImgDetail` | `getPhotoDetail` |
| 图片收藏/取消收藏 | `POST /Client/Product/setImgCollected` | `toggleFavorite` |
| 用户图库收藏列表 | `GET /Client/Product/getProductImgCollectionList` | `getFavorites` / `getFavoriteIds` |

`utils/gallery-api.js` 整个重写为真实接口层（走 `utils/request.js`，自动带
`userToken`/`terminal=3`/`language` 与两枚鉴权头），**对页面的字段名保持不变**
（`{id,title,url,thumbUrl,ratio,favorited}` / 详情 `{...,desc,sizes}`），所以 wxml 基本没动。

字段映射里三处**接错了页面照样渲染、只是数据不对**的地方（已由 `tests/gallery-api.test.js` 锁住）：

- `productImgId` 是 integer：页面拿它当 id 比对、还要进 URL，**归一为字符串**；
  提交给接口时又必须是数字（`setImgCollected` / `getProductImgDetail` 的入参都是 integer）。
- 详情的简介字段叫 **`content`**（不是 `desc`），收藏态是 **`isAlreadyCollected` 0/1**（不是布尔）。
- 列表是 `BasePageOutput`，判停**优先 `pageCount`**：只看条数会在「后端无视 `pageSize` 按自己的
  默认值分页」时提前停（购买记录页踩过同一个坑）。

### 页面侧随之而来的三件事

1. **分页**：后端列表默认 10 条/页，图库列表页与收藏页都改成滚到底续拉（`bindscrolltolower`，
   `lower-threshold=200`，脚注「上拉加载更多 / 加载中 / 没有更多了」同购买记录页口径）。
   ⚠️ 续页是**往两列里追加**（`appendColumns` 接着当前累计高度排），**不是**把全量重新分列 ——
   重新分列会把已经在屏上的卡片挪位，用户正看的那张会跳走。
2. **「全部」分类**：后端只给真实分类，而列表接口的 `categoryId` 可选（不传即全部）。
   端上在分类条首位补一项 `id: ''` 的「全部」并默认选中 —— 否则进页面只能看见第一个分类。
   ⚠️ 它的 id 是空串，判空**不能**写成 `if (id)`，否则「全部」会被当成没选中。
3. **图片高度**：见下面的缺口①。

## Technical Decisions

- **`setImgCollected` 的返回值不参与判定**。它的出参是 `BaseOutput<boolean>`，而这个布尔到底是
  「操作是否成功」还是「切换后的收藏态」文档没写。端上一律按**取反当前态**推新状态：两种语义下
  这都是对的（真失败会走 reject），原值打进日志供后续对账。所以 `toggleFavorite(id, 当前态)`
  多收了一个入参 —— 三个调用页都得把自己的当前态传进来。
- **先请求成功再改 UI**（不做乐观更新）：失败时红心闪一下又弹回去，比慢 200ms 更难受。
- **收藏页取消后重拉、图库列表页只改那一张**：两页诉求不同 —— 收藏页那张图要消失，
  图库列表那张还在原位，重拉只会把用户正看的卡片挪走。
- **`getFavoriteIds()` 静默失败返回空数组**：未登录/接口异常只让红心显示成描边，
  不打断图库浏览，也不弹红字（点击本身仍然可用，以详情/收藏列表为准）。

## Risks

⚠️ **两处后端缺口，端上在兜；补齐后端上兜底即可删**：

1. **列表项没有图片宽高/比例**（`ClientProductImgApiOut` 只有 `img`/`imgThumb`/`productImgId`/`title`）。
   瀑布流要在渲染前把高度占住，现在先按 `DEFAULT_RATIO = 0.75` 占位、图片 `bindload` 拿到真实
   宽高后校正**那一张**（只改高度，不重新分列）。
   代价：首屏所有卡片同高、图加载完各归其位时会有一次轻微重排；分列也因为初始比例相同而退化成
   奇偶交替，两列高度可能不齐。**请后端在列表项补 `width`/`height` 或 `ratio`**（端上两种写法都认，
   补上即自动生效）。
2. **列表项没有收藏态**（只有详情有 `isAlreadyCollected`）。图库列表的红心要按收藏态显示，
   现在每次进图库额外拉一页收藏列表（200 条）在端上标记。
   代价：多一个请求；收藏超过 200 条时，第 200 条之后的图在列表里会显示成未收藏（点进详情仍是对的）。
   **请后端给 `ClientProductImgApiOut` 补 `isAlreadyCollected`**。

其它：

- 详情页的「适用设备尺寸」上一轮已按产品要求去掉，`productSizeList`/`productSizes` 仍解析进
  `photo.sizes` 备用（后端有这个字段，端上不渲染）。
- mock 时代的 8 张示例图与 `getFavoriteCount()` 一并删除；「我的」页早已不显示收藏数，无影响。
