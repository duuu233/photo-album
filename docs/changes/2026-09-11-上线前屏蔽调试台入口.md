# 2026-09-11 上线前屏蔽调试台入口（小程序）

## 需求

> 【相册小程序】【相册APP】查看下是否有调试台的入口，准备上线了，屏蔽调试台的入口。

## 一、查到的入口（小程序）

调试台本体是 `subpackages/device/debug/debug`（`app.json` 的 `subpackages/device` 分包里），
它能对设备发**任意** BLE 指令——包含 `0x12 删除图片`、`0x13 改连接间隔`、「保存给真实投屏」
覆盖全局传输参数——而且整页**未接多语言**。绝不能暴露给最终用户。

进它的路**有两条**，都在绑定页 `subpackages/device/bind`：

| # | 位置 | 形态 | 备注 |
| --- | --- | --- | --- |
| 1 | `bind.wxml:15` | 页面顶部「🔧 硬件联调调试台」卡片，`bindtap="openDebug"` | 显眼，原注释写了「需要屏蔽时注释掉本段即可」 |
| 2 | `bind.wxml:44` | **附近设备列表每一行** `bindlongpress="openDebug"`，长按某台设备直接带 `deviceId` 进调试台 | **隐藏入口**，藏在 `nearby-device` 的一长串属性里，只改 wxml 第 1 条会把它留在线上 |

⚠️ 第 2 条是本次排查的重点：它没有任何可见提示，靠读 `bind.js` 里 `openDebug` 的调用方才
能发现。

## 二、改法：**只放行开发版**，体验版与正式版都屏蔽

产品口径（2026-09-11 追加）：

> 现在只要开发版可以看到就行，体验版也屏蔽入口，包括正式版。

所以判定不是"拦正式版"，而是**只认开发版**：

```js
wx.getAccountInfoSync().miniProgram.envVersion === 'develop'
```

抽成 `utils/system.isDevEnv()`（放在 `isDevTools` 旁边，同属环境判定）。读法与
`utils/request.js:9` 判 mock 那份同源，但口径更严：那边只拦 `release`，这里把 `trial`
也拦掉。**取不到环境信息时返回 `false`（按"不是开发版"处理）**——宁可在某台设备上少一个
入口，也不能把内部入口漏到体验版或线上。

⚠️ **为什么体验版也要拦**：体验版是要发给外部人（客户、测试、渠道）试用的，调试台能
`0x12` 删图、能覆盖全局传输参数，发出去一样是事故。开发版（含微信开发者工具）`envVersion`
就是 `develop`，所以日常联调完全不受影响。

为什么不直接删代码或从 `app.json` 摘掉页面：调试台是硬件联调的长期工具，删了下次对接要
重写；从分包摘掉则连开发版都用不了。按环境关入口是唯一既上线安全、又保留联调能力的做法。

### 三道拦截

| 层 | 位置 | 作用 |
| --- | --- | --- |
| ① 不渲染 | `bind.wxml:15` 加 `wx:if="{{showDebugEntry}}"`；`bind.js` data 新增 `showDebugEntry: false`，`onLoad` 里置 `system.isDevEnv()` | 体验版/正式版看不到那张卡片 |
| ② 不放行 | `bind.js openDebug()` 开头 `if (!system.isDevEnv()) return` | 兜住 ①，**并且兜住长按那条隐藏入口**——它不走 wxml 的 `wx:if` |
| ③ 不可达 | `debug.js onLoad()` 开头：非开发版直接 `navigateBack`（失败退到首页 `switchTab`） | 页面即使没有入口按钮，仍可能被分享卡片、扫码或历史路径打开 |

②、③ 是有意的冗余：①只管"看不见"，②才管"点不动"，③管"绕过前两层也进不去"。

## 三、相册 APP（Flutter）：调试台**本来就已屏蔽**，不需要改

- `bleDebug`（硬件联调调试台，对齐小程序那一页）已经是**双重** `kDebugMode` 门禁：
  - 入口卡片 `bind_device_debug_entry.dart` 在 release 下 `return const SizedBox.shrink()`；
  - 路由 `app_routes.dart:181` 在 release 下不给 builder。
  - 绑定流程三态（searching / found / not-found）都只用这一个卡片组件，没有第二条路。
- 另有一页 `blePerf`「投屏性能自检」，入口是**设置 → 更新 BoltStar → 连点版本号 7 次**
  （3 秒内），**刻意在正式包里保留**。它不是调试台：只读链路事实（MTU/分包/写方式）、
  RTT 间接实测连接间隔、跑一次纯 BLE 吞吐测速，**不发任何写设备/删除类指令**。
  保留的理由写在 `ble_perf_page.dart` 头注释：iOS 端 CoreBluetooth 没有 API 能读连接间隔、
  `CrashLogger` 只有 Android 实现、release 包 `debugPrint` 不输出、没有 Mac 拿不到 Xcode
  日志——「0x13 请求的 15ms 生没生效」只能靠这一页在机内自证。
  **本次未动**；要不要一起关由产品决定（关掉等于放弃 iOS 正式包里唯一的性能自证手段）。

### 上线前自检清单

| 环境 | `envVersion` | 期望 |
| --- | --- | --- |
| **开发版 / 微信开发者工具** | `develop` | 绑定页顶部能看到「🔧 硬件联调调试台」卡片，点进去正常；长按某台设备也能带 `deviceId` 进去 |
| **体验版** | `trial` | **没有**那张卡片；长按设备行**没有任何反应**（只触发选中态）；旧的调试台分享卡片/历史路径打开后立刻退回 |
| **正式版** | `release` | 同体验版，全部不可达 |

体验版这一档是 2026-09-11 产品追加的要求，**别漏测**：它和正式版走的是同一条
`!isDevEnv()` 分支，但只有真正发一个体验版才能验证 `envVersion` 确实是 `trial`。
