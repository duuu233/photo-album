# 2026-10-27 WiFi 版配网：按设备入网流程补齐国家码、绑定先于轮询

> 分支：`main-wifi`；修改前：a8317c7。依据：[docs/wifi/设备入网流程.md](../wifi/设备入网流程.md)（2026-10-27 最终流程）。

## 对照文档补的缺口

| 文档要求 | 改前 | 改后 |
|---|---|---|
| 步骤 2 三条 BLE 指令：WiFi 信息 → `mqtt_config` → 国家码（2.2、3.2） | 没有国家码 | `mqtt_config` 之后发 `wifi_set_country_code`，小程序固定 `{ country: '01' }` |
| 国家码回执（3.2、5.1） | — | `pending=1` 优先，暂缓执行也继续；`result=0` 通过；无 pending 且 `result≠0` 换新 msgid 重试一次，仍失败继续；等不到回执不重试、继续。国家码始终不阻塞配网 |
| msgid：13 位毫秒 + 3 位随机，共 16 位，重试换新（3.1） | 13 位毫秒 | `blufi.newMsgid()` 生成 16 位；`session.request` 可传入 msgid，日志「参数」行记下实际 msgid |
| BLE 回执超时建议 5 秒（2.2） | `mqtt_config` 等 10 秒 | `mqtt_config` / 国家码都等 5 秒 |
| 三条指令都在步骤 2 完成，完成后断开 BLE；步骤 3 设备侧无状态上报（2.2） | 步骤 3 才发「连接 WiFi」并经蓝牙等 30 秒 WiFi 状态报告 | 国家码之后发「连接 WiFi」（0x03），步骤 2 结束即释放蓝牙；不再等 WiFi 状态报告 |
| 绑定必须先于在线查询；步骤 3 绑定，绑定失败不轮询（约束 1、2.2） | 先轮询在线、上线后才绑定（10-26 产品调整的顺序） | 步骤 3 老服务绑定，失败停在步骤 3；步骤 4 才轮询在线 |
| 503 是权限服务不可用，不按配网失败处理（2.2） | 超时一律「设备联网超时」 | 503 继续轮询；超时时最后一次仍是 503 则提示「服务暂时不可用，请稍后重试」 |
| deviceId 统一 12 位大写十六进制，绑定也用这个格式（约束 7） | `addUserProduct` 的 `deviceId` 带冒号 `AA:BB:…` | ~~传不带冒号的 12 位~~ 同日产品确认后改回带冒号，见文末「产品确认」 |

日志【流程N】标签按新文档第二节编号：③ 蓝牙连接、④ 下发 WiFi、⑤ MQTT、⑥ 国家码、⑭ 老服务绑定、⑮ 轮询在线（原 ⑦ WiFi 状态报告已不再采集）。
手机发出的自定义数据帧（`mqtt_config` / 国家码）一律整帧打码，内容看上一行「参数」（`pwd` 打码）。

## 同日追加：MQTT 参数改调接口获取

后端提供 IoT 接口 `GET /api/device/provisioning/mqtt`（Header `userToken`，返回 `{ code, msg, data: { host, port, usr, pwd } }`）：

- `utils/iot-api.js` 新增 `getProvisioningMqtt`，走 IoT 客户端（401 重登、503 不登出）。
- `utils/wifi-provision.js` `getMqttConfig` 改为调该接口：每次配网现取，不缓存、不落本地；`host` / `port`（转数字，须大于 0）/ `usr` / `pwd` 缺任一项按取不到处理。
- 取参数放在第 2 步最前面、连设备之前：接口失败 / 参数不完整 → 「获取设备网络配置失败，请稍后重试」，401 →「登录已失效，请重新登录」，都停在第 2 步，不下发 WiFi，避免设备只收到半套配置。原「config 为空则跳过 mqtt_config」分支删除，`mqtt_config` 每次都发。
- 日志：「接口【配网 MQTT 参数】GET …」+「参数 无」+「返回 {…pwd:（已隐藏）}」；下发帧仍整帧打码。
- `utils/config.js` 删除 `iotMqttConfig`（含设备账号密码）。注意：该密码仍在仓库历史提交里，是否轮换由后端决定。
- 测试：`tests/wifi-provision.test.js` 按「先取参数再下发」调整，新增接口失败 / 401 / 参数不完整不动设备、port 字符串转数字用例。

## 同日追加：密码不记录、响应不缓存（产品要求）

- 不记录密码：`utils/blufi.js` 新增 `txFrameHex`，手机发出的 WiFi 密码帧（数据帧 0x03）与自定义数据帧（0x13，含 `mqtt_config`）**不把原始字节交给任何监听方**（`frame` 事件 `hex` 为空、`redacted: true`），日志从源头拿不到密码；配网日志原有打码保留。接口返回只记 `pwd:（已隐藏）`。
- 响应不缓存：`getProvisioningMqtt` 请求头带 `Cache-Control: no-cache, no-store`、`Pragma: no-cache`；客户端不存 Storage、不放模块 / 全局变量，参数只在 `run()` 局部变量里，`mqtt_config` 发出（或发送失败）后立即置空。每次配网重新请求。
- 服务端响应头建议同样返回 `Cache-Control: no-store`（前端无法控制，待后端确认）。
- 测试：`tests/blufi.test.js` 加带密码帧不出 hex 用例；`tests/iot-foundation.test.js` 加不缓存请求头用例。
