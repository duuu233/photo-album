# 2026-11-04 WiFi版分享链接有效期校验

> 分支：`main-wifi`｜依据：服务端新增接口 `GET /Client/UserProduct/getCurrentTime`（获取当前时间戳，`retData` long）、`GET /Client/UserProduct/chkTimeValid`（入参 `currentTime`，校验时间是否有效，`retData` boolean）

## 做了什么

在 [2026-10-29 简化版分享](2026-10-29-WiFi版设备分享简化版.md) 的流程上加有效期：分享时取服务器时间戳写进卡片，被分享人点开卡片时用这个时间戳校验是否过期。过期时长由服务端决定，端上不按本机时间判断、不换算单位。

| 位置 | 改动 |
|---|---|
| `utils/api.js` | 新增 `getServerTime`（`getCurrentTime`，返回数字串，取不到算失败）、`checkShareTimeValid(currentTime)`（`chkTimeValid`，`true` 为仍有效）；两个都不自动弹错 |
| `utils/wifi-share.js` | 卡片路径新增参数 `t`（分享时的服务器时间戳，原样）；`parseAcceptQuery` 缺 `t` 或不是正整数时按无效处理（有效期上线前发出的卡片没法校验，一律显示「分享链接无效」） |
| 分享列表 `wifi-share` | 进页面取一次时间戳，取不到时「分享设备」置灰，点一下会重取，取到后换回分享按钮并提示再点一次；真正分享时 `onShareAppMessage` 返回 `promise` 再取一次最新的，3 秒内没取到或失败按默认参数（进页面时的时间戳）发出。开发版「复制测试参数」复制前也取一次最新的 |
| 接受页 `wifi-share-accept` | 已登录时进页面就校验一次（按钮显示「校验中…」），过期显示「分享链接已过期，请让对方重新分享设备给你」+ 返回首页；校验失败不拦。点「接受」时再校验一次并以这次为准：过期换成过期卡片，校验不了提示「暂时无法校验分享链接，请稍后重试」，都不绑定。未登录不校验（接口要登录态，401 / 406 会被统一拉去登录页），登录后回到本页再校验；登录前记下的卡片带着原时间戳 |

- 服务端口径（同日确认）：`chkTimeValid` 只看 `retData` 布尔值，`true` 有效、`false` 过期。`retCode` 非 200 但带了布尔 `retData` 的也按该值算；登录失效 / 冻结（401 / 405 / 406 / 409）、网络失败或没有布尔值时按校验失败处理。
- 控制台：`[设备分享] 获取服务器时间戳失败`、`[设备分享] 链接有效期校验 <时间戳> 有效 / 已过期`、`[设备分享] 链接有效期校验失败`。
- 仍然没有一次性 / 撤回，有效期内卡片被转发，拿到的人都能加入。

## 待确认

- `getCurrentTime` 返回的单位（秒 / 毫秒）与 `chkTimeValid` 的有效时长：端上原样透传，按服务端口径。
- `chkTimeValid` 是否只校验时间：卡片其余参数（设备号、所有者）未参与校验，`addUserProduct` 仍需服务端兜底。
