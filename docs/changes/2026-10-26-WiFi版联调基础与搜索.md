# 2026-10-26 WiFi 版 STEP 0 联调基础 + STEP 1 搜索

> 分支：`main-wifi`；修改前：445d35e。依据：[docs/wifi/对接开发进度.md](../wifi/对接开发进度.md) STEP 0 / STEP 1、[前端对接文档_草稿.md](../前端对接文档_草稿.md)。

## STEP 0 联调基础

IoT 服务与 BoltFox 老服务是两套口径（返回 `{code,msg,data}`、503 不是登录失效），单独建一层客户端，不改老服务的 `utils/request.js` 判定逻辑。

- `utils/config.js`：`iotBaseURL = https://iot.boltfox.cn`、`iotWsURL = wss://iot.boltfox.cn/ws/push`。
- `utils/iot-errors.js`：统一错误码表（4000/401/403/404/4040/4041/4044/4045/4130/429/503/5000~5003），每码给中文文案和处理方式 `action`：
  `relogin`（401）/ `retry`（503、429、5xx 等）/ `none`。401/403/404/503 以 HTTP 状态为准，其余以 body.code 为准；429 读 `data.retryAfter`，没有再读 Header `Retry-After`；码表外的 5xx 按服务异常可重试；码表外的业务码退回服务端 `msg`。
- `utils/iot-request.js`：Header `userToken`（同一个登录 token）；GET 参数自己拼 url、空值不拼；401 走老服务同一套登出引导（`request.expireSession`），503 不动登录态；网络失败只给 GET 静默重试 2 次，POST 不重发；错误文案前缀「接口(IoT)-」。
- `utils/iot-ws.js`：单例、按需连接（App 启动不连，BLE 版用户用不到）。Header `userToken` 握手；`subscribe/unsubscribe` 记账，连上 / 重连后自动补订；每 30s `ping`；断线 1s、2s、4s… 上限 30s 退避，回前台立即重连；重连成功的 `state` 事件带 `reconnect:true`，页面据此补查状态；握手 401 停止重连。`app.clearSession` 时 `close()`。
- `utils/iot-api.js`：先放 `getDeviceOnline(deviceNo, since)`、`getDeviceInfo(deviceNo)`。
- 调试台（仅开发版）新增「IoT 联调」卡：连接 / 断开 WS、ping、按 deviceNo 订阅、查在线看错误码，结果都打到收发控制台。

## STEP 1 搜索

- `utils/broadcast-match.js`：后台广播 ID 带 `*` 为 WiFi 模板，按 `*` 拆前缀 / 后缀，中间正好 12 位（字母数字）取作 deviceId，大小写不敏感、deviceId 转大写；不含 `*` 为蓝牙版，**沿用原来的包含匹配**（扫描白名单、搜索尺寸、绑定选产品都是这个口径，改完全匹配会让带后缀的现网广播名搜不到）。
- `utils/bluetooth.js`：新增 `includeWifi` 选项，只有搜索设备页传；该订阅者按模板放行 WiFi 设备，并给每台标 `commType`（`WIFI` 带 `wifiDeviceId` / `BLE`）。不传时行为与之前一致：连接前扫描、自动重连、调试台都不会把 WiFi 设备当候选。产品列表拉不到时兜底名单加 `IJ_*`。
- `utils/api.js`：`getProductByDevice(deviceNo)` 调 `GET /Client/Product/getProductByDevice`；静默、不做网络重试（`request.js` 新增 `retry:false`）；不做结果缓存（同日按产品口径去掉了原先「查到缓存 5 分钟」，与老逻辑一致），重新搜索全部重查。
- 搜索设备页：
  - 广播名后挂「WiFi版」（青绿）/「蓝牙版」（蓝）标签，带小图标，与选中态的橙色错开；标签不增加卡片高度。
  - WiFi 行：设备ID 显示 12 位 deviceNo；第二行按查询状态显示「规格查询中… / 型号 · 尺寸 / 未知设备（警示色）」，同一次搜索每台只查一次，重新搜索时查不到的再查一次。
  - 选中 WiFi 设备时底部按钮为「立即配网」：查到规格 → 停扫进 WiFi 配置页；未知设备 → 弹「未知设备，请联系客服开通」、不进配网；还在查 → 提示稍候。蓝牙设备的「立即绑定」流程未改。
- 新增两张静态页（`subpackages/device/wifi-config`、`wifi-provision`）：
  - WiFi 配置：头图（手机 → 设备 → 云）、「设备仅支持 2.4G WiFi 配网」、WiFi 名称（右侧切换图标弹列表，点选即回填、无确认按钮）、WiFi 密码（明文）、下一步。列表目前是示例数据，弹层上有标注；密码不进页面路由。
  - 配网状态：同一头图、「设备正在进行配网」、「请将手机靠近设备，保持网络连接稳定」、四个状态（手机网络正常 / 设备网络配置已完成 / 设备正在连接Wi-Fi / 设备正在连接云端）。现在按固定节奏演示：执行中转圈、通过打勾，全部通过后标题改「设备入网成功」并出「立即体验」（静态阶段回首页）；失败态打叉、标题改错误文案、出「重新配网」「取消」，开发调试可带 `?demo=fail` 看失败样子。
- 新图标：`wifi-provision-art.svg`（手机 → 设备 → 云，品牌橙）、`badge-wifi.svg`、`badge-bluetooth.svg`、`wifi-switch.svg`。

## 同日追加：尺寸读 sizeModel、未知设备拦截补强

反馈：后台产品新增 `sizeModel`（如「13.3寸」），搜索列表要直接显示、没有显示「--寸」；「查不到 / 返回空 / 失败显示未知设备、禁止连接」和「未知设备点击直接弹窗」两条没有生效。

本机拿不到登录态，未能看到 `getProductByDevice` 的真实返回，按代码排查出三处会让这两条失效，一并改掉：

- **WiFi 设备被当成蓝牙版**：识别只认后台写成 `IJ_*` 的模板；后台若写成不带 `*` 的 `IJ_`，会走蓝牙版包含匹配，设备显示为「蓝牙版」，不查规格、点「立即绑定」走蓝牙流程，自然没有未知设备拦截。
  现在 `broadcast-match` 内置 `IJ_*` 模板（WiFi 前缀按约定固定为 `IJ_`），广播名合模板的一律是 WiFi 版；后台另配的 `*` 模板仍优先。
  非搜索页的扫描入口一律不收 WiFi 设备（包括包含匹配或厂商数据能对上的情况）。
- **空壳记录被当成查到**：原先只要有 `sizeModel`、或 `productId` 为 0 也算查到。现在「查到」只认有效 `productId`（非空、非 0）或非空产品名；`null` / 空对象 / 字段全空或为 0 的记录都算查不到 → 未知设备。（`api.normalizeWifiProduct` 已导出供测试。）
- **点行没有反应**：原先点行只是选中，要再点底部「立即配网」才弹窗。现在 WiFi 行点击即处理：未知设备当场弹「未知设备，请联系客服开通」且不选中；查到规格的选中并进 WiFi 配置页；规格还在查时提示稍候。底部按钮行为不变。蓝牙行仍是点选 + 「立即绑定」。
- 尺寸：WiFi 行第二行改为直接显示 `sizeModel`，没配显示「--寸」（不再拼产品名）。蓝牙行的尺寸仍按 10-23 口径（匹配到产品才显示，没配不显示），未改。

## 同日追加：规格查询不缓存、返回形状兼容

- 去掉 `getProductByDevice` 的 deviceNo 缓存：老逻辑里搜索列表只缓存产品列表（`getProductList` 整次会话复用），没有按设备查询这一环，也就没有可沿用的缓存，按「没有就不做」处理。每次搜索实时查，重新搜索全部重查；同一次搜索里同一台只查一次（边搜边显示会反复回调同一台）。
