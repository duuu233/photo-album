# 2026-10-29 WiFi版 TF 卡本地模式与设备详情改版

> 分支：`main-wifi`｜依据：[前端对接变更说明（2026-10-29）](../wifi/前端对接20261029.md)、产品口径（详情页改版、TF 卡、本地模式下的操作限制、投屏入口过滤）

## 做了什么

### 投屏进度页

WiFi 投屏结果页中间不再放投屏图片，改为状态图标，与蓝牙版结果页同一组素材：进行中 `upload-icon01`、全部成功 `upload-icon03`、有失败 `upload-icon02`。多张时下方列表的缩略图保留。

### 设备状态「本地模式」

- `utils/wifi-status.js`：`status=LOCAL_TF` → `local`，文案「本地模式」（首页设备卡、我的设备卡、WiFi 详情同一套映射，紫色）。按对接说明一.4，**不认识的新状态值按「状态未知」降级**（原来按 `online` 回退）；没有 `status` 字段的旧响应仍按 `online` 回退。
- 本地模式下不允许的操作（投屏、轮播设置、TF卡，以及轮播设置页的「保存」）按钮照常可点，只提示「当前设备状态：本地模式，请恢复设备网络再试」。设备信息、休眠设置、消息中心、分享、解除绑定、删除设备照常。WiFi 版目前没有 OTA 入口，无需处理。
- 新增 `projectBlockedTip`（投屏严格口径：只放行在线；离线 / 本地模式 / 查不到一律「设备不在线」，休眠 / 关机沿用原提示）、`queryBlockedTip`（保存前查一次，查不到交给接口）、`filterPickable`（选择设备列表过滤）。

### 投屏入口

| 位置 | 处理 |
|---|---|
| AI 生图、官方图库的「选择投屏设备」列表 | 离线 / 本地模式 / 状态未知的 WiFi 版不进列表；一台都没有时提示「暂无可投屏的电子纸设备」。蓝牙版不受影响 |
| AI 生图选中 WiFi 版 | 原来没接 WiFi 版（会去连蓝牙），现在同官方图库：不连蓝牙，确认在线后带 `isWifi` 进预览 |
| 我的上传：选中 WiFi 版照片点投屏 | 离线 / 本地模式 / 状态未知提示「设备不在线」；删除照片不受影响 |
| 投屏预览页「开始投屏」 | WiFi 版再查一次状态，离线 / 本地模式 / 状态未知不允许 |
| 轮播设置页「保存」 | 保存前查一次状态，本地模式 / 离线 / 休眠 / 关机直接提示，不发请求 |
| 我的设备 WiFi 卡「投屏」「轮播设置」 | 本地模式提示同上 |

### WiFi 设备详情改版

- 布局与蓝牙版一致：设备卡 → 「投屏 / 轮播设置」→ 功能栏 → 页底「删除设备」。电量挪到在线状态那一栏（仅在线时显示）。
- 功能栏依次：设备信息、休眠设置、消息中心、TF卡、分享设备（仅所有者）、解除绑定。
- 设备信息（新页 `subpackages/device/wifi-info`）：WiFi信号、WiFi名称、最后上线、最后心跳、固件版本；不再显示国家码。
- 解除绑定：只删设备记录（`delUserProduct`），照片保留。
- 删除设备（仅所有者，两级确认，样式同蓝牙版）：WiFi 版设备端不存图片，联网下的投屏和轮播都靠云端照片，所以「先删图片」只处理云端：① `clearUserProductImg` 清这台设备的相册记录（同蓝牙版一键清空的后端那一步）→ ② IoT `POST /api/device/photo/delete`（`all=true`）删该设备全部云端 bin → ③ `delUserProduct`。任一步失败就停下，不删设备。
- 所有者判定（`utils/wifi-share.js`）：`isToHave=1` 是所有者；带 `shareUserId` 的是接收者；两者都没有的老记录按所有者。

### TF 卡

- 详情功能栏「TF卡」：未插卡显示「未插卡」、不可点；有卡显示「已用/总量」（满 1GB 换算 GB）+ 箭头，点进 TF 卡设置；设备没上报过显示「--」、不可点。
- TF 卡设置（新页 `subpackages/device/wifi-tf`）：开关「TF卡播放」+ 说明「开启后设备将进入本地模式，无法进行APP投屏和取消本地模式，如需恢复请将设备重新入网。」
  - 打开：先查设备，只有在线且已插卡（`tfStatus=present`）才弹二次确认，否则不让开并提示；确认后 `POST /api/device/play-tf`，再等 WS `command.result`（`action=play_tf`，按 `msgid` 匹配，推送早于 HTTP 响应也认），30 秒超时，期间 loading 防重复点击。
  - 结果：`success=true` 提示「设备已切换，即将进入本地模式」；`false` 提示「设备拒绝切换（result=xxx）」；超时先补查一次，已是本地模式按成功，否则提示「设备未响应，请稍后重试」。错误码 4000 / 4041 / 4045 有对应提示。
  - 开关不存本地：开 = 设备当前是本地模式。设备重新入网（`ONLINE`）后开关自然回到关闭；刚接受切换、还没断开的那一小段（60 秒内）按开显示。协议没有远程切回指令，关闭只提示「如需恢复联网，请在设备上重新入网」。
- 本期不做 TF 卡清除。
- 消息通知新增类型 `TF_LOCAL_MODE`：「设备已进入本地模式」。

### 分享设备

- 新页 `subpackages/device/wifi-share`：第一栏固定所有者（头像、昵称、「所有者」标签，橙色底色区分），下面是接收者（头像、昵称、加入时间、移除），底部按钮「分享设备」。
- 数据用老服务已有的 `GET /Client/UserProduct/getShareUserProductList?deviceId=`（`api.getShareUsers`），返回 `avatar`、`userName`、`isToHave`、`userProductId`；列表里没有所有者时用当前用户资料兜底。
- **服务端缺口**：该接口没有加入时间字段（显示「--」）；邀请（生成分享）与移除成员接口尚未提供（见 [设备分享方案](../wifi/设备分享方案.md)），「分享设备」「移除」两个按钮当时只提示「即将上线」；同日已按简化版接上，见 [设备分享简化版](2026-10-29-WiFi版设备分享简化版.md)。
