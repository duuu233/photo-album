- **2026-07-25（二）·「来回切图预览照片闪一下、像重新加载」修复**：`preview.{js,wxml,wxss}` 三处都改。
  **根因是三条叠加**，只修其中一条都还会闪：
  1. **交接时机错**（主因）：`.preview-swiper` 的 `is-hidden` 与编辑层的挂载条件都是 `editing && !sliding`，
     即**同一次 `setData` 里 swiper 藏掉、编辑层刚挂上**。此时编辑层的 `<image>` 还没解码出画面，
     中间几帧露出的是 `.edit-clip` 的灰底 `#e6ecf4` —— 用户看到的「闪一下」就是它。
     → 新增 `editReady` 状态：编辑层**先挂着但透明**，等 `<image>` 的 `bindload` 到了才
     （a）编辑层显形（b）swiper 才加 `is-hidden`。交接期间**始终有一层在画**，不再露底。
     兜底：`EDIT_READY_TIMEOUT_MS = 800ms` 强制放行，防「新旧 src 恰好相同 → 小程序不再抛 load 事件」
     时永远停在过场态；`binderror` 同样放行。
  2. **编辑层被销毁重建**：`.edit-layer` 原来是 `wx:if="{{editing && !sliding}}"`，每次切图整层销毁，
     里面的 `<image>` 节点跟着没了，切回来必然重新下载 + 解码 —— 这就是「像重新加载」的手感。
     → 改成整层常驻（`wx:if="{{imageCount && editSrc}}"`），只切 `.edit-layer.is-hidden`
     （`opacity:0 + pointer-events:none`）。`switchImage` **不再置 `editing:false`**，改置 `editReady:false`。
     - ⚠️ 这里**必须用 `opacity` 而不是 `visibility/display`**：后两者在部分机型会让 `<image>` 推迟甚至
       不发起加载，`bindload` 永远不来，编辑层就再也显不出来（与第 1 条互锁）。`pointer-events:none`
       保证透明期间手势落到底层 swiper，不被本层 `catch*` 吞掉。
  3. **`wx.getImageInfo` 每次切图重跑**：`enterEdit` 每次都重新量图片原始宽高，远程 `url` 还要走一次
     下载，「来回切换」每次都得干等 → 新增 `_infoCache`（`src → {width,height}`，尺寸恒定所以永不失效），
     第二次起同步命中；并 `_prefetchNeighbors(index)` 预读左右各一张（顺带把远程图暖进微信图片缓存），
     第一次滑到也不用等。
  - **顺带去掉切图时的「处理中」蒙层**：原先 `_switchWithBake` 是**滑动那一刻**才 `wx.showLoading` +
    烘焙 `previewSrc`，蒙层本身就是一次打断。改为**空闲预烘焙**：手势松手 / 换向 / 转 90° 后
    `PREBAKE_IDLE_MS = 800ms` 无操作即 `bakePreviewForActive({ silent: true })` 静默出图。
    真正滑动切图时多半直接命中缓存秒返回，「开始投屏」也复用同一份缓存少出一次图。
    - 烘焙全部串到 `_bakeChain` 一条链上：预烘焙与切图烘焙**共用同一个离屏 `#cropCanvas`**，
      并发会互改画布尺寸导致出图错乱。`confirmProjection` 出图前先 `_clearPrebake()` 并 `await _bakeChain`。
    - `bakePreviewForActive(options)` 现在只是「入链」的壳，实际逻辑挪进 `_bakePreviewOnce`；
      `options.silent` 控制是否弹 `showLoading`。
  - 新增计时器 `_readyTimer / _prebakeTimer` 均已在 `onUnload` 清理；`restoreOrigin` 一并置
    `editReady:false` 并 `_clearPrebake()`。
  - ⚠️ 未真机验证。**Flutter APP 未同步**：`cast_preview_page.dart` 是原生 widget 树，没有
    「swiper 底图 + 编辑层」双层结构，本次三条根因里只有第 3 条（图片尺寸缓存）可能同样适用，
    需单独评估后再动。
- **2026-07-25（用户 4 条反馈修复）**：`preview.{js,wxml,wxss}` 三处都改：
  1. **切到横向时底层竖向图不再残留**：编辑层起来时（`editing && !sliding`）整条 `.preview-swiper`
     加 `is-hidden`（`visibility:hidden`）。根因是横向取景框比竖向矮，框上下会露出底层 swiper 里
     那张按**竖向**比例铺的原图。用 `visibility` 而不是 `wx:if`/`display:none`——后两者会销毁重建
     swiper，`current` 复位且切图过场会闪。
  2. **竖/横/原点击区放大**：可点范围即元素盒子，故把 `.tool` 撑大 `padding: 20rpx 56rpx`
     （每颗约 156×128rpx），`.tool-bar` 自身 padding 由 `28rpx` 收到 `8rpx`，卡片总高基本不变。
  3. **长按拖拽阈值 2s → 1s**：`LONG_PRESS_MS = 1000`，`.gesture-tip` 文案同步改「长按1秒后…」。
  4. **左右滑动切图不再闪回未裁剪原图**：过场里 swiper 显示的一直是**原图**（编辑是非破坏性的、
     从不落文件），所以切图瞬间会闪一下未裁剪的构图、切完再跳回编辑结果。改为**切之前先烘焙进
     预览缓存**：`_commitSwipe` → `_switchWithBake` → `bakePreviewForActive()` →（有编辑且指纹变了）
     `wx.showLoading('处理中')` + `_bakeToFile` 出图存 `image.previewSrc`，swiper 的 `<image>` 改取
     `previewSrc || tempFilePath || url`；**没编辑过的图不烘焙**，直接无缝切（原图与编辑层所见本就一致）。
     - **`previewSrc` 不覆盖 `tempFilePath`**（关键）：原图仍是编辑基准，切回来能继续拖；否则横向
       烘焙图（竖向文件、内容转过 270°）会被当成新原图，再进编辑层就是躺倒的。
     - 缓存指纹 `_editSignature`（src/方向/zoom/tx/ty/angle/frameW/baseScale）与投屏出图共用：
       `prepareProjectionImages` 命中即直接复用 `previewSrc`，同一组构图不重复出图（顺带省一次出图耗时）。
     - `restoreOrigin`（原图还原）会一并清 `previewSrc/_bakedKey`，否则过场里还会闪出还原前的构图。
     - 烘焙抽出 `_bakeToFile` + `_applyBakedFile` 两个纯函数，正式投屏出图与预览缓存**共用同一段几何**，
       保证「过场看到的」与「真正投出去的」逐像素一致。烘焙失败只 `console.warn` 并回退原图显示，不挡切图。
  - ⚠️ 均未真机验证。**Flutter APP 已于同日同步**：`cast_preview_page.dart` 按 07-22~07-25 的模型整页重写
    （常驻编辑层 + 竖/横取景 + 长按1秒拖拽 + 双指缩放旋转 + 转90° + 切图前烘焙预览缓存 + 横向 270° 导出铁律），

## 实现说明

### 交互模型：常驻编辑态 + 非破坏性状态

- 进入页面（`onReady`）/ 点「上一张/下一张」都会自动 `enterEdit()`：固定取景框 + 图片在框下自由
  单指平移、双指缩放+旋转（原「长按旋转/双指旋转」二选一的对比开关**已删除**，定版双指旋转）。
- **每张图一份编辑状态**（`this._states[index]` = `_edit` 快照：方向 + tx/ty/zoom/angle + 几何量），
  切图时保存、切回时恢复；**不落文件**。点「开始投屏」才统一出图（`prepareProjectionImages`）：
  - 状态真的动过（缩放/平移/旋转/切了横向）→ `bakeEditedImage` 按框内所见烘焙为设备物理分辨率新图；
  - 什么都没动（`isPristineEdit`）→ 等价未编辑：`cropW>0`/`imgBle` 原样保留（**imgBle 直传判定不被破坏**），
    其余走 `coverCropOne` 竖向中心裁切。
- 换图不再用 swiper：wxml 里 swiper 已删，改单编辑层 + 「上一张/下一张」按钮（多图才显示，端点置灰）。

### 竖向/横向（取代 07-20 的 VIEW_SWAPPED 总开关）

- `ORIENT_PORTRAIT / ORIENT_LANDSCAPE`，**按张记录**，默认 `DEFAULT_ORIENTATION = 竖向`
  （= 07-20 改版前的原始样子；若产品要默认横向，改这一个常量即可）。
- 切换只重算取景框与 cover 基准，并用 zoom 反向补偿保住图片的绝对显示大小/位置（`setOrientation`），
  夹取逻辑（`_clampTransform`）会在新框盖不满时自动把 zoom 顶上去——即「横向类似裁剪，超出部分拖动可见」。
- **导出（2026-07-22「调整三」起）**：画布 = 取景方向的可视区域分辨率，**无任何旋转**、所见即所得。
  - 竖向取景：设备物理分辨率（如 480×720），与旧行为一致；
  - 横向取景：宽高对调分辨率**直出**（如 720×480），裁剪图原样上传，方向适配由接口侧负责。
  - 旧方案（07-20 ~ 07-22 调整三前）：横向整幅转 270° 画进竖向画布 + 预览 `computeRotatedImgStyle`
    反向转正——已整链路删除，回滚从 git 历史找回。
  - ⚠️ 历史教训仍然有效：后端若按「上传图像素」出帧且不适配横向，设备按竖向行宽解析会无报错花屏
    （见顶部操作日志「调整三」风险备忘）。

### UI

- 分段控制器 `.orient-seg`：灰底容器 + 白色滑块（`transition: transform`）滑到选中项，选中文字橙色——仿 el-segmented。
- 右上角 `.rotate-fab`：跟随取景框右上角定位（JS 下发 px 坐标 + `translateX(-100%)`），`catchtap="rotate90"` 顺时针 +90°。
- 工具栏只剩「原图」（二次确认后清空该图全部编辑与已烘焙文件、恢复 `_origSrc`，并重新进入编辑态）。
- 「开始投屏」不再因编辑态置灰（编辑态是常驻的），仅投屏中防连点。
- 舞台高由 760rpx 收到 **680rpx**（多了分段器和切图按钮两行）；`STAGE_H_RPX` 已同步，两处改动必须成对。
