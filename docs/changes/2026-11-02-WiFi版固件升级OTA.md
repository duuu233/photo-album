# 2026-11-02 WiFi版固件升级（OTA）

> 分支：`main-wifi`｜依据：[前端对接变更说明（2026-10-31）](../前端对接文档20261031.md)、[前端对接文档草稿](../前端对接文档_草稿.md) 3.9 固件升级

## 做了什么

### 入口

- WiFi 设备详情功能栏「消息中心」之后新增「固件升级」：右侧显示设备当前固件版本（IoT `GET /api/device/info` 的 `firmwareVersion`，服务端已归一化为 `x.y.z`；读不到显示 `--`），有新版本时箭头旁亮红点（同蓝牙版）。本地有进行中的升级时显示「升级中」、不亮红点。
- 启动时的「强制升级」弹窗（`app.js checkForcedFirmwareUpgrade`）：当前选中设备是 WiFi 版时，本地有进行中的升级就不弹；「立刻更新」进 WiFi 版升级页，蓝牙版照旧。

### 版本来源与比对（`utils/wifi-ota.js evaluate`）

- 目标版本与固件包：老服务 `getDeviceDetail` 的 `newVersionNo` / `downloadPath`（与蓝牙版同一来源）。
- 当前版本：`firmwareVersion`（没有时用 `shadow.version`）。
- 两边都是 `x.y.z` 时按数字段比较，目标更高才算有新版本；目标不是 `x.y.z` 时退回「不相同即有新版本」。
- 当前版本为空或仍是旧格式（如 `M H:3 F:0.6.1`）：显示「暂时无法判断是否有新版本」+「重新检查」，不报错。
- 有新版本但固件包地址不是 http / https：显示「升级包信息不完整」，不下发。

### 升级页（`subpackages/device/wifi-ota`）

与配网状态页同一种形态（样式直接 `@import` 配网页）：插画 + 标题 + 说明 + 四步状态圈 + 底部按钮。

| 步骤 | 状态 | 文案 |
|---|---|---|
| 1 | `SENT` | 已下发，等待设备响应 |
| 2 | `DOWNLOADING` | 设备下载固件中 |
| 3 | `FLASHING` | 设备写入固件中 |
| 4 | `VERIFYING` | 升级完成（说明：等待设备重启，结果将通过消息中心通知您） |

- 「立即升级」：先按设备状态拦截（离线 / 休眠 / 关机 / 本地模式提示对应文案），二次确认后 `POST /api/device/ota`（`type=main`、`url=downloadPath`、`version=newVersionNo`）。
- 下发成功**立即**保存 `msgid`：独立 key `ota_inflight:{deviceNo}`，记录 `{ deviceNo, type: 'ota', msgid, version, baseVersion, status, lastStep }`，一台设备只留一条；读的时候类型不是 `ota` 的不认。
- 进度：每 3 秒 `GET /api/device/ota/status`，WS `ota.result` 按 `msgid` 匹配后立即按推送的状态刷新并补查一次；WS 重连后补查。页面隐藏时停轮询，回来继续。`elapsedSeconds` 显示为「已进行 X 分 Y 秒」。
- `VERIFYING`：四步全勾，标题「升级完成」，按钮「完成」，用户可离开。本地记录保留到终态。
- `FAILED` / `TIMEOUT`：在当前那一步打叉、后续不再执行，标题「升级失败」/「升级超时」，按钮「重新升级」「取消」。
- `SUCCESS` 不在步骤页口径内；万一跳过 `VERIFYING` 直接到了，也按完成收尾（说明改为「设备已重启，固件升级成功」）。
- 不认识的状态值：停在已到达的那一步转圈，不白屏、不判成败。
- 下发返回 `4045`，或 `4000`（OTA 接口上表示已有升级任务进行中）：提示「设备正在升级，请稍候」，页面切到「设备正在升级」，不显示成普通失败。

### 重新进入升级页

1. 本地有记录 → 先查一次状态：终态（`SUCCESS` / `FAILED` / `TIMEOUT`）或 `4044` 清记录，按正常检查走；
2. 仍是 `SENT` / `DOWNLOADING` / `FLASHING` → 直接进步骤页接着展示；
3. 已是 `VERIFYING` → 不进步骤页、不提示升级，显示「升级完成 · 等待设备重启」（这段时间设备上报的仍是旧版本，只比版本会重复提示升级）；
4. 查询失败（网络 / 503）→ 记录保留，按记录里的状态展示，下一轮再查。

### 消息中心

新增消息类型 `OTA_SUCCESS`「固件升级成功」、`OTA_FAILED`「固件升级失败」；详情行显示版本变化（如「0.6.1 → 0.6.2」），`reason=timeout` 追加「升级超时」，`reason=corrected` 按升级成功展示、不另加说明。

## 自行决定（可改）

- 升级类型固定 `main`（主控），FPGA 升级没有入口。
- `4000` 的服务端文案明显是别的问题（不含「升级 / 进行中」）时按普通失败提示，避免参数错误被当成「正在升级」。
- 轮询间隔 3 秒。

## 待确认

- 老服务 `getDeviceDetail` 对 WiFi 版设备是否下发 `newVersionNo` / `downloadPath`，`newVersionNo` 是否与设备上报同为 `x.y.z`。
- 固件包由设备自己下载，小程序不下载；request 合法域名沿用 `iot.boltfox.cn`，无需新增。
