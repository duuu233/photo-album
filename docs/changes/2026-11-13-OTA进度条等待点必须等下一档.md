# 2026-11-13 WiFi 固件升级进度条：19 / 39 / 59 / 79 必须等到下一档数值

> 分支：`main`｜依据：产品口径——0~20 由前端自己匀速走到 19，之后在 19 / 39 / 59 / 79 停住等 `progress` 上报（19 等 20、39 等 40、59 等 60、79 等 80），收到后继续前进；固件不上报（null）走到 98 停住

## 问题

2026-11-12 的 `utils/wifi-ota.js` `progressCap` 里有两条按状态直接放开到 98 的分支，会越过等待点：

- 进入 `FLASHING` 一律放到 98：例如收到 60 后状态变成写入，进度从 79 不等 80 直接走到 98；
- 进入 `DOWNLOADING` 但还没收到数值就放到 98：状态先于 20 到达时，19 不等 20 直接走到 98。

## 改动

| 情况 | 原上限 | 现上限 |
|---|---|---|
| 没收到任何数值（SENT / DOWNLOADING） | SENT 19、DOWNLOADING 98 | 19 |
| 收到 20 / 40 / 60 / 80（不论 DOWNLOADING 还是 FLASHING） | DOWNLOADING 39 / 59 / 79 / 98，FLASHING 一律 98 | 39 / 59 / 79 / 98 |
| 一个数值都没收到就进入 FLASHING（固件不上报） | 98 | 98 |
| VERIFYING / SUCCESS | 100 | 100（不变） |

- 状态只决定步骤，不再放开分档；下载阶段为 null 不算「不上报」（可能只是 20 还没到），仍停 19。
- 失败停住、只认收到过的最大进度、本地记录续走均不变；页面 `subpackages/device/wifi-ota` 未改。

## 涉及文件

`utils/wifi-ota.js`、`tests/wifi-ota.test.js`。

## 验证
