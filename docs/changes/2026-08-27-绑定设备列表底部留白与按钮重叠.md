# 绑定设备：搜到的设备列表压在「立即绑定」底下且滚不动（2026-08-27）

> 状态：**已修**，**未真机验收**
> 最后核对：2026-08-27
> 适用范围：微信小程序 绑定设备页（`subpackages/device/bind`）
> 上一版：2026-08-05 折叠屏适配（`.bind-content` 高度改用 page-nav 实测的 `--nav-h`）
>
> ✅ **仅小程序，且已核对 App 侧无此问题**：`bind_device_found.dart` 是
> `Column` + `Expanded(SingleChildScrollView)`，列表本来就吃剩余高度；「立即绑定」在
> `FigmaScreen` 的 `bottom` 槽里（`EdgeInsets.fromLTRB(24, 8, 24, 12)` + `SafeArea`），
> 是**流内**节点、不是绝对定位，压根不存在「按经验值猜列表高度」这回事。底部留白那 8px 也已经有了，无需同步。

## 一、现象

搜索到的设备一多：

- 列表下沿的设备项被贴底的「立即绑定」压住；
- 而且**滚不动**——被压住的那几台既看不全也划不出来。

顺带：列表滚到底时最后一张卡片贴着按钮，没有留白。

## 二、原因：列表高度是**猜**的，而且猜错了基准

列表高度原来写死一条经验值：

```css
.device-list { max-height: calc(100vh - var(--status-bar) - 940rpx); }
```

`940rpx` 这个量级其实估得不离谱（调试台横幅 ≈131rpx + 雷达 540rpx + 统计行 ≈92rpx +
按钮那条 160rpx ≈ 923rpx），**错的是基准和漏项**：

| 漏算 | 差多少（以 iPhone 13 / 390×844 计） |
| --- | --- |
| 减的是 `--status-bar`（状态栏），不是整个导航 —— 少减一个胶囊行 88rpx | ≈ 46px |
| 完全没减 `--safe-bottom`（全面屏手势条） | 34px |

两项合计 ≈ 80px，列表下沿因此落到「立即绑定」顶下方约 88px 处。

「滚不动」是同一个根因的第二段：越出来的那截仍在 `.bind-content`（`height: 100vh - --nav-h`）
之内、只是被绝对定位的按钮盖住，`scroll-view` 认为自己放得下全部卡片，于是**不产生滚动**——
用户既看不见也划不动，而不是「滚到底了」。

## 三、改法：只动 `.device-list` 一条规则

```css
.device-list {
  box-sizing: border-box;
  max-height: calc(
    100vh - var(--nav-h, calc(var(--status-bar) + 88rpx)) - 960rpx - var(--safe-bottom)
  );
  padding: 0 48rpx 24rpx;   /* 原来是 0 48rpx 8rpx */
}
```

- **基准换成整个导航** `--nav-h`（page-nav 回抛的实测值，含状态栏；取不到时按
  `状态栏 + 88rpx` 兜底，与 `.bind-content` 的高度用同一套算式）；
- **补减 `--safe-bottom`**；
- 经验值 940 → **960rpx** = 上面几块（调试台横幅 ≈131 + 雷达 500+40 + 统计行 ≈92）
  + 按钮那条（112 + 贴底 48 + 24 缝）；
- `padding-bottom` 8 → **24rpx**，就是这次要的底部留白（也给卡片投影让出空间）；
  配 `box-sizing: border-box`，让这段留白算在 max-height 之内，不再反过来把盒子撑高。

⚠️ **没动**别的：`.bind-content` 的高度算式、雷达/统计行/调试台的排布、卡片样式、
按钮与「扫描不到怎么办」的贴底位置、扫描中/空态两个分支——一律原样。

## 四、测试

`tests/bind-device-list-layout.test.js`（新增）：

- max-height 必须减 `--nav-h`（不是 `--status-bar`）和 `--safe-bottom` —— 当初漏的就是这两项；
- 底部 padding ≥16rpx，且 `box-sizing: border-box`；
- 把 wxss 里的 `calc()/var()/rpx/vh` 按三种机型（iPhone 13 / SE / 大屏安卓）真算成 px，
  断言「列表下沿 ≤ 按钮顶」、缝隙不超过 60px（白扔高度）、列表至少放得下一张卡（≈190rpx）。
  列表上面那几块的高度按 740~790rpx 的区间来卡：算下沿用上界（上界都不越过，实际更不会），
  算缝隙用下界。把 960 改回 940 用例立刻红。

## 五、待办 / 未动

- ⚠️ 真机未验。
- ⚠️ **`960rpx` 仍是「上面几块有多高」的经验值**，不是算出来的。调试台横幅（wxml 里注明
  「需要屏蔽时注释掉」）一旦下线，或雷达/统计行改尺寸，这个数要跟着调——用例会把差多少直接报出来。
  一劳永逸的做法是把 `.bind-content` 改成竖向 flex、让列表 `flex:1` 自己吃剩余高度，
  但那要动整页排布，这次没做。
- ⚠️ **折叠屏展开（宽而矮，1rpx 被放得很大）本页整体仍然挤**：雷达 500rpx + 调试台横幅几乎吃满一屏，
  这条 max-height 算出来是负的（CSS 按 0 处理，列表整个不显示），上面那几块自己就压到按钮上了。
  这是本页版式在该形态下的老问题（改前也一样），本次没动，用例里也不含这一档。
