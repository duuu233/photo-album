# 图片详情：白卡不再压住图片下沿，整张图必须看得全（2026-09-01）

> 状态：**已改**，⚠️ **两端均未真机验收**（App 侧本机无 Flutter SDK，`dart analyze` / `flutter test` 没跑）
> 最后核对：2026-09-01
> 适用范围：微信小程序 `subpackages/gallery/detail` + Flutter `official_gallery_detail_page.dart`
> 上一版：[2026-08-21 图片详情大图与白卡断层修复](2026-08-21-图片详情大图与白卡断层修复.md)
> 权威来源：产品需求原文「下面的文字部分不要挡住图片，让图片完整展示出来，下面适当减少高度」
>
> 🔁 **本轮两端都要改**（与 08-21 那次只改小程序不同）：那次修的是小程序特有的「起点差一个导航高度」，
> App 的 `Stack` 两者同起点、本来就没有；而这次的两条毛病 App 一条不落，甚至多一条（见第五节）。

## 一、现象与要求

1. 白卡（`.detail-card` / App 的白色容器）**压在图片下沿上** 3vh —— 设计稿本来如此（圆角压图），
   但产品复看后判定「下面的文字挡住了图片」，要求接缝处**一点都不许压**。
2. 「让图片完整展示出来」：大图是 `absolute` / `Positioned` 垫在滚动区**下面**、**不跟着滚**，
   往上滑只会让白卡盖住更多 —— 所以**一屏放不下的部分等于永远看不到**。
   比例长一点的竖图（`heroPad` 越过一屏）下半截就这么一直在屏幕外。
   这一点 08-21 的文档里当时是作为「版式固有取舍」记下的，本轮产品明确不接受。
3. 「下面适当减少高度」：底部文字区收到**够用就行**，剩下的高度全让给图。

## 二、改法（两端同一套账）

| | 小程序 | Flutter |
| --- | --- | --- |
| 底部文字区最小高度 | `--detail-card-min: 420rpx` + `--safe-bottom` | `_kCardMinHeight = 210` + `padding.bottom` |
| 大图高度上限 | `--hero-max: calc(100vh - var(--detail-card-min) - var(--safe-bottom, 0px))` | `size.height - (_kCardMinHeight + bottomInset)` |
| 大图高度 | 内联 `height: {{heroPad}}vw` + `max-height: var(--hero-max)` | `math.min(size.width * _heroAspect, maxHeroHeight)` |
| 白卡起点 | `calc({{heroPad}}vw - {{navHeight}}px)`，`max-height` 与大图同源封顶 | `spacerHeight = heroHeight` |
| 图片画法 | `mode` 由 `aspectFill` 改 **`aspectFit`** | `fit` 由 `BoxFit.cover` 改 **`BoxFit.contain`** |

三处细节：

- **420rpx / 210 是同一笔账**：内边距 32 + 标题行（收藏胶囊）72 + 简介 22 + 两行 90 +
  让开贴底按钮的 196 ≈ 420rpx；420rpx 在 375pt 屏上正是 210pt，两端一致。
- **白卡起点仍要减 `navHeight`**（小程序独有，08-21 那条不能丢）：大图从**屏幕顶端**起算、
  滚动区从**导航栏下沿**起算。这轮只是把第三项 `− 3vh` 删掉，白卡顶＝图片底。
  实测导航高度现在还要以 `--nav-h: {{navHeight}}px` 落到根容器上，供留白的 `max-height` 用。
- **必须改成 aspectFit / contain**：封顶之后盒子比例不再等于图片比例，
  `aspectFill` / `cover` 会「放大填满再裁掉两边」—— 那就把「不裁图」的老结论（2026-08-13 需求 4）
  又推翻了。没被封顶时（绝大多数图）两者逐像素相同。

⚠️ **不用 CSS `min()`**：小程序 iOS 端仍有老 WKWebView，不认 `min()`/`clamp()` 时整条声明会被丢掉、
大图直接塌成默认尺寸；`max-height` 所有内核都认，效果一样。

## 三、这轮之后各屏的样子（iPhone 13，390×844，导航 91，安全区 34）

| 图片 | 大图高度 | 白卡顶 | 底部文字区 |
| --- | --- | --- | --- |
| 3:4 竖图（兜底比例） | 520 | 520 | 324 |
| 16:9 横图 | 219 | 219 | 625 |
| 长图（钳到 240） | 600（**封顶**，两侧留底色） | 600 | 244 |

## 四、测试

`tests/gallery-detail-hero.test.js` 重写：不看字符串，把 wxml 的内联表达式与 wxss 的 `max-height`
**一起算成 px**（三种机型 × 四种比例，含一张会被封顶的长图），断言三条：

1. 白卡顶 = 图片底（既不压图，也不留断层）；
2. 图片下沿 ≤ 一屏 − 底部文字区（长图不再有下半截落在屏幕外）；
3. 底部文字区 ≥ `--detail-card-min` + 安全区（放得下标题 + 简介 + 按钮让位）。

外加三条字符串断言：`bind:measure`、根容器的 `--nav-h`、大图必须是 `aspectFit`。
谁把 `− 3vh` 加回去、把 `max-height` 删掉、或把 `mode` 改回 `aspectFill`，用例立刻红。

## 五、App 侧多修的一条

`official_gallery_detail_page.dart` 的白卡原来写死 `minHeight: size.height * 0.45`。
**横图**时（图矮 → 留白也矮）白卡下沿会停在屏幕中段，底下露出一条页面米色、贴底按钮浮在那条米色上。
现改成 `cardMinHeight = size.height - spacerHeight`（＝小程序 `.detail-body{min-height:100%}` +
`.detail-card{flex:1}` 的等价写法），白卡永远铺到屏幕底部。这条小程序没有。

封顶时 `contain` 在两侧留出的空档由外层 `ColoredBox(0xFFDFE3E9)` 兜底 ——
与小程序 `.detail-hero { background: #dfe3e9 }` 同色，不是页面的米色。

## 六、风险与取舍

- ⚠️ **矮屏上 3:4 图会被封顶**：屏高 ≤ 667pt 的机型（iPhone SE2/8 一类），
  3:4 兜底比例按满屏宽算出来的高度已经越过「一屏 − 420rpx」，于是缩进框里、
  两侧各留约 14~16px 的 `#dfe3e9` 底色。这是「整图可见」与「图满屏宽」二选一的结果 ——
  产品这轮点名要前者。要换回满屏宽，把 `--hero-max` / `_kCardMinHeight` 那条去掉即可，
  代价是矮屏上图的下沿又会被白卡盖住。
- 白卡的两个圆角（32rpx / 16pt）现在不再压在图上，露出的是页面米色而不是图片。
- 大图仍然**不跟着滚**：这套「白卡盖大图」版式没变，只是现在保证了静止时整张图看得全。
