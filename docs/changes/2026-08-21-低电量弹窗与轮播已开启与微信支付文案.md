## 一、产品要求（原文）

1. **10% 连接设备弹窗提示，低于 3% 弹窗提示语**
   主动点击任意功能按钮（连接，投屏，相册按钮，设备相关操作按钮等）需要连接设备的时候就弹出，
   **如果某些场景涉及到自动连接时则不弹**。
   - 电量 10%~4%：`目前电子纸设备电量较低，请将电子纸设备放置在光线明亮处使用，并可适当减少操作频次。`
   - 电量 3% 以下：`目前电子纸设备电量低于3%，即将关机，请将电子纸设备放置在阳光充足或光线明亮的区域，进行光能充电即可恢复使用。`
2. **设备详情 - 轮播设置**：开启时的文字改为「已开启」（关闭时维持现状不变），不显示具体的轮播内容文字（顺序/随机），只显示已开启。
3. **支付选择**：「微信虚拟支付」文字改为「微信支付」。

## 二、第 1 项 · 低电量提醒

### 新增收口层 `utils/low-battery.js`

```js
lowBattery.warnIfLow(deviceId, { device, battery })  // → Promise<boolean> 是否弹了窗
```

- 分档：`≤10 && >3` → 第一段文案；`≤3`（含 0）→ 第二段文案；`>10` 或**电量未知**（`null`/非法值）→ 不弹。
  ⚠️ **3% 归到第二档**：需求原文是「10%~4%」与「3% 以下」，字面上 3% 本身落在两档中间的缝里；
  按第一档明确到 4% 为止，3% 只能归下面那档（弹窗文案本身也写着「低于3%」，以电量档位而非字面区间为准）。若产品另有口径，改 `CRITICAL_BATTERY_MAX` 一处即可。
  电量未知不弹是刻意的：没有判据就不报警，与详情页「未连接整行 `--`、红点恒灭」同一套态度。
- 电量取值走 `utils/battery.readLatestBattery`：**15 秒内复用最近一次 0x04**，过期才真读，读失败回落最近有效值。
  所以「点一下弹一次」不会变成「点一下多发一条 BLE 指令」；调用方手上已有电量时（连接刚返回的 `info.battery`）直接传 `battery`，一条都不发。
- 弹的是 `wx.showModal`（标题「电量提醒」、单按钮「知道了」）。**不阻断**原动作：用户点掉之后该投屏投屏、该清空清空。
  之所以 `await` 而不是甩出去，是为了不和紧随其后的 `wx.showLoading`（保存中/删除中/清空中/升级中）抢同一块屏。
- 模块内 `showing` 闸：两条异步链路先后连上同一台设备时不叠两个一模一样的弹窗。

### 「主动点击才弹、自动连接不弹」是怎么保证的

不是靠每个调用方自觉，而是**挂在连接层的分工线上**：

| 函数 | 谁在用 | 弹不弹 |
| --- | --- | --- |
| `active-device.ensureConnectedForAction` | 「操作前确保已连接」——调用方清一色是点击处理函数（相册再投/删除、投屏记录再投、轮播设置保存、固件升级、结果页再选图、OTA 连接并升级） | **弹**（本次加在这里） |
| `active-device.ensureDeviceConnected` | 底层自动连接——投屏预览页预热连接、结果页图传前的续连 | **不弹** |
| `active-device.connectBoundDevice` | 三处「连接」按钮共用的连接主链（同时也被上面复用） | **不弹**，由页面在成功后各调一次 |

因此「自动连接不弹」是结构上成立的：自动链路根本不经过弹窗那一层。

### 逐个入口

| 入口 | 位置 | 弹的时机 |
| --- | --- | --- |
| 首页「连接蓝牙」 | `pages/home/home.js · connectCurrentDevice` | 连上之后（用本次连接读到的电量，不再多发 0x04） |
| 首页「拍照 / 相册」（投屏入口） | `home.js · ensureCanProject` | 未连接 → 由 `connectCurrentDevice` 弹；**已连接 → 在 `ensureCanProject` 里补弹**（这一支没走连接流程） |
| 设备列表「连接」/「投屏」 | `subpackages/device/list/list.js · connectDevice / startProjection` | 同上：连上后弹；已连接那一支单独补弹 |
| 详情页「连接」/「投屏」 | `subpackages/device/detail/detail.js · connectDevice / startProjection` | 同上 |
| 详情页「一键清空」 | `detail.js · clearCopies` | 点击后、**二次确认框之前**（清空不自动重连，不走 `ensureConnectedForAction`，得自己弹一次） |
| 详情页「固件升级 → 立刻更新」 | `detail.js · enterOtaUpgrade` | 由 `ensureConnectedForAction` 弹 |
| 轮播设置（详情页间隔 picker / 轮播设置页开关） | `detail.js` / `slideshow.js · applyPlayback` | 由 `ensureConnectedForAction` 弹 |
| 我的相册「再次投屏」「删除」 | `subpackages/album/list/list.js · ensureConnectedDevice` | 由 `ensureConnectedForAction` 弹 |
| 投屏记录「再次投屏」 | `subpackages/projection/records/records.js` | 由 `ensureConnectedForAction` 弹 |
| 投屏结果页「拍照 / 相册」再投 | `subpackages/projection/result/result.js · pickAndContinue` | 由 `ensureConnectedForAction` 弹 |
| AI 对话页 / 官方图库详情页「投屏」「连接并投屏」 | `subpackages/ai/chat/chat.js · startProjection`、`subpackages/gallery/detail/detail.js · startProjection` | 下载图片、跳预览页之前。这两处**自己不建连接**（连接发生在预览/结果页，属自动连接），所以只有「选中的这台此刻已连接」时才有电量可判、才会弹 |

**一次点击只弹一次**：链式路径都做了避让——首页投屏未连接时只由 `connectCurrentDevice` 弹；
详情页「立刻更新」弹过之后，OTA 页自动开始那一跳走的是「已连接直接复用」分支，不会再弹第二次。

**故意不弹的地方**：
- 详情页点「轮播设置」这一行只是**跳页**（不连接、不下发指令），真正的设备操作是页内那个开关，由它弹；
- 投屏预览页预热连接、结果页图传中的续连、OTA 自动开始 —— 都是自动连接，弹窗只会打断正在跑的流程；
- 电量读不到（未连接、0x04 失败且无历史值）时一律不弹。

## 三、第 2 项 · 轮播设置只显示「已开启」

`detail.js · getPlaybackLabel`：开着一律返回 `已开启`（原来按 `playbackMode` 返回「顺序轮播 / 随机轮播」），
关着（`playbackMode === 'manual'` 或用户明确关过轮播 `carouselEnabled === false`）**维持原样**返回 `未启用`。
未连接时整行仍是 `--`（与设备ID/内存/固件版本同一套占位约定），不在本次改动范围。
顺序/随机的选择本身没动，仍在轮播设置页里选。

## 四、第 3 项 · 支付方式改叫「微信支付」

`subpackages/token/confirm/confirm.wxml`：支付方式那一行由「微信虚拟支付」改为「微信支付」。
**只改面向用户的这一处文案**，底层通道一个字没动（仍是小程序虚拟支付 `wx.requestVirtualPayment`，见 `utils/wx-virtual-pay.js`）。

⚠️ **隐私政策里的「微信虚拟支付」保持不变**（`subpackages/settings/privacy/privacy-content.js`）：
那是 2026-08-13 换上的法务 v3 全文，说的是「支付由哪个渠道完成」这一法律事实，不是支付按钮文案，改它属于改法务文本。
