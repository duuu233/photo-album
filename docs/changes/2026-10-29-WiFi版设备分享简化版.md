# 2026-10-29 WiFi版设备分享（简化版：微信卡片）

> 分支：`main-wifi`｜依据：服务端新增接口——`getUserInfo` 出参 `userId`；`addUserProduct` 入参 `isToHave`（是否所有者）、`shareUserId`（分享者 userId，默认 0）；`getShareUserProductList`；分享列表移除成员沿用 `delUserProduct`。产品口径：先按简化版接，用微信卡片分享。

## 做了什么

| 位置 | 改动 |
|---|---|
| `utils/api.js` | 个人信息读出数字 `userId`（与展示用的 `id` / `userNo` 分开）；`addUserProduct` 默认带 `isToHave=1`、`shareUserId=0`（蓝牙绑定），WiFi 配网绑定同样显式带上；新增 `acceptSharedDevice`（`isToHave=0`、`shareUserId=所有者 userId`）、`removeShareUser`（`delUserProduct`，成员那条 `userProductId`） |
| `utils/wifi-share.js` | 卡片路径编解码 `buildAcceptPath` / `parseAcceptQuery`（`d` 设备号、`p` 产品 ID、`u` 所有者 userId、`n` 设备名、`o` 所有者昵称）、`findBound`（按设备号去冒号比较） |
| 分享列表 `wifi-share` | 「分享设备」改为 `open-type="share"` 发微信卡片，标题「xx邀请你共用电子纸设备「设备名」」；拿不到自己的 `userId` 或产品 ID 时按钮置灰、点了提示，右上角转发退回首页卡片。「移除」二次确认后删成员记录并刷新列表 |
| 新页 `wifi-share-accept` | 卡片打开的接受页：显示设备名与分享者；参数不全显示「分享链接无效」。点「接受」：自己分享的提示不接受；已在自己列表直接进详情；否则 `acceptSharedDevice`，成功后回查列表进 WiFi 详情。未登录时按钮为「登录并接受」，先记下本次卡片（10 分钟内有效）再去登录 |
| 登录页 | 登录成功时有待接受的分享卡片，`reLaunch` 回接受页，不进首页 |

- 成员身份：成员的设备记录 `isToHave=0`、`shareUserId>0`，WiFi 详情据此隐藏「分享设备」「删除设备」，保留「解除绑定」（即退出共用，只删自己那条）。
- 没做：首页 / 我的设备的「共享」标签（设备列表接口没有 `isToHave`）；加入时间（分享列表接口没有该字段，仍显示「--」）。

## 已知风险与待服务端确认

- **没有邀请码**：卡片里就是设备号、产品 ID、所有者 userId，拿到卡片的人都能加入，做不到一次性 / 过期 / 撤回。需要服务端至少校验 `shareUserId` 确实是该设备的所有者，且设备已有所有者时拒绝他人以 `isToHave=1` 绑定。
- 所有者能否用 `delUserProduct` 删成员的记录；删后是否踢掉成员在 IoT 的推送订阅。
- IoT `checkPermission` 对成员是否放行。
- `getShareUserProductList` 的 `deviceId` 传绑定时的原样设备号（WiFi 版带冒号），是否正确待联调。

## 服务端答复（2026-10-29）

- 所有者删除设备：所有分享者的记录一并删除，分享者看不到这台设备，其照片也没有了。
- 解除绑定：不删图片。
- 删除设备只有所有者有；分享者只有解除绑定。

小程序现状与之一致：WiFi 详情「删除设备」仅所有者显示（`isOwner`），走清相册记录 → 删云端全部 bin → `delUserProduct`；成员只有「解除绑定」，只删自己那条记录、不删图片。据此只调整了删除设备一级确认的文案，补上「已分享的成员也将同时失去这台设备及其照片」。
