# AI 网关错误提示与服务协议 v2

> 状态：current-change-record  
> 日期：2026-07-28  
> 适用范围：微信小程序、Flutter App  
> 当前长期规则：[AI 客户端架构](../architecture/ai-client.md)

## Background

BoltStar AI 接口除自身的 `{ success, code, data, params, detail }` 协议外，还可能直接收到阿里云网关的大写字段错误。与此同时，AI 服务协议在同日完成了一次实质性法务文案更新。

## Problem

- 网关返回 `Code=JWTTokenIsMissing`、`Message=the jwt token is missing` 时，原解析器只识别小写数字 `code`，最终只能显示泛化的系统异常。
- 动态 `RequestId` 没有进入用户截图，服务端难以定位具体失败请求。
- 旧协议缺少 AI 生成内容标识、知识产权和专业领域风险等完整条款，且首次违规措施与新口径不一致。
- 已经同意旧正文的用户不能被继续视为已同意实质变更后的协议。

## Solution

- AI 请求层仅对白名单签名 `JWTTokenIsMissing + the jwt token is missing` 生成受信 `userMessage`。
- toast 展示 `Code`、`Message` 和动态 `RequestId`；JSON 对象和 JSON 字符串响应都能识别。
- 任意其它未知网关响应继续降级到既有错误码；`detail` 继续只写日志，禁止直接展示。
- 完整协议替换为八章新正文，新增 AI 生成内容标识、知识产权、专业领域免责声明及公司主体说明。
- 两端内部协议版本同步提升为 `2026-07-28-v2`，页面更新/生效日期仍为 2026 年 7 月 28 日。
- 用户提供的联系方式句末沿用现有邮箱 `boltstarservice@boltstar.net`，保证联系渠道可实际使用。

- `utils/ai-api.js`
- `utils/ai-i18n.js`
- `utils/ai-service-consent.js`

## Technical Decisions

- 以 `Code + Message` 精确匹配而不是只匹配 `Code`，避免把未来语义不同的响应误列为安全可展示内容。
- `RequestId` 仅作为该固定错误的定位信息展示，不把完整响应对象或任意服务端详情透传到 UI。
- 白名单错误使用 toast，不进入 30xxx 的重试确认框，符合“直接显示方便定位”的产品要求。
- 协议实质性变化必须提升同意版本，即使展示日期没有跨天。

## Risks

- toast 文案较长，需在小程序和 App 真机确认窄屏换行与停留时间足够。
- 若网关修改 `Code` 或 `Message` 的大小写/措辞，白名单将安全失配并退回泛化错误，需要按新的稳定契约更新。
- 公司主体、数据不存储/不训练和知识产权条款属于法务口径，后续变化必须同步两端正文和协议版本。

## Verification

- 用对象与字符串两种 JSON 响应验证固定网关错误均显示动态 `RequestId`。
- 验证相似但不完全匹配的响应不会把未知字段展示给用户。
- 验证旧版同意记录在 v2 下失效，用户需重新确认。
- 对照检查两端中文正文、违规阶梯、邮箱和展示日期一致。
