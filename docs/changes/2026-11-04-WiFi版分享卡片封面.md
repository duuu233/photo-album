# 2026-11-04 WiFi版分享卡片封面

> 分支：`main-wifi`｜依据：产品要求分享出去的微信卡片用画出来的样式，不用页面截图；风格与小程序一致，简洁大气、一眼看懂

## 做了什么

分享列表 `onShareAppMessage` 原来没传 `imageUrl`，微信默认截当前页面（头像、成员列表、按钮）当卡片图。现在拿到设备详情后用离屏 Canvas 画一张 5:4 封面，分享时作为 `imageUrl`。

卡片版式（逻辑 500×400，导出 750×600 PNG）：

- 底：暖白 `#fff6ee` → 浅蓝 `#e8f2ff` 斜向渐变，右上淡橙光、左下淡蓝光；
- 左上：橙色浅底标签「设备共享邀请」；
- 中部：左边机型设备图（`device-thumb.thumbOf`，与首页 / 我的设备同一张，带淡橙投影），右边设备名（粗体 38px，最多两行，超出省略）+ 规格「WiFi版 · 尺寸」（没配尺寸只写「WiFi版」），整体与设备图垂直居中；
- 底部：橙色渐变（`#ff9140` → `#ff6a20`，同页面主按钮）圆角按钮「点击接受邀请」。

卡片标题仍是「X邀请你共用电子纸设备「设备名」」，图上不重复昵称。

| 位置 | 改动 |
|---|---|
| `utils/share-card.js`（新增） | `cardInfo(device)` 取设备名 / 规格 / 设备图；`wrapText` 按实际宽度折行、末行省略；`drawCard(ctx, info, img)` 在逻辑坐标上画整张卡；`render(device)` 用 `wx.createOffscreenCanvas` 画好后 `canvasToTempFilePath` 导出，resolve 临时文件路径。没有离屏 Canvas、导出失败时 resolve 机型设备图本身（不退回页面截图）；设备图解码失败只画文字 |
| 分享列表 `wifi-share` | `load()` 拿到设备详情就开始画（`cardPromise`）；`onShareAppMessage` 默认参数带已画好的封面，没画好先用设备图；`promise` 里等取最新时间戳和封面画完，再返回带封面的参数 |

不能分享时退回的首页卡片未改（仍为默认截图），只出现在缺 userId / 产品 ID / 时间戳的异常情况。
