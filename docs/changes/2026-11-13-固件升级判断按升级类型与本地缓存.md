# 2026-11-13 固件升级判断：按后台升级类型、强提醒每次启动一次、列表页 / 首页本地缓存

> 分支：`main`｜依据：产品复核（弱提示升级被误弹；强提醒只在进入设备页提醒一次；列表页 / 首页强制升级判断加 loading 并缓存）。在 [固件强制升级 / 强提醒升级判断](2026-11-13-固件强制升级与强提醒升级判断.md) 的基础上调整。

## 升级类型

后台「升级类型」`compulsory` 归一为 `updateType`：

| 值 | 类型 | 弹框 | 红点 |
|---|---|---|---|
| 1 | 强制升级 | 弹 | 照旧 |
| 2 | 强提示升级（强提醒） | 弹 | 照旧 |
| 3 | 弱提示升级 | 不弹，用户自己点「固件升级」 | 照旧 |
| 4 | 不提示升级 | 不弹 | 照旧 |

原来把「不是 1」都当强提醒，弱提示也会弹窗，而且强提醒点取消会照常继续，所以投屏取消后仍会弹出拍照 / 相册。现在 3、4 不弹。

## 强提醒（2）

- 只在进入设备详情页时弹（`firmwareGate.checkOnEnter`）。
- 每台设备每次启动小程序只弹一次；取消后本次不再提醒，重新打开小程序才再提醒。
- 详情页的功能按钮、列表页、首页都不弹强提醒。

## 强制升级（1）

- **设备详情页**：
  - 进入时弹。
  - 取消后点任意功能按钮（投屏、轮播设置、重命名、一键清空等）都再弹，这次操作不继续。按钮的判断只看强制升级（`forceOnly`）。
- **列表页、首页**：
  - 列表页指蓝牙「投屏」和 WiFi「投屏」「轮播设置」，首页指拍照 / 相册投屏。
  - 点击时弹，取消后这次操作不继续，再点再弹。
  - 本次启动第一次点某台设备时，显示 loading「检查固件版本」现查一次：WiFi 查设备信息（在线和当前版本），蓝牙读当前版本，再查设备详情。结果写进本地缓存 `fw_gate_cache`。
  - 之后再点直接按缓存判断，不再请求接口。列表里已知不在线的 WiFi 设备不判断；首页调用前已确认在线，传 `{ online: true }`。

## 缓存更新

- 详情页进入时的判定写进缓存，列表页、首页直接用。
- 升级完成后缓存改成「无需升级」：蓝牙 `ota` 页升级成功时，WiFi `wifi-ota` 主固件走到设备重启确认时（优雅刷新不涉及）。
- 缓存按设备 id 存。每次启动第一次点击仍会现查一次，避免后台新发的版本一直用旧缓存。
