# 2026-08-07 SSE 新增 init / heartbeat / **mode**：占位盒显形时机改由 mode 决定

> 状态：**小程序端已实现**，**未真机验收**
> 适用范围：微信小程序 AI 模块（`utils/ai-api.js` 解析层注释 + `subpackages/ai/chat/chat.js` 渲染层）
> 需求来源：服务端新增 `mode` 参数，两条事件流：
>
> ```
> 纯文字：init → pre_text:"星宝努力思考中" → heartbeat → mode:"text"  → pre_text:"" → text → done
> 生图：  init → pre_text:"星宝努力思考中" → heartbeat → mode:"image" → pre_text(替换) → progress → …
> ```
>
> 「`mode:"image"` 时才走生图流程、加载占位图 loading，否则走文字流程直接加载出来。」
> ⚠️ 本次没有拿到新版接入文档正文，事件顺序与语义按上述需求描述实现；
> `mode` 的字段名按 `{"type":"mode","mode":"image"}` 取，同时兼容 `{"type":"mode","content":"image"}`。
> 真机联调时若服务端用的是第三种写法，改 `chat.js` 的 `case 'mode'` 一行即可。

## 一、要点：占位盒的开关从 `pre_text` 挪到 `mode`

改造前是「`pre_text` 一到就把渐变占位盒亮出来」——那时候 `pre_text` 只在生图链路出现，
这么写没毛病。**新流程里两条路的开头一模一样**（`init` → 同一句「星宝努力思考中」→ `heartbeat`），
服务端要到 `mode` 事件才分叉。照旧写法，纯文字回复也会先闪一个生图占位盒再收掉。

所以：

| 事件 | 改前 | 改后 |
| --- | --- | --- |
| `init` | 落到 default 忽略 | 显式忽略（无内容，界面继续挂三点动画） |
| `heartbeat` | 落到 default 忽略 | 显式忽略（长等待续命包） |
| `mode:"image"` | — | **唤出占位盒** + 进度起步 5% + 强制贴底 |
| `mode:"text"` | — | 什么都不做（继续走三点动画 → 打字机） |
| `pre_text`（非空） | 唤出占位盒 + 起进度 + 写文案 | **只写文案**（收三点动画、不碰占位盒） |
| `pre_text`（空串） | `if (!content) return` 直接丢弃 | **擦掉预描述**；擦完气泡若空了把三点动画放回去 |
| `progress` | 唤出占位盒 + 补间 | 不变，但 `mode:"text"` 之后一律不显形 |
| `done` | 无条件 `applyProgress(100)` | 只在出过进度时补（`stream.target > 0`） |

### 三个容易漏的细节

1. **空串 `pre_text` 必须当成「擦除」**，不能当成「没有这条事件」丢掉 —— 纯文字流程靠它抹掉
   「星宝努力思考中」。擦完正文往往还没到，气泡里什么都不剩，要把三点动画放回去，
   否则会晾出一个空白气泡。
2. **擦完要把 `stream.hasContent` 归位**。这个字段决定「流中途断了是保留已生成内容还是换失败卡片」，
   保留那条**不给重试入口**（服务端已经算过、可能已扣费）。屏上又空了却还留着 `hasContent=true`，
   断线时用户会拿到一个既没内容也不能重试的死气泡。
3. **`done` 不再无条件补进度**。纯文字这一路压根没有占位盒，`applyProgress(100)` 会让补间从 0 每
   80ms 走 3 步爬到 100 —— 三十来次没人看得见的 `setData`。用 `stream.target > 0` 判而不是用
   `mode`，老部署（不发 `mode`）也一样受益。

## 二、灰度兼容：没有 `mode` 的老部署

`progress` 事件保留了「一来就唤出占位盒」的兜底，所以老部署的生图链路照旧工作，
只是占位盒的显形时机从 `pre_text` 推迟到第一条 `progress` —— 两者本来就前后脚，观感无差。
服务端灰度期间两种流会同时存在，**这条兜底不能拆**（`tests/ai-stream-render.test.js`
的 `testGenCanvasFallsBackToProgress` 锁着它）。

## 三、改动清单

| 文件 | 改动 |
| --- | --- |
| `chat.js` | `beginStream` 新增 `mode` 字段；`onStreamEvent` 新增 `init`/`heartbeat`/`mode` 三个 case；`pre_text` 拆出空串擦除分支、不再唤占位盒；`progress` 加 `mode:"text"` 闸；`done` 加 `target > 0` 闸；事件顺序注释重写 |
| `ai-api.js` | 事件表补 `init`/`heartbeat`/`mode` 三条说明（解析层本身**一行没改**：未知事件本来就原样透传给 `onEvent`） |
| `tests/ai-stream-render.test.js` | `testGenerateFlow`/`testCanvasHidesAtHundred` 按新事件流改写；新增 `testModeTextKeepsNoGenCanvas`、`testGenCanvasFallsBackToProgress` |
| `tests/ai-stream-doc-conformance.test.js` | 新增 `testModeEventsPassThrough`：两条流的开头逐事件核对，锁「新事件按序原样送到页面、且不混进汇总结果」 |

23 个测试全部通过。

## 四、真机验收要看的点

1. **纯文字提问**：全程不出现渐变占位盒；「星宝努力思考中」被擦掉后是三点动画接上打字机，
   中间不闪空白气泡；
2. **一句话生图**：`mode:"image"` 到达时占位盒出现并从 5% 起步，预描述随后被替换成真文案；
3. 生图链路的 100% 换真图、停止生成、断线保留等原有行为不变；
4. 若服务端 `mode` 事件的字段名与这里假设的不一致，占位盒会退回到「第一条 progress 才出现」
   —— 看起来只是晚一点点，别误判成没接上，抓包确认字段名即可。
