# 2026-11-06 WiFi 版「我的上传」存原图（IJ_101 照片倒置）

> 分支：`main-wifi`

## 现象

IJ_101（WiFi 版）、EC-370、EF6-370 后台都配置竖向旋转 180°。「我的上传」里 EC-370 / EF6-370 的照片方向正常，IJ_101 的照片是倒过来的。

## 原因

两类设备写进相册记录的 `img` 不是同一张图：

- 蓝牙版结果页（`uploadOriginalForRecord`）上传的是进预览页前的**原图**（`_origSrc`），没有旋转；
- WiFi 版结果页（`saveAlbumRecord`）上传的是**投屏用的那张**——预览页已按设备 `verticalRotation`（横向为 `rotationDegree`）转过的成品。

所以竖向 180° 的 WiFi 版设备，相册记录存的就是倒图，「我的上传」和轮播选图都显示倒置；从「我的上传」再次投屏时，预览页又以这张倒图为源，再转一次 180°，设备上会是倒的。

## 做了什么

- `subpackages/projection/wifi-result/wifi-result.js`：写相册记录改用原图，口径同蓝牙版：
  - 取预览页备份的 `_origSrc`；是云端地址（再次投屏）就先下载；
  - 长边大于设备长边时按比例缩到设备长边（质量 90），不大于就原样上传；
  - 没有 `_origSrc`（预览页没处理过，发出去的就是原图）或原图下载失败时，退回投屏用的那张；缩放失败用未缩的原图；
  - 投屏本身（`/api/device/play`）仍用转过的成品，`imgBle` 仍是本次的 `binUrl`，轮播 / 设备播放不受影响；
  - 投屏日志多一行「相册记录用图：原图 / 原图（云端图已下载）/ 投屏图（…）」。
- `utils/api.js`：`addWifiAlbumRecord` 注释同步。
- `tests/wifi-projection.test.js`：新增一组——投屏用图不变、记录用原图（本地 / 云端下载 / 下载失败退回 / 无备份）、`imgBle` 不变、只缩超过设备长边的原图。

## 未覆盖

- 已经存进去的 IJ_101 记录仍是倒图，接口无法改写，需删除后重新投屏。
- 横向构图同理（原先存的是按 `rotationDegree` 转过的图），本次一起改为存原图，未单独验证。
- 记录存原图后「我的上传」显示的是未裁剪的原图（与蓝牙版一致），不再是取景框内的画面。
