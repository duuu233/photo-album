# 2026-08-07 AI 聊天页：生图占位盒贴底对齐 + 自动滚动平滑

> 状态：**小程序端已实现**，**未真机验收**
> 适用范围：微信小程序 AI 模块（`subpackages/ai/chat/chat.{js,wxml,wxss}`）
> 需求来源：用户反馈两条 ——
> ① 生图过程中，整个 loading 盒子的底部要与底部固定的输入框正好平齐，「停止生成」改为悬浮在盒子偏下方；
> ② 自动向下滚动「太快、像一闪一闪的卡顿」，要更慢、更丝滑。
> 未改动：SSE 协议、请求参数、进度补间节奏、打字机节奏，一行没动。

## 一、生图占位盒底部与输入框对齐

### 改前为什么对不齐

占位盒底边到输入框上沿之间，从内到外垫着**三层**间距，一层都不能漏：

| 层 | 来源 | 高度 |
| --- | --- | --- |
| 气泡内边距 | `.bubble { padding: 20rpx 24rpx }` | 20rpx |
| 消息行间距 | `.msg-row { margin: 20rpx 0 }` | 20rpx |
| 贴底空带 | `.bottom-anchor--sending` | 150rpx |

那条 150rpx 的空带本来是给「停止生成」腾位置用的（药丸 `position: fixed`，
`bottom: 450rpx` 悬在半空），代价就是出图时占位盒被顶在半空、下面空一大截。

### 改后

占位盒在场时（`item.streaming`，100% 落下即复位）把这三层一起收掉：

```css
.msg-row--gen { margin-bottom: 0; }
.bubble--ai.bubble--gen { padding-bottom: 0; border-bottom-{left,right}-radius: 22rpx; }
.msg-row--gen + .bottom-anchor { height: 0; }   /* 权重 0,2,0 压住 --sending 的 0,1,0 */
```

- 圆角要跟着改：气泡 28rpx、占位盒 22rpx，盒子贴到气泡底边时两个下角会露出渐变的尖角。
- `+ .bottom-anchor` 成立的前提是**占位盒所在的消息一定是最后一条**（holder 之后不再追加消息）。
- 收完之后只剩 `.input-area` 自己的 `margin-top: 8rpx`（≈4px），那是输入框卡片自身的呼吸位，
  没有再抹掉——真机看下来若仍嫌有缝，把这 8rpx 也做成生图态下收起即可。
- **只对出图那一段生效**。图出完之后进入正文打字阶段，`.bottom-anchor--sending` 的 150rpx
  照旧留着，否则「停止生成」会压住正在打出来的字。

### 「停止生成」改为锚在输入框上

节点从 `.ai-root` 的直接子节点移进 `.input-area`（与 `.tool-popover` 同一套定位手法）：

```css
.stop-pill { position: absolute; bottom: calc(100% + 16rpx); }  /* 原：fixed + bottom: 450rpx */
```

`bottom: 100%` 就是输入框上沿，输入框长高（待发图缩略图那一条）时自动跟着走；
原来那个 450rpx 是照「输入框大概多高」猜的，输入框一变高药丸就会飘到卡片里面去。
生图态下占位盒底边已经压到输入框，于是药丸正好悬浮在盒子偏下 ~72rpx 的位置。

## 二、自动向下滚动改成平滑滑行

### 改前为什么「一闪一闪」

`stickToBottom()` 的跟随路径（打字出字、占位盒换真图、图片 bindload 校正高度）
一律 `scrollAnimate: false` + 80ms 节流 —— **每 80ms 把视图瞬移到底一次**，一秒十几下，
看着就是顿挫。当初关动画是有原因的（见旧注释「动画本身就是赶不上打字机的来源」）：
80ms 一次而组件动画约 300ms，每次都在动画中途原地重启，越追越远。

### 改后

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 跟随类滚动 | 瞬移 | 带动画滑行（`animate` 不传时按 `!force` 取默认值） |
| 节流 `SCROLL_STICK_MS` | 80ms | 260ms（≈ 组件动画时长，一次滑行快走完了下一次才发起） |
| 首屏定位（`openSession`） | 瞬时 | **仍瞬时**（force 且未显式传 animate → 默认关动画） |
| 发消息那几处 | `animate: true` | 不变（都是显式传的） |

按打字机节奏折算：慢流约 62 字/秒 → 260ms 约 16 字（不到一行），滚动落后不到一行，
且正文阶段底部还留着 150rpx 空带，看不出来。

### 附带必须修的一处：别把自己判成「用户上翻」

`onChatScroll` 原本对**所有**滚动事件都按「距底 > 60px 就认为用户翻上去了」来判。
贴底一旦带上动画，我们自己发起的滚动也会一路推 scroll 事件，而动画**中途**距底可能有好几百 px
—— 照单全收就会在滑向底部的路上把自己判成上翻，之后整条回复都不再跟着滚。

改为只认用户手势滑出来的滚动：

- `bindtouchmove` → `_touching = true`（用 touchmove 不用 touchstart：点一下关工具栏/收键盘
  不该算滚动，否则正好撞上动画中途照样会误判）；
- `bindtouchend/cancel` → 仅当确实滑过才记 `_touchEndAt`，松手后 `SCROLL_FLING_MS`(700ms)
  的惯性滑行期内仍算用户的；
- 其余时间的 scroll 事件不改贴底状态。

「用户上翻后不再自动拽回」「用户自己滑回底部后恢复跟随」两条行为都保持不变。

| 文件 | 改动 |
| --- | --- |
| `chat.wxss` | `.msg-row--gen` / `.bubble--gen` / `.msg-row--gen + .bottom-anchor` 三条新规则；`.stop-pill` 改 absolute 锚到 `.input-area` |
| `chat.wxml` | 消息行与 AI 气泡按 `item.streaming` 加 `--gen` 类；`.stop-pill` 节点移进 `.input-area`；scroll-view 加 `bindtouchmove/touchend/touchcancel` |

`tests/` 23 个用例全部通过（本次未新增用例：改动集中在 WXSS 布局与滚动手感，

## 四、真机验收要看的点

1. 生图中：占位盒底边是否贴着输入框上沿（只剩输入框卡片自己的 4px 外边距），下方无空带；
2. 生图中：「停止生成」是否悬浮在占位盒偏下方，且没有挡住百分比与文案；
3. 100% 换真图那一下：高度变化是否只滑一次、不跳；
4. 正文打字阶段：药丸不压字（150rpx 空带仍在）；
5. 长回复打字过程中滚动是否连续，不再一顿一顿；
6. 打字中用手往上翻 → 视图不再被拽回；再自己滑回底部 → 恢复跟随。
