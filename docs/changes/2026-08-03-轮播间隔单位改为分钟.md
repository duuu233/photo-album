## 一 · 背景：改单位之前，分钟级间隔在两端都活不下来

后端字段 `carouselInterval` 原本单位是小时（整数），改成分钟后会出现 `5`、乃至历史遗留的
`0.0833`（=5 分钟的小时表示）这类值。核查两端的处理链路，结论是**都存不住**，
且不止是显示不对——用户点一下轮播开关就会把设备上的真实间隔覆盖掉。

| 端 | 位置 | 改前行为 |
| --- | --- | --- |
| 小程序 | `utils/api.js` `normalizeDevice` | **根本没读 `carouselInterval`**，只认 `intervalSeconds`/`intervalHours`（后端不下发这两个名字）→ 恒取兜底 2 小时 |
| 小程序 | `utils/api.js`、`detail.js`、`mock.js` | `intervalHours = Math.max(1, Math.round(秒/3600))`：300 秒 → `round(0.083)=0` → 兜成 **1 小时** |
| 小程序 | `slideshow.js` / `detail.js` `applyPlayback` | 入参是**小时**，`Number(intervalHours) || 2` → 下发 `7200` 秒，把设备现有间隔覆盖成 2 小时 |
| Flutter | `state.dart` `_deviceFromJson` | `_asInt(data['carouselInterval'])`：double `0.0833` → `toInt()=0`；字符串 `"0.0833"` → `int.tryParse` 失败 → 0 → 回落默认 2 小时 |

BLE 协议本身没有问题：`buildSetPlaybackPayload` 两端都是 uint32 **秒**
（`utils/frame-protocol.js:260`、Flutter `device/ble/frame_protocol.dart:466`），300 秒完全表达得了。
瓶颈全在端上把间隔建模成了「整数小时」。

## 二 · 口径（改后，两端一致）

```text
后端 carouselInterval（分钟，可带小数）
        ↓ ×60，四舍五入到秒，最小 1 秒
端上 intervalSeconds / carouselIntervalSeconds（秒）  ← 唯一权威单位，直接喂 BLE 0x12
        ↓ ÷3600，不取整
intervalHours（仅展示/选择器下标派生，允许小数）
```

铁律：**「小时」只允许出现在展示派生和默认值常量里，任何写回设备的路径都必须走秒。**
一旦在中间层 `Math.round` 成整数小时，分钟级间隔就再也回不来了。

## 三 · 改动明细

### 小程序

| 文件 | 改动 |
| --- | --- |
| `utils/api.js` `normalizeDevice` | 新增读 `carouselInterval`（分钟）→ `Math.max(1, Math.round(分钟*60))` 得 `intervalSeconds`；列表接口不下发该字段时回落 `intervalSeconds`（BLE 0x01 读回值），再兜底历史 `intervalHours`（兼容本地缓存旧记录） |
| `utils/api.js` | `intervalHours` 改为 `intervalSeconds / 3600` 派生，**去掉 `Math.round`**；未知时仍回落 2 |
| `subpackages/device/slideshow/slideshow.js` | 新增 `DEFAULT_INTERVAL_SECONDS = 2*3600`；`applyPlayback(mode, intervalSeconds, …)` 入参改为**秒**；`toggleCarousel`/`changePlayback` 改传 `device.intervalSeconds`（只改模式，不动间隔）；`changeInterval` 把选择器的小时值 `*3600` 后再传；`loadDevice` 复用选中设备时补带 `intervalSeconds` |
| `subpackages/device/detail/detail.js` | 同上三项；另把两处 BLE 0x01 回填的 `Math.max(1, Math.round(info.intervalSeconds/3600))` 改为 `info.intervalSeconds / 3600` |
| `utils/mock.js` `realDeviceFields` | 同款取整改为不取整 |
| `tests/carousel-interval.test.js`（新增） | 7 条断言：5 分钟→300s、0.5 分钟→30s、字符串 `"90"`→5400s、缺字段回落 BLE 秒值、两者皆无→0 且展示回落 2h、旧 `intervalHours` 兜底还原 |

### Flutter

| 文件 | 改动 |
| --- | --- |
| `lib/src/state.dart` | 新增 `_asDouble()`（`_asInt` 会把 `0.5` 截成 0、把 `"0.5"` 判非法，带小数的接口字段一律不能走它） |
| `lib/src/state.dart` `_deviceFromJson` | `carouselHours = _asInt(...)` → `carouselMinutes = _asDouble(data['carouselInterval'])`；`*3600` → `math.max(1, (carouselMinutes * 60).round())`；补 `import 'dart:math' as math` |
| `lib/src/state.dart` | 接口字段文档注释里 `carouselInterval`(单位**小时**) → 单位**分钟** |

`state.dart` 其余间隔相关逻辑本就按秒，无需改：`_carryOverBleFields`（列表刷新不覆盖真机读回的间隔）、
`_applyConnectedInfo`（0x01 秒值直接采用）、`setDeviceCarousel`（复用 `device.carouselIntervalSeconds` 下发）。

## 四 · 仍未做（本轮有意不改）

- **两端都没有「轮播间隔」的 UI**。`slideshow.wxml` / `detail.wxml` 只渲染了开关 + 顺序/随机，
  `intervalOptions: [1,2,4,8,24]` 与 `changeInterval` 是**未挂载的死状态**；Flutter
  `carousel_settings_page.dart` 同样没有间隔控件。本轮只保证「后端下发多少、就原样带着走、不被改坏」，
  没有新增选择器。真要放开分钟级选择，选项表要从小时数组改成秒数组（如 `[300, 3600, 7200, …]`）。
- **提示文案写死「24小时」**：`slideshow.wxml` 的 `.setting-tip` 与 Flutter `app_l10n.dart` 的
  `carouselTip`（四语种）都写死 24 小时，与实际间隔无关。属文案问题，待产品确认后按实际值格式化。
- **端上不回写后端**：改轮播只下发 BLE，没有把新间隔同步回 `carouselInterval`。
  后端记录与设备真值可能不一致，需与后端确认是否要提供写接口。
- Flutter `state.dart` `toggleCarousel()`（纯本地态、会把间隔重置成默认 2h）**全仓无调用方**，
  未清理，勿再接回。
