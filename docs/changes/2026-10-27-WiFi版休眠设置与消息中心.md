# 2026-10-27 WiFi版休眠设置 · 消息中心 · 轮播保存后立即切图

> 分支：`main-wifi`｜依据：[V1.4 对接实现报告 · 服务端反馈](../wifi/V1.4对接实现报告反馈.md)

## 做了什么

### 休眠设置（反馈第二节）

- 新页 `subpackages/device/wifi-sleep`（已注册），入口在 WiFi 设备详情「休眠设置」。
- 进页调 `GET /api/device/sleep` 回显：从未设置「未开启休眠」；周期「每天 22:00 ~ 次日 07:00」；一次性「开始 ~ 结束」；关闭过「已关闭休眠」。
- 三种模式：关闭（先确认，提交 `mode=0`）/ 周期（休眠、唤醒两个 `HH:mm`，不能相同，可跨午夜）/ 一次性（开始、结束各一个日期 + 时间，开始早于结束、结束不能已过）。只传本地时间，不转 UTC。
- 保存 `POST /api/device/sleep`，成功后重新查询回显；4041 补查给离线 / 休眠 / 关机提示，4000 显示服务端给的字段说明。
- 换算与校验在 `utils/wifi-sleep.js`。

### 消息中心（反馈第三节）

- 新页 `subpackages/device/wifi-messages`（已注册），入口在 WiFi 设备详情「消息中心」，带未读角标（`GET /api/notification/unread-count`，进页查，收到本设备 `notification.new` 再查，超过 99 显示 99+）。
- 列表 `GET /api/notification/list`：每页 20 条，下拉刷新回第一页、触底加载更多（按 id 去重）；「只看未读」开关；按 `type` 翻译文案（含 `PLAY_SUCCESS` / `PLAY_DOWNLOAD_FAILED` / `PLAY_STORAGE_ERROR` / `PLAY_FAILED`），`payload` 关键参数一行展示，未知 `type` 显示通用文案；空态「暂无消息」，错误态可重试，403 单独提示。
- 点未读的一条即标记已读（`ids` 原样回传，失败回滚），「全部已读」传空数组。
- 订阅该设备，收到 `notification.new` 或长连接重连成功后刷新第一页与未读数（合并 500ms）；自己订阅的退出时退订。
- 文案与分页合并在 `utils/wifi-messages.js`。

### 轮播（反馈第六节）

- 回显 `imgUrls=null`（全部相册）改为页面全选；`[]` 提示「已全部删除，请重新选择」。
- 一张不选不让保存（提示「请至少选择一张照片」）；按相册顺序全选时不带 `imgUrls`，保持「全部相册」（之后新上传的也进轮播）。
- 轮播中改选图直接保存；保存成功后立即投第一张（选中的第一张，全部相册取相册第一张）：下载这张图 → `POST /api/device/play` `refresh=true`，屏幕马上切过去。这一张不写新的相册记录。

### 删除（反馈第四节）

- 提示按响应为准：`deviceAction=PLAY_NEXT` 时「已删除，相框已切换到下一张」；其余口径不变。`nextImageUrl` 仍取相册剩下的第一张。

## 没做的 / 需注意

- 保存轮播后立即投的那张会生成新的 bin，服务端记的「最后一次投屏」是这张新 bin 而不是相册里的 `imgBle`；之后删这张照片时服务端按「轮播范围」判断，不受影响。
- 「轮播后休眠」`idle=0` 断开可能被判离线（反馈第七节，待固件确认），前端照常下发 `idle`。
- 休眠窗口内显示「休眠中」沿用服务端 `status`，前端无改动。
