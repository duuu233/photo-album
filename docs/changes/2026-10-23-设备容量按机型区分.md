# 2026-10-23 设备容量按机型区分（规格书 v1.6）

> 分支：`main`；修改前：7ad56b3。

## 问题

- EC-370（挂牌）：设备详情「最大照片数量」读不出来。
- EB-169（吧唧）：小程序读不出来，App 显示得出来（App 是用常量 32 兜底，数值并不对）。

## 原因

规格书 v1.6 §5.2 的各机型最多图片数：EF6-370 95、EF6-589 51、EB-169 25、EC-370（挂牌）11。

- 0x01 应答没有容量字段，原来按屏型表 `SCREEN_TYPES` 给容量，表里只有 0x01/0x02/0x03；
  EB-169 报 0x04，容量为 0 → 详情页整行 `--`。
- EC-370 与 EF6-370 同为 3.7 寸 480×720，§6.10.5 与 §6.10.7 屏型同报 0x01。屏型分不出两者，按屏型只会给出 95；
  若真机报的是表外的码，同样是 0 → `--`。EC-370 的容量只能按机型（产品 broadcastId）区分。

## 改动

- `utils/frame-protocol.js`：新增 `MODEL_CAPACITY` 与 `capacityOf(model, screenType)`：先按机型（大小写不敏感的包含匹配，
  同设备图口径），认不出再按屏型，新屏型 0x04 给 25；都认不出返回 0（不猜）。`parseDeviceInfo` 的 `capacity` 改用它，
  0x04 现在给 25。`SCREEN_TYPES` 不加 0x04（尺寸以设备列表为准，避免影响型号否决、OTA 面板预检）。
- 设备详情（三处）、设备列表连接收尾：`totalMemory` 改为 `capacityOf(device.broadcastId, info.screenType)`。
- `utils/projection-device.js` `resolveTransferInfo`：机型认得出就按机型容量定槽位上限，EC-370 不会选到 11 号及以后的槽位；
  认不出机型时口径不变。
- 新增 `tests/device-capacity.test.js`。

## 已知限制

- 机型取自设备记录的 `broadcastId`（设备列表下发或按 productId 回查）。取不到时退回屏型：EC-370 若报 0x01 会显示 95。
- 未在真机确认 EC-370 0x01 实际上报的屏型字节；不论报什么，记录带 broadcastId 时都按 11 显示。
