## Background

支付体系上线后，AI 侧一直缺一件事：**端上根本判断不了「这一轮对话够不够扣」**。
`utils/ai-token.js` 里那道 `LIMIT_ENABLED = false` + `hasBalance()`（按余额数字比大小）的闸
从 2026-08-11 起就写着「等后端定下扣费口径再打开」——在此之前余额为 0 也照发，全靠 AI 网关兜。
本轮后端给了 `chkAiDialogue`，这个悬案可以了结；同时产品调整了图片张数与全站货币文案。

## Problem

1. `/chat` 只带 `user_id`（`boltfox_<id>` 拼出来的），AI 网关无法回 BoltFox 侧核对用户与扣费。
2. 本地图片上传上限是 4 张（BoltStar 文档 §二 `image_urls` 上限），产品要 5 张。
3. 全站货币文案是「Token」，产品要改为「星币」。
4. 端上那道余额闸形同虚设，「能不能用 AI」实际上没有任何前置判据。

## Solution

### 1. `/chat` 新增请求参数 `usertoken`

`utils/ai-api.js` 新增 `getUserToken()`（内存 `app.globalData.token` 优先、`storage『token』` 兜底，
与 `getJwtToken()` 同款取法），`buildChatPayload()` 里固定带上 `usertoken`。

- 值是**小程序登录接口 `setWechatAppLogin` 下发的 `userToken`**，即 `request.js` 打给 BoltFox 的那枚公共参数，
  **不是** `Authentication` 头里的 `jwtToken`。两枚 token 长得都像 token，接错了不会报错，
  只会静默变成「服务端认不出这个用户」。
- 参数名按 AI 侧要求是**全小写 `usertoken`**，别顺手改成驼峰。
- 未登录时是空串，仍原样发出：让服务端自己判「没登录」，比端上悄悄省掉字段好排查
  （何况未登录时 `Authentication` 头也缺，网关那关先就过不去）。
- 流式与非流式共用 `buildChatPayload`，两条链路一起生效。

### 2 & 3. 本地图片上传上限 4 → 5 张

`chat.js` 的 `MAX_IMAGES = 5`，两处超限提示统一成产品文案「**当前AI只允许上传5张图**」
（已达上限时不再拉起相册；相册不严格按 `count` 限制、多回了图时截到 5 张并提示）。
`utils/ai-i18n.js` 的 `error.20012`（服务端超限错误）四语种同步改成 5 张。

> 需求第 2、3 条是同一件事的两种说法（「用户上传本地图片」与「AI 助手页面上传本地图片」都指
> 聊天页输入框里的相册/拍照入口，全项目只有 `chat.js pickImage` 这一处），改一处即两条都满足。

### 4. 所有 Token 文案改成「星币」

改的是**面向用户的文字**，代码标识符与后端字段名一律不动（`availableToken`/`tokenBalance`/
`token-pill`/`subpackages/token` 保持原样——改名只会制造与 swagger 对不上的翻译层）：

| 位置 | 改动 |
| --- | --- |
| 星币管理页 `subpackages/token/index` | 导航标题「Token管理」→「星币管理」、卡片标题「我的token」→「我的星币」、余额/总额/已消耗单位、赠送角标、`≈ ¥x/Token` |
| 确认购买页 `subpackages/token/confirm` | 套餐单位、合计获得单位；支付结果弹窗三句（`已到账 N 星币` / `星币已到账` / `当前余额 N 星币`）与「稍后在『星币管理』查看余额」 |
| 购买 & 消费记录 `subpackages/token/records` | 购买行 `N 星币`、消费行 `-N 星币` |
| AI 会话列表页 | 顶部余额胶囊单位 |
| 「我的」页 | 入口名「Token管理」→「星币管理」、右侧「剩余 N 星币」 |
| AI 聊天页 | 余额不足弹窗（见下） |

⚠️ **调试台的「第三方 Token」不改**：那是 seekink 抖动接口的鉴权 token，与货币无关。

⚠️ **端上改不到的两处**：消费记录里的「场景」一列直接渲染后端 `description`（实测形如「200 token」），
套餐名渲染后端 `goodsName`（形如「500 Token」）—— 这两处文案在后端，**需后端同步改成星币**。

### 5. 发起对话前的服务端校验 `chkAiDialogue`

- `utils/token-api.js` 新增 `checkAiDialogue()` → `GET /Client/Order/chkAiDialogue`。

  ⚠️ **两种答复的形状不对称**（2026-08-12 真机实测，与最初理解的「retData 布尔」不同）：

  | | 响应 |
  | --- | --- |
  | 可以发 | `retCode=200`，`retData=true` |
  | 不能发 | `retCode=403`，`retMsg="token余额不足，需要最低余额：30.0 token"`，`retData=null` |

  也就是说**否定答复是从 `request.js` 的失败分支出来的**。只认 `retData===true` 的写法会把
  403 当成「接口挂了」而走兜底放行 —— 余额为 0 的用户照样能发，闸等于没加。
  所以：**403 → resolve 成 `{allowed:false, required, message}`（`required` 从 `retMsg` 里抠出的
  最低余额），其余错误原样 reject 交给上层兜底**；200 一律放行，不再纠结 `retData` 是不是字面 `true`
  （真在这一支较真，后端哪天不下发该字段就会把所有人拦在门外，那比放过去糟得多）。
- `utils/ai-token.js` 新增 `canDialogue()` 封装，**同时删除 `LIMIT_ENABLED` 与 `hasBalance()`**，
  `chat.js` 的 `guardToken()` 一并删除 —— 留着两个口径不一致的闸，出问题时「到底谁拦的」无从查起。
- `chat.js sendChat()` 在**任何 `setData` 之前**过闸（`guardAiDialogue`）：不允许时 `/chat` 一个请求都不发、
  用户气泡一条都不上屏、弹「星币不足」（确认键直达星币管理页）、顺带刷一次余额。
  提示文案是**数字用后端的、话由我们说**：后端原话「token余额不足，需要最低余额：30.0 token」
  对外不合适（`token` 是内部叫法、`30.0` 是浮点、整句带接口味），端上抠出 30 后拼成
  「发起一次 AI 对话至少需要 30 星币，当前余额不足。购买后即可继续和星宝聊天。」；
  抠不到数字才退回后端原话（`token`→`星币`）—— 403 也可能是余额之外的理由，
  那时硬套「星币不足」反而是错的。
  「重试」入口（`onRetryMessage`）同样过闸——那也是一次真实调用，且上一轮失败到现在余额可能已经不够。
- `sendChat` 改为**返回是否真的发出去**，`onSendTap` 据此把草稿和待发图**还回输入框**：
  清空动作发生在发送之前，不还回去用户就得照着记忆重打一遍，而「星币不足」恰恰是他每次发都会撞上的。

## 二轮补充（同日，产品复看后三条）

### A. 星币不足弹窗改自绘，与全站同一套版式（需求 1）

`wx.showModal` → 页面自绘 `.confirm-mask` / `.confirm-dialog`（chat.wxml），与本页的删除确认框、
「我的相册」删除弹窗完全同款：左上角图标（用余额胶囊那颗 `ai-token-spark.png`）+ 标题「星币不足」
+ 说明 + 「知道了 / 去购买」两颗按钮。原生弹框的圆角、字号、按钮排布与全站对不上，一眼能看出是两拨人做的。
状态收在 `data.tokenDialog = { show, desc }`，文案仍由 `showTokenShortModal` 拼（口径不变）。

### B. 校验提前到建会话之前（需求 2）

原顺序：协议 → **`POST /session/new`** → 清输入框 → `sendChat`（在这里才查星币）。
余额见底的用户每点一次发送，都会在服务端多留一条空的「新对话」——**每用户上限 20 条**，
点几次就占满了，还得自己去列表里删。

现顺序：协议 → **`chkAiDialogue`** → 建会话 → 清输入框 → `sendChat`。
`sendChat` 新增 `options.dialogueChecked`，由 `onSendTap` 透传「我已经查过了」，
**一次用户动作只打一次校验请求**（由 `tests/ai-dialogue-guard.test.js` 断言 `checkRequests.length === 1`）。
其余入口（一键生图、语音、重试）没有建会话在前的问题，仍在 `sendChat` 里查。

### C. 等待气泡的三个点改成动画（需求 5）

`assets/images/ai-loading-bubble.png` 是一张**静态图**（白胶囊 + 三个深浅不同的点）。
现在胶囊与阴影按原图几何/配色用 CSS 还原（画布 213×151、可见胶囊 150×88 全圆端、填充 `#fbf9f4`、
暖褐色下糊阴影 → 折算成 100×60rpx 的 `.loading-bubble`），三个点改成常见的依次亮起 + 轻跳，
一轮 1.2s、间隔 0.18s。

- 静止态压到 0.28 透明度：某些机型不跑动画时，看到的仍是「三个深浅不一的点」，与原图接近，
  不会退化成三个死点。
- 顺带修掉一个小抖动：原图整体带约 21rpx 透明左边距，胶囊比其它 AI 气泡的背景左缘缩进；
  改成 CSS 后两者对齐，回复到达时不再横向跳一下。
- 那张 PNG 已无引用，暂时保留（本节记着它的量取结果，日后要还原有据可依）。

## Technical Decisions

- **校验接口本身失败一律放行**。网络抖动、后端 5xx、字段缺失都算。读不到判据就把 AI 锁死是更糟的
  失败模式：真不够的话紧接着那次 `/chat` 服务端照样会拒，用户看到的才是真实原因，而不是被端上一次
  网络故障扣上一顶「星币不足」的帽子。同理由见 `ai-token.fetchBalance`。
- **闸放在气泡上屏之前，不放在之后**。放之后（与建会话并行）能省掉一次等待，但余额见底的用户
  **每次**发送都会看到「气泡闪一下又被撤掉」；放之前只是多等一趟很短的 GET。
- **闸只有 `sendChat` 一处**（所有发送入口——普通发送、一键生图、语音——都汇到它）加「重试」入口。
  散到各入口去加会漏，且一次用户动作可能打两遍请求。
- **文案改星币、标识符不改**。后端字段是 `availableToken`、页面数据是 `tokenBalance`，改名等于
  在端上造一层与 swagger 对不上的翻译，收益为零。

## Risks

- ⚠️ **张数与服务端不一致的风险**：BoltStar 文档 §二 `image_urls` 上限仍写 4 张，超限回 `20012`。
  若服务端没同步放宽，第 5 张会被服务端打回（端上已把 `20012` 文案改成 5 张，届时提示语也会对不上）。
  **需与 AI 侧确认已放宽到 5**。
- ⚠️ `chkAiDialogue` 的**否定答复靠 403 这个业务码识别**。后端若改用别的码（或换成 200+false 之外的
  第三种形状）来表达「不够」，端上会当成「接口异常」放行，闸就失效了 —— 判定口径写在
  `token-api.AI_DIALOGUE_FORBIDDEN_CODE`，由 `tests/ai-token-balance.test.js` 按真机响应体锁住。
- ⚠️ 「最低余额」是从 `retMsg` 里**用正则抠数字**的（取第一个数）。后端改文案（例如加上
  「当前余额 5」这类前置数字）会让提示里的数字变错 —— 更稳的做法是请后端把它做成独立字段。
- ⚠️ `usertoken` 的取值/大小写若与 AI 侧理解不一致，不会报错，只会静默失效。
- 弹窗标题固定是「星币不足」。403 若还有余额之外的含义（账号被停等），标题会不准 ——
  正文在抠不到数字时会退回后端原话，至少说得清原因，但标题没跟着分流。
