# 2026-10-29 WiFi版投屏进度条含图片处理阶段

> 分支：`main-wifi`｜依据：产品口径——进度条 1~100% 要涵盖「图片上传中」和「图片处理中」，100% 只显示「已发送，屏幕即将刷新」

## 做了什么

原来进度条只表示上传进度：上传完就到 100%，接下来的「图片处理中」（服务端处理最长约 8 秒）一直停在 100%。现在改为：

| 阶段 | 文案 | 进度条 |
|---|---|---|
| 上传 | 图片上传中 | 0~50%，由真实上传进度折算（上传 30% → 15%） |
| 服务端处理 | 图片处理中 | 50% 起按时间渐近爬向 99%（约 1 秒 64%、3 秒 81%、8 秒 95%），不会到 100 |
| 接口返回 SENT | 已发送，屏幕即将刷新 | 100% |
| 接口返回 UPLOADED（多张时前面几张） | 已上传 | 100% |
| 失败（接口 FAILED / 报错） | 失败原因 | 停在当时的位置，不再上涨 |

- `utils/wifi-projection.js`：常量 `UPLOAD_SHARE` / `PROCESSING_CAP` / `PROCESSING_TAU_MS` 控制分段与爬升速度；上传完开始计时，接口返回或报错就停止。日志里的「上传进度 25% / 50% …」仍是真实上传百分比。
- WiFi 投屏结果页：成功后写「我的上传」记录时，不再把文案改成「正在存入我的上传」，100% 时一直显示「已发送，屏幕即将刷新」；写记录的过程照常记在投屏日志里。进度条下方的说明改为「进度含图片上传与处理；…」。
- 处理阶段没有真实进度，这一段是按时间估算的。
