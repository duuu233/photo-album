## 一、需求

产品原话：「搜索设备结果页面，假如有 6 个设备、6 条数据，把目前只显示 3 个的完整的设备的高度
改成显示 4.5 个的高度，让用户看最后一个设备一部分露出来的效果，表达是可以滚动的效果。」

要点是**露出半张**——一屏正好切在卡片缝上，看着就像「就这么多」，用户不会去滑。

## 二、改前：列表只能捡剩下的高度

上一版是一条经验值：

```css
.device-list { max-height: calc(100vh - var(--nav-h) - 960rpx - var(--safe-bottom)); }
```

`960rpx` = 上面几块（调试台横幅 ≈131 + 雷达 500+40 + 统计行 ≈92）+ 按钮那条（112+48+24）。
它当时解决的是「卡片被按钮压住又滚不动」，但列表拿到的**只是减剩下的那一截**：

| 机型 | 列表实得 | ≈ 几张卡（一张 ≈190rpx） |
| --- | --- | --- |
| iPhone 13（390×844） | 422rpx | 2.2 |
| 大屏安卓（412×915） | 488rpx | 2.6 |
| 小屏 SE（320×568） | 221rpx | 1.2 |

雷达占着 540rpx（500 + 40 上边距）雷打不动，列表想长到 4.5 张（844rpx）根本无从谈起。

## 三、改法：整页改竖向 flex，让列表先拿够、雷达让位

### 1. `.bind-content` 变成 flex 容器，底部替按钮占位

```css
.bind-content {
  display: flex;
  flex-direction: column;
  height: calc(100vh - var(--nav-h, calc(var(--status-bar) + 88rpx)));
  padding-bottom: calc(184rpx + var(--safe-bottom));   /* 112 按钮 + 48 贴底 + 24 缝 */
  box-sizing: border-box;
}
```

「立即绑定」是绝对定位、不占流，这段 padding 就是替它在流里占的位。
⚠️ 绝对定位的包含块是 **padding box**，所以按钮和「扫描不到怎么办」的贴底位置**没有挪动**。

### 2. 列表按 4.5 张封顶，允许被压

```css
.device-list {
  box-sizing: border-box;
  flex: 0 1 auto;
  max-height: 844rpx;     /* 4 张整 190×4 + 露出半张 168÷2 */
  min-height: 0;
  padding: 0 48rpx 24rpx;
}
```

- **844rpx** 的账：一张卡 ≈190rpx（卡本体 ≈168 = 上下 padding 48 + 描边 4 + 设备名 ≈43 +
  两行副标题各带 8rpx 上间距 ≈73；卡间距 22）。底部那 24rpx 留白**不额外加高**——
  滚动容器的裁剪边界是 padding box，卡片滚动时本来就会画进这段 padding 里。
- 仍用 `max-height` 而不是写死 `height`：只搜到一两台时列表收到内容高度，不在卡片下方留大片空档。
- `min-height: 0` 不可省：flex 项默认 `min-height: auto`，压不到内容高度以下。

### 3. 雷达在「已搜到设备」这一态主动让位

```css
.radar-wrap        { flex: 0 40 auto; width: 500rpx; height: 500rpx; min-height: 200rpx; }
.radar-wrap--found { width: 340rpx; height: 340rpx; min-height: 180rpx; margin-top: 24rpx; }
```

- 500 → 340rpx 让出的 200rpx，正是列表从「2 张多」长到「4.5 张」所需的那一截；
- `flex-shrink: 40`（列表是 1）＝「先压雷达，压到 `min-height` 才轮到列表」：收缩量按
  `shrink × basis` 摊，40×340 对 1×844 ≈ 94% 落在雷达上；
- `--found` 类由 `devices.length` 挂上去，与列表的渲染条件完全一致；搜索中/未发现两态
  雷达仍是 500rpx（那两态它是页面主体）。
- 雷达里的图是 `aspectFit`，容器被压扁只会让图跟着缩小居中，不会变形。

### 4. 不参与压缩的三块

`.debug-entry` / `.nearby-head` / `.scan-copy` 显式写 `flex: 0 0 auto` ——
flex 项默认 `flex-shrink: 1`，不写死的话它们会跟着一起被压扁。

## 四、改后各机型实得（用例算出来的）

| 机型 | 雷达 | 列表 | ≈ 几张卡 |
| --- | --- | --- | --- |
| iPhone 13 | 249rpx | 838rpx | 4.3 ~ 4.7 |
| 大屏安卓 | 310rpx | 842rpx | 4.3 ~ 4.8 |
| 小屏 SE | 180rpx（触底） | 706rpx | 3.7 ~ 4.0 |
| iPhone 13（开发版，多一条调试台横幅） | 180rpx（触底） | 784rpx | 4.0 ~ 4.4 |

区间是因为**行高各端不同**（iOS 苹方 ≈1.4、安卓 ≈1.2），卡本体实际在 159~175rpx 之间浮动，
露出的那张因此在 0.3~0.8 张之间，取中就是产品要的「半张」。
小屏 SE 装不下 4.5 张是物理限制：这时雷达已压到下限，再要就得切卡片——按降级处理，
但仍比改前的 1.2 张好得多。

## 五、测试

`tests/bind-device-list-layout.test.js` **整篇重写**（旧断言针对已作废的经验值 max-height）：

- 结构：`.bind-content` 是竖向 flex；`padding-bottom` 含 `--safe-bottom`，且 ≥「按钮高 + 贴底 + 16」；
- 列表：用 `max-height` 而不是 `height`、`box-sizing: border-box`、`min-height: 0`、`flex-shrink > 0`、底部留白 ≥16rpx；
- **4.5 张这件事本身**：拿 `.nearby-device` / `.nearby-name` / `.nearby-sub` 的实际声明按
  1.2 与 1.4 两种行高算卡高，断言 `max-height` 落在 **4.2~4.9 张**之间 —— 以后改卡片
  padding/字号/行距，这条会直接报「现在只够几张」；
- 雷达：`flex-shrink` 必须大于列表的；`--found` 态必须更矮；wxml 里那个条件类要真的挂着；
- 数值：三种机型 × 开发/正式两版，跑一遍**与浏览器同构的 flex 收缩**（按 `shrink × basis` 摊、
  碰 `min-height` 冻结后重分配），断言「三块高度和不越过按钮顶」「雷达不低于下限」
  「正式版 ≥4.2 张、开发版 ≥3.2 张」。

跑法：`node tests/bind-device-list-layout.test.js`。本轮仓库内其余 Node 用例一并跑过，
只有 `tests/token-page-layout.test.js` 失败，**与本轮无关**（它在改动前就已失败，
断言的是 `subpackages/token/index/index.wxss` 里已被 `487869b` 删掉的规则）。

## 六、待办 / 未动

- ⚠️ **真机未验**：尤其是「露出半张」的实际观感，以及 iOS 上行高偏大时露出的比例。
- ⚠️ 折叠屏展开（宽而矮，1rpx 被放得很大）仍然挤：那种形态下雷达会一路压到 180rpx、
  列表也吃不满。至少不会再出现「卡片被按钮盖住又滚不动」——底部空间现在是硬预留的。
  用例里仍不含这一档。
- 未动：`.bind-content` 的高度算式、按钮与「扫描不到怎么办」的贴底位置、卡片样式、
  扫描中 / 未发现两个分支的排版、`bind.js` 的任何逻辑。
