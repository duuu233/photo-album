# 相册 WiFi 版：无 TF 卡时删除指定照片

> 状态：draft｜2026-10-27
> 依据：[XT 相框通讯协议 V1.3.1](XT相框通讯协议_V1.3.1.md) §2.8~2.15、[前端对接文档草稿](../前端对接文档_草稿.md) §1 / §3 / §3.10、[前端评审回复](前端评审回复.md) §8

## 一句话结论

**删云端就行，不需要发"同步下载"指令**（协议里也没有）。设备会按时自己拉列表。
唯一要补的：**删的若正是屏上那张，要补发一次 `play` 换图**。

## 为什么没 TF 卡也能投屏

- `play`（§2.8）只带下载地址：服务端转 bin → 放 OSS → 设备自己下载、刷屏，不经过 TF 卡。
- 平台方确认：TF 卡和 App 投屏是**两条独立通道**，App 投的图不存在设备里。
- 设备上只有"屏幕上那一张"，电子纸断电后画面也不会消失。

## 删除流程

| 步骤 | 做什么 | 说明 |
|---|---|---|
| 1 | 删老服务相册记录 | 设备拉的列表 `/device/playlist` 读的就是这里的 `imgBle`；有 60 秒缓存 |
| 2 | 判断是否屏上那张 | 是 → 服务端发 `play` 换成下一张；删空后显示什么，产品定 |
| 3 | 延后删 OSS 上的 bin | 防止设备正在下载时报下载失败 |
| 4 | 设备离线时 | 控制接口返回 4041；记录照删，等 `DEVICE_ONLINE` 再补发换图 |

建议提示文案：**"已从相框播放列表移除，设备联网后更新"**。

## 不能用的接口

| 接口 | 原因 |
|---|---|
| `clean_tf` / `POST /api/device/clean-tf` | 属于 TF 通道；服务端固定清"全部"，无卡时什么也不做，有卡时连内置图（出厂页、无 WiFi 提示等）一起清掉 |
| `image_refresh` / `POST /api/device/refresh` | 协议说明写的是"清空 TF 卡内容"，和标题"刷新图片"矛盾；且是唯一没有执行结果回执的指令，成败无法判断 |

## 小程序侧注意

蓝牙版删图依赖记录里的槽位号 `imgIndex`，WiFi 版没有槽位：删除逻辑按设备类型分开，后端不要塞假槽位号。
