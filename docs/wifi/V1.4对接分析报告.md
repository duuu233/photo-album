# XT相框协议 V1.4 · 小程序对接分析报告

> 日期：2026-10-27｜分支：`main-wifi`｜依据：[V1.4 更新说明](XT相框通讯协议_V1.4_更新说明.md) v1.1、[协议 V1.4](XT相框通讯协议_V1.4.md)｜改动明细见 [变更记录](../changes/2026-10-27-WiFi版V1.4对接.md)

## 一句话

投屏改成「发出去就算完」，照片进「我的上传」，新增 WiFi 轮播设置（可选照片），WiFi 照片能删，设备多了「已关机」；另外每个页面都加了可复制的日志浮窗。

## 改了什么

| 项 | 以前 | 现在 |
|---|---|---|
| 投屏 | 等设备回执，最长等 90 秒 | 接口返回「已发送」就结束，提示「已发送，屏幕即将刷新」 |
| 多张投屏 | 每张都刷一次屏 | 前面几张只上传，最后一张才刷屏，整批只刷一次 |
| 我的上传 | WiFi 投的图不进相册 | 每张投完写一条相册记录（缩略图 + 设备下载地址） |
| 我的设备 / 设备详情按钮 | 投屏 + 刷新状态 | 投屏 + **轮播设置** |
| 轮播设置 | 没有 | 新页面：间隔时间 / 固定时间、顺序 / 随机、轮播后休眠；从「我的上传」单选 / 多选 / 全选照片，按选择顺序轮播，不选 = 轮播全部 |
| 删除照片 | WiFi 版删不了 | 先删相册记录，再删云端文件；删到屏上那张时服务端自动换下一张 |
| 设备状态 | 在线 / 休眠中 / 离线 | 多一个「已关机」（灰） |
| 日志 | 只有投屏结果页有 | 每个页面左下角「日志」浮窗，点开看、一键复制（开发版 / 体验版） |

## 协议 V1.4 本身对前端的影响

- 104 下载失败细分成 200～212：服务端统一按「图片下载失败」发消息，前端不用处理。
- `strategy_bin` / `image_refresh` / `wifi_sleep` 等字段修正、文档里的笔误：都是设备和服务端之间的事，前端不涉及。

## 没做的（小程序还没有对应页面）

- 休眠设置的「一次性休眠」：还没有 WiFi 休眠设置页。
- 消息中心：投屏成功 / 失败（`PLAY_SUCCESS` 等）要在消息列表里看，小程序还没有消息页；目前投屏结果只看相框画面。

## 需要确认的

| # | 问题 | 找谁 |
|---|---|---|
| 1 | 写相册记录用的是 `addUserProductImgRecord`（不带任务号新建一条）：老服务是否接受、「我的上传」能否按设备查回来 | 老服务 |
| 2 | 删除时「下一张」取相册里剩下的第一张，是否符合产品预期 | 产品 |
| 3 | 轮播中平台不知道屏上是哪张，删图可能不会自动换图（服务端只认最后一次投屏的那张） | 固件 / 后端 |
| 4 | 设备是每次到点都重新拉列表，还是只在收到轮播设置时拉；后者的话删图、加图后要重新保存一次轮播 | 固件 |
| 5 | 说明里「设备内页：蓝牙设备保留投屏，连接改为轮播设置」：按 WiFi 版设备详情理解（蓝牙版的连接按钮没动） | 产品 |
