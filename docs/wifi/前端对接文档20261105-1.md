## 一、这次要改什么

> 每条先「原样引用」产品原话，再给「后端说明」。原话不改写，确保表述不走样。

### 第 1 条 · 图片选择弹层

**产品原文：**

> 轮播图片，不要默认展开改成同高级设置里一样的选择图片交互，弹出层需要加一个从下往上拉的动效，每行显示3张图（同我的上传图片样式、pagesize改为21）

**后端说明：**

- 纯前端改动，服务端不涉及。
- 补充：**高级卡片里的图片选择也要加同样的动效**（与简单模式保持一致）。
- `imgUrls` 提交上限仍是 **100 张**，弹层里要限制并提示。
- 未选择任何图片时，服务端按"轮播全部相册（含之后新上传的）"处理。

### 第 2 条 · 时区显示本地化

**产品原文：**

> 时区显示去掉UTC+8文字，根据语种显示文字，下拉框列表不需要左右2个文字，保留左边的即可（单左边的文字需要根据语种显示），中国就中国/北京  即可。

**后端说明：**

- 纯前端改动，服务端不涉及。
- ⚠️ **展示文案可以本地化，但提交给服务端的值必须是 IANA 名**（`Asia/Shanghai`）。传「中国/北京」会返回 `4000 时区非法`。
- 展示层和提交值必须是两套数据，不要合并。

### 第 5 条 · 下次刷新加卡片类型

**产品原文：**

> 下次刷新，时间后面新增一个 卡片类型（每N天 or 每N分钟或小时\工作日\周末\纪念日）期待结果：下次刷新：11-06 08:00 · 工作日
>
> GET /api/device/strategy
> → nextRefreshAt           : "2026-11-06 08:00:00"
> → nextRefreshCardType     : "base" | "weekday" | "weekend" | "anniversary"
> → nextRefreshCardMonthDay : "10-20"（仅纪念日）
> 如果nextRefreshCardType==base 则 每 N 分钟 / 每 N 天」用已有的 updateType / intervalMinutes / updateDays 就能区分

**后端说明：**

- **三个字段已经实现并上线**，返回结构与你写的一致。
- 拼接规则：

| `nextRefreshCardType` | 显示文案 | 取哪个字段 |
|---|---|---|
| `base` | `每 N 分钟` / `每 N 小时` | `intervalMinutes`（间隔模式） |
| `base` | `每天` / `每 N 天` | `updateDays`（固定模式，`1` 显示「每天」） |
| `weekday` | `工作日` | — |
| `weekend` | `周末` | — |
| `anniversary` | `纪念日` | 可附 `nextRefreshCardMonthDay` |

- ⚠️ **必须兜底的情况：**

| 情况 | 处理 |
|---|---|
| `nextRefreshAt` 为 `null` | **整行不显示**（暂停轮播，或 367 天内没有触发） |
| `nextRefreshCardType == "base"` 但 `intervalMinutes` 为 `null` | 不显示类型后缀 |
| `nextRefreshCardType == "base"` 但 `updateDays` 为 `null` | 不显示类型后缀 |
| `updateDays == 1` | 显示「每天」，不要显示「每 1 天」 |

> `intervalMinutes` 和 `updateDays` 现在**都可能是 `null`**——当用户关闭「简单模式」、只配了高级卡片时就会出现。

### 第 6 条 · 每 N 天上限 30 天

**产品原文：**

> 固定时间每个N天 最大天数选择为30天。

**后端说明：**

- **后端已改并上线**：`updateDays` 上限由 365 改为 **30**，超出返回 `4000`。前端同步限制 1–30。
- ⚠️ 存量配置如果原本大于 30，**调度会继续按原值跑，但用户保存不了任何修改**（会被 30 卡住）。前端读取到 `updateDays > 30` 时应提示用户调整播放频率。

---

### 第 7 条 · 纪念日只选月日

**产品原文：**

> 纪念日只允许选择月、日 ，不允许选择年。

**后端说明：**

- 后端存的是 `MM-dd`，没有年份。
- ⚠️ **截图里纪念日的说明文字「02月29日只在闰年生效」是错的，必须删掉**。后端**已经拒绝 `02-29`**（返回 `4000`）。
- 前端日期选择器规则：

> 选了月份后，日只能选该月的合法日期：**2 月最多 28 日**，4/6/9/11 月最多 30 日。

这样 2 月 29 日、2 月 30 日根本选不出来。2 月 29 日出生的人请选 **2 月 28 日**。

---

### 第 8 条 · 基础配置不再必填

**产品原文：**

> 基础模式时间不再是必填，只要 基础 工作日 周末 纪念日任意一个填了就可以保存成功，如都没有启用或填写保存按钮置灰。

**后端说明：**

- **后端已放开**，两种模式都支持：

| 模式 | 基础为空时 | 保存条件 |
|---|---|---|
| 固定模式 | `updateTimeList` 不传 / 空数组 | 「基础时间点」或「至少一张高级卡片」二选一 |
| 间隔模式 | `timingTime` 不传 | 「基础间隔」或「至少一张高级卡片」二选一 |

- 固定模式下，**`updateDays` 仅在 `updateTimeList` 非空时必填**——基础为空时不用传。
- 全部为空时的错误文案分模式：
  - 固定模式：`4000`「至少配置一项播放时间」
  - 间隔模式：`4000`「至少配置一项播放间隔」
- 建议前端在保存前就拦住，给统一提示「至少配置一项」。

---

### 第 9 条 · 基础设置做成「简单模式」卡片

**产品原文：**

> 重点：间隔和固定 下的基础设置需要也做成卡片 并带有 启用开关，默认启用并展开 名称：简单模式

**后端说明：**

- 纯前端改动。
- 开关关闭 = **不提交基础字段**：
  - 间隔模式：不提交 `timingTime` / `beginTime` / `endTime`
  - 固定模式：不提交 `updateDays` / `updateTimeList`
  - 两种模式都不提交基础的 `imgUrls` / `mode`
- 关闭后**必须至少启用一张高级卡片**，否则保存报 `4000`。
- ⚠️ 间隔模式下，**高级卡片里也必须有「起止时间 + 播放间隔」两栏**（和简单模式一致，只是各自独立）。

## 三、交互与校验规则

### 3.1 简单模式的启用开关

| 操作 | 行为 |
|---|---|
| 默认 | **启用并展开** |
| 关闭 | 不提交基础字段（间隔模式的 `timingTime`/`beginTime`/`endTime`，固定模式的 `updateDays`/`updateTimeList`），图片与顺序也不提交 |
| 关闭后 | 至少启用一张高级卡片才能保存 |

### 3.2 保存校验（前端先拦，后端兜底）

| # | 规则 | 失败表现 |
|---|---|---|
| 1 | 「简单模式已启用」**或**「至少一张高级卡片已启用」 | 前端提示「至少配置一项」；后端 `4000` |
| 2 | `updateDays` 范围 **1–30** | `4000` |
| 3 | 间隔值 **600–86400 秒**（10 分钟–24 小时） | `4000` |
| 4 | 时间点格式 `HH:mm`；`endTime` 允许 `24:00` | `4000` |
| 5 | 纪念日按月份限制合法日期（**2 月最多 28 日**）；同一设备内 `monthDay` 不可重复 | `4000` |
| 6 | `imgUrls` 最多 **100** 张 | `4000` |
| 7 | `timeZone` 必须是 IANA 名 | `4000` |

### 3.3 「下次刷新」文案拼接

```
下次刷新：{MM-dd HH:mm} · {卡片类型}
```

| `nextRefreshCardType` | 显示 | 取哪个字段 |
|---|---|---|
| `base` | `每 N 分钟` / `每 N 小时` | `intervalMinutes`（间隔模式） |
| `base` | `每 N 天` / `每天` | `updateDays`（固定模式） |
| `weekday` | `工作日` | — |
| `weekend` | `周末` | — |
| `anniversary` | `纪念日`（可加 `nextRefreshCardMonthDay`） | — |

**必须兜底的情况**：

| 情况 | 处理 |
|---|---|
| `nextRefreshAt` 为 `null` | **整行不显示**（暂停轮播 / 367 天内无触发） |
| `nextRefreshCardType == "base"` 但 `intervalMinutes` 为 `null` | 不显示类型后缀 |
| `nextRefreshCardType == "base"` 但 `updateDays` 为 `null` | 不显示类型后缀 |
| `updateDays == 1` | 显示「每天」而不是「每 1 天」 |


### 3.4 时区

| 项 | 要求 |
|---|---|
| 显示 | 按语种本地化，如「中国 / 北京」「美国 / 纽约」 |
| **提交值** | **必须是 IANA 名**（`Asia/Shanghai`），**不能提交本地化文案**，否则 `4000 时区非法` |
| 默认 | 自动取手机系统时区 |

> ⚠️ 展示层和提交值必须是两套数据，不要合并。

### 3.5 纪念日

- 只选「月、日」，不选年（后端存 `MM-dd`）
- **按月份限制可选天数**：
  - 2 月：**1–28**（不出现 29、30）
  - 4 / 6 / 9 / 11 月：1–30
  - 其余月份：1–31
- **2 月 29 日出生的人请选 2 月 28 日**
- 同一设备内不能重复（如两个 `10-20`）
- 纪念日当天独占：工作日 / 周末 / 简单模式都不执行

## 四、字段对照

### 4.1 间隔模式提交

| UI 区块 | 字段 |
|---|---|
| 顶层 | `deviceNo` / `updateType=2` / `timeZone` |
| 简单模式 | `timingTime` / `beginTime` / `endTime` / `mode` / `imgUrls` |
| 工作日 / 周末 | `weekday` / `weekend` 对象内的 `timingTime` + `beginTime` + `endTime` + `mode` + `imgUrls` |
| 纪念日 | 同上 + `monthDay` |

### 4.2 固定模式提交

| UI 区块 | 字段 |
|---|---|
| 顶层 | `deviceNo` / `updateType=1` / `timeZone` |
| 简单模式 | `updateDays` / `updateTimeList` / `mode` / `imgUrls` |
| 工作日 / 周末 | `weekday` / `weekend` 对象内的 `updateTimeList` + `mode` + `imgUrls` |
| 纪念日 | 同上 + `monthDay` |

> 一张卡片里同时带两组参数也没关系，服务端只取当前 `updateType` 需要的那组。**推荐前端复用同一个卡片组件**，切模式时只切换显示的字段。

### 4.3 查询响应（新增 / 变化）

| 字段 | 说明 |
|---|---|
| `timeZone` | 当前时区（IANA） |
| `nextRefreshAt` | 下次刷新时间 `yyyy-MM-dd HH:mm:ss`，可能为 `null` |
| `nextRefreshCardType` | `base` / `weekday` / `weekend` / `anniversary`，可能为 `null` |
| `nextRefreshCardMonthDay` | 仅 `anniversary` 有值 |
| `intervalMinutes` | **基础未配置时为 `null`**（原来返回 0） |
| `updateDays` | **基础未配置时为 `null`** |
| `weekday` / `weekend` / `anniversaries` | 卡片回显 |

## 五、错误码

| code | 场景 |
|---|---|
| `4000` | 参数错误（时区非法、间隔越界、`updateDays` 超 30、时间格式错、纪念日 `02-29`、日期重复、基础与卡片全空、普通与高级字段混传等），原因见 `msg` |

| `4041` | 设备离线 |
| `429` | 操作过于频繁 |
