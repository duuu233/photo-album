# 设备休眠状态对接说明

> 版本：v1.0（2026-10-27）
> 适用端：小程序 / App
> 依据：[前端对接文档_草稿.md](前端对接文档_草稿.md) v0.39、服务端提交 `c7a0de3`
> 目的：在现有「在线 / 离线」基础上补充「休眠中」，避免把设备正常休眠显示成离线。

---

## 一、变更摘要

| 接口 / 消息 | 变化 | 兼容性 |
|---|---|---|
| `GET /api/device/online` | `data` 新增 `status` | 只增字段，旧客户端可忽略 |
| `GET /api/device/info` | `data` 新增 `status` | 只增字段，旧客户端可忽略 |
| WebSocket `device.status` | 消息体新增 `status` | 只增字段，旧客户端可忽略 |
| `POST /api/device/sleep` | 请求字段不变；新增校验：开始时间不能等于结束时间 | 正常调用无影响 |

`status` 取值固定为三个大写字符串：

| 值 | 含义 | 建议展示 |
|---|---|---|
| `ONLINE` | 在线 | 绿色「在线」 |
| `OFFLINE` | 离线 | 灰色/红色「离线」 |
| `SLEEPING` | 休眠中 | 蓝色「休眠中」 |

`online` 布尔字段保留不变：`status=SLEEPING` 时 `online=false`。

---

## 二、接口返回示例

### 2.1 `GET /api/device/online`

```
GET /api/device/online?deviceNo=D0CF13F02FF8
Header: userToken
```

在线：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "deviceNo": "D0CF13F02FF8",
    "online": true,
    "status": "ONLINE",
    "lastOnlineAt": "2026-10-27 16:16:48"
  }
}
```

休眠中：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "deviceNo": "D0CF13F02FF8",
    "online": false,
    "status": "SLEEPING",
    "lastOnlineAt": "2026-10-27 16:16:48"
  }
}
```

离线：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "deviceNo": "D0CF13F02FF8",
    "online": false,
    "status": "OFFLINE",
    "lastOnlineAt": "2026-10-27 16:16:48"
  }
}
```

### 2.2 `GET /api/device/info`

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "deviceNo": "D0CF13F02FF8",
    "online": false,
    "status": "SLEEPING",
    "lastOnlineAt": "2026-10-27 16:16:48",
    "firmwareVersion": "M H:2 F:0.6.2",
    "shadow": { "battery": 85, "lastHeartAt": "2026-10-27 16:15:56" }
  }
}
```

### 2.3 WebSocket `device.status`

```json
{
  "type": "device.status",
  "deviceNo": "D0CF13F02FF8",
  "online": false,
  "status": "SLEEPING"
}
```

- 订阅方式不变：先 `subscribe` 该设备，且用户具备设备权限。
- 休眠断开时推送 `online=false, status=SLEEPING`。
- 设备唤醒登录时推送 `online=true, status=ONLINE`。
- 休眠期间不会推送 `DEVICE_OFFLINE` 通知。

---

## 三、状态判定规则

1. **在线优先**：设备当前在线时一定是 `ONLINE`，即使处于休眠时间窗口内。
2. **休眠其次**：设备离线时，如果服务端保存的休眠计划处于生效窗口内，返回 `SLEEPING`。
3. **其余为离线**：设备离线且不在休眠窗口，返回 `OFFLINE`。
4. 休眠计划由 `POST /api/device/sleep` 成功下发后保存；`enable=false` 时计划失效。
5. 窗口按 `Asia/Shanghai` 计算，支持跨天（如 `22:00 → 07:00`），开始时间包含、结束时间不包含。
6. 到达唤醒时间但设备仍未连上云端时，状态会从 `SLEEPING` 变为 `OFFLINE`。

## 四、前端展示建议

### 4.1 状态映射

```js
function statusText(status, online) {
  const value = status || (online ? 'ONLINE' : 'OFFLINE');
  return {
    ONLINE: '在线',
    OFFLINE: '离线',
    SLEEPING: '休眠中'
  }[value] || '未知';
}
```

- 服务端未升级、返回里没有 `status` 时，按 `online` 回退，保持旧行为。
- 不要在 `SLEEPING` 时提示「设备离线，请检查网络」。
- 设备列表、设备详情、首页卡片建议统一使用同一套状态文案和颜色。

### 4.2 操作限制

- 休眠中的设备执行投屏、轮播、刷新、配置等操作，服务端仍会返回 `4041 设备已离线`。
- 建议在 UI 上提前提示「设备休眠中，唤醒后可操作」，避免用户反复点击。
- 休眠状态不需要前端自行定时刷新；按原有进入页面/下拉刷新/轮询逻辑查询即可。

### 4.3 配网轮询

- 配网第 4 步仍然轮询 `GET /api/device/online`，只有 `online=true` 才算成功。
- `SLEEPING` 不等于配网成功，不要停止轮询。
- `since` 语义不变，只有设备新一次登录/连接才会让 `lastOnlineAt > since`。

## 五、休眠设置接口补充

`POST /api/device/sleep` 原有字段不变：

```json
{
  "deviceNo": "D0CF13F02FF8",
  "enable": true,
  "sleepTime": "22:00",
  "wakeTime": "07:00"
}
```

新增约束：

- `enable=true` 时，`sleepTime` 不能等于 `wakeTime`，否则返回 `4000`。
- 时间仍是本地 `HH:mm`，前端不要转 UTC。
- 接口返回 `msgids` 不变，不返回状态。
- 设备必须在线的状态下才能修改休眠设置；设备正在休眠时无法通过本接口关闭休眠。

---

## 六、已知限制

1. 只有通过本服务 `POST /api/device/sleep` 设置的休眠计划才会被识别。通过旧版本、公版 App 或设备自身设置的休眠，服务端没有记录，断开时仍显示 `OFFLINE`。
2. 休眠计划保存在 Redis（已开启 AOF/RDB）。如果 Redis 数据被清空，计划会丢失，设备会显示为 `OFFLINE`。
3. 服务端按 `Asia/Shanghai` 判断窗口；设备本地时钟偏差较大时，实际休眠时间可能与状态不一致。
4. 休眠期间设备完全离线，无法接收云端指令，这是正常行为。

## 七、前端验收清单

- [ ] 在线设备显示「在线」，颜色正确。
- [ ] 普通离线设备显示「离线」。
- [ ] 休眠窗口内断开的设备显示「休眠中」，不显示「离线」，不弹网络错误提示。
- [ ] 设备唤醒后恢复「在线」。
- [ ] WS 收到 `device.status` 时能正确展示 `SLEEPING`。
- [ ] 服务端返回缺少 `status` 时，按 `online` 回退，不报错。
- [ ] 配网轮询只认 `online=true`，`SLEEPING` 不会误判成功。
- [ ] 休眠中点击投屏等操作时，能展示「设备休眠中」提示（服务端返回 4041）。
