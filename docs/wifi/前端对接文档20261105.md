## 一、这次改了什么（一页看懂）

轮播从「设备自己按 strategy 定时拉图」改为「服务端按配置定时推送图片」。原因是**设备时钟不可靠**（实测每次开机回退到上次开机时刻，走时速率约 0.1%），设备侧的固定时间轮播从来没真正跑通过。

| # | 变更项 | 变化 | 前端要做什么 |
|---|---|---|---|
| 1 | **时区** | 新增 `timeZone`，间隔/固定共用一个值 | 新增时区控件，默认取手机时区，可手动下拉选择其他时区 |
| 2 | **间隔范围** | 沿用 `timingTime`（秒），最小值改 **600 秒（10 分钟）**，去掉 1 分钟 / 5 分钟选项 | 候选项改为 10 分钟 / 15 分钟 / 30 分钟 / 1 小时 / 2 小时… 24小时|
| 3 | **间隔窗口** | `beginTime`/`endTime` 保留，不传默认 `00:00–24:00`；`endTime` 允许 `24:00` | 保留起止时间控件 |
| 4 | **高级设置** | 新增可展开的「高级设置」，内含 **工作日 / 周末 / 纪念日** 三类卡片 | 新增展开面板 + 三张卡片 |
| 5 | **轮播休眠** | `idle` 废弃，服务端不做休眠联动 | 去掉「轮播后休眠」开关 |
| 6 | **模式互斥** | 间隔 / 固定二选一，切换**不清空**另一方数据 | 切回时读回之前的配置 |
| 7 | **离线不补发** | 设备离线期间错过的轮播，上线后不补 | 无 |
| 8 | **新通知类型** | `CAROUSEL_NOT_SENT`（轮播未发送成功） | 新增通知渲染 |
| 9 | **时间重叠校验取消** | 因为每天只会有一种卡片生效，不需要再校验时间点重复 | **删掉相关校验逻辑** |
| 10 | **投屏成功或失败结果页** | 新增再投一张按钮，同蓝牙一样的2个按钮
| 10 | **配网步骤** | App 把配网 设备正在接入云端的 等待窗口从 ~60 秒提到 120 秒

## 二、时区（新增）

### 2.1 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `timeZone` | string | **是** | IANA 时区名，如 `Asia/Shanghai`、`America/New_York` |

**间隔/固定共用同一个值**，切换模式时保留。

### 2.2 默认值与交互

| 项 | 要求 |
|---|---|
| 默认值 | 自动取手机系统时区（iOS `TimeZone.current.identifier`；Android `TimeZone.getDefault().getID()`；小程序用 `getSystemInfoSync().timezone` 换算成 IANA 名） |
| 交互 | 下拉选择，支持搜索 |
| 展示 | 「Asia/Shanghai（UTC+8）」，带偏移便于理解 |
| 保存后 | 以服务端回传值为准 |

### 2.3 建议候选列表

| 分组 | 时区 |
|---|---|
| 中国 | `Asia/Shanghai` |
| 港澳台 | `Asia/Hong_Kong`、`Asia/Macau`、`Asia/Taipei` |
| 亚洲 | `Asia/Tokyo`、`Asia/Seoul`、`Asia/Singapore`、`Asia/Bangkok`、`Asia/Dubai` |
| 欧洲 | `Europe/London`、`Europe/Paris`、`Europe/Berlin`、`Europe/Moscow` |
| 美洲 | `America/New_York`、`America/Chicago`、`America/Denver`、`America/Los_Angeles` |
| 大洋洲 | `Australia/Sydney`、`Australia/Perth`、`Pacific/Auckland` |

### 2.4 校验

- 必须是合法 IANA 名，否则 `4000`
- **不要传 `UTC+8` 这类固定偏移字符串**——有夏令时的地区会算错

### 3.3 展开状态与数据来源

这两件事要分开看。

#### 展开 / 收起

| 项 | 规则 |
|---|---|
| 进入页面时 | **默认收起，不自动展开** |
| 用户手动展开 | 只影响当前页面会话，不持久化 |
| 再次进入页面 | 回到收起状态 |

> 不自动展开的理由：高级设置是低频功能，默认展开会让普通用户一进来就看到三张卡片，增加心智负担。

**可选优化**：在「高级设置」按钮上加已配置数量提示，例如「高级设置（2 项）」，让用户知道里面有内容但主界面不被撑开。

#### 数据来源

| 场景 | 高级设置里显示什么 |
|---|---|
| 填写了但**没保存**，收起后再展开（没离开页面、没重新拉数据） | 保留**本地已填写**的内容（草稿） |
| 关闭 App / 小程序后重新进入，或任何触发**重新拉取轮播数据**的动作 | **以服务端为准**；服务端没保存过高级设置就显示默认空状态 |

> 一句话：**未提交的编辑只在当前页面会话内有效**；一旦重新拉数据，草稿丢弃，一律以服务端为准。

## 四、判定规则（核心）

服务端每天判断「今天落进哪一格」，**每天只有一种卡片生效**：

```
1. 今天是纪念日？
     → 用对应的纪念日卡片（当天独占）

2. 今天周六 / 周日？
     周末卡片已启用  → 用周末卡片
     否则            → 跳到 4

3. 今天周一到周五？
     工作日卡片已启用 → 用工作日卡片
     否则             → 跳到 4

4. 基础配置
     间隔模式：按起止时间 + 间隔触发
     固定模式：今天符合「每 N 天」节奏才触发
```

**优先级：纪念日 > 周末 / 工作日 > 基础配置**

### 4.1 由此带来的两个结果

| 结果 | 说明 |
|---|---|
| **不需要时间重叠校验** | 每天只有一张卡片在工作，跨卡片的时间点天生不会冲突 |
| **启用任意一张 → 基础配置在对应日子不生效** | 只启用「工作日」时，基础配置只剩周末生效；只启用「周末」时，基础配置只剩工作日生效 |
| **工作日 + 周末都启用 → 基础配置永不生效** | 每一天要么工作日、要么周末，轮不到基础配置 |

### 4.2 前端必须做的提示

**只要「工作日」或「周末」任意一张被启用**，轮播页面上就要出现提示，位置在基础配置旁。分三档：

| 启用情况 | 提示文案（建议） | 样式 |
|---|---|---|
| 只启用「工作日」 | 工作日已启用独立配置，本配置在工作日不生效 | 灰字 |
| 只启用「周末」 | 周末已启用独立配置，本配置在周末不生效 | 灰字 |
| **两张都启用** | **工作日与周末均已启用，本配置将不会生效** | 灰字 |

补充规则：

- 提示为**纯文字**，不阻断保存，也不参与任何校验
- 三档提示在**同一位置**，按启用状态切换文案
- 「纪念日」不需要常驻提示——它是单日事件，在纪念日卡片上标注「当天独占」即可

> 为什么只启用一张也要提示：只启用「工作日」时，基础配置在工作日不生效、只在周末生效。用户看不到提示就会以为"我设的配置怎么一周只跑两天"。



### 4.3 卡片参数非法时的回落

某张卡片参数非法（如间隔小于 10 分钟）时，服务端会**跳过该卡片并回落到下一级判定**，而不是当天完全不刷。

## 五、间隔模式

### 5.1 参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `beginTime` | string | 否 | 起止窗口开始，`HH:mm`，不传默认 `00:00` |
| `endTime` | string | 否 | 窗口结束，`HH:mm` 或 `24:00`，不传默认 `24:00` |
| `timingTime` | number | 是 | 间隔，**单位秒**，范围 `600–86400` |
| `mode` | number | 否 | `1` 顺序（默认）/ `2` 随机 |
| `imgUrls` | string[] | 否 | 图片组，去重保序，最多 100；不传 = 全部相册 |
| `timeZone` | string | 是 | 见第二节 |

**候选项建议**：10 分钟、15 分钟、30 分钟、1 小时、2 小时、3 小时、6 小时、12 小时、24 小时。

### 5.2 触发规则

| 项 | 规则 |
|---|---|
| 相位锚点 | **用户保存配置的时刻**（服务端落库时间，精确到秒） |
| 首次触发 | 锚点 + 1 个间隔，**不取整**（例：`10:31:20` 保存、间隔 10 分钟 → 首次 `10:41:20`） |
| 后续触发 | 锚点 + k × 间隔，跨天连续滚动 |
| 窗口过滤 | 只有落在 `[beginTime, endTime)` 内的触发点才真正下发 |
| 窗口外 | 跳过，相位继续滚动，下一个落在窗口内的点再发 |
| 跨天窗口 | 支持（如 `22:00 ~ 06:00`），`beginTime > endTime` 视为跨天 |
| 相位重置 | **仅当间隔值变化，或首次开启轮播**；改图片/顺序/窗口不动相位 |

### 5.3 前端展示

轮播设置页展示一行只读信息：

```
下次刷新：2026-11-05 10:41
```

数据来自 `GET /api/device/strategy` 的 `nextRefreshAt`。

## 六、固定模式

### 6.1 参数（基础配置）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `updateDays` | number | 是 | 每 N 天，`1–365`，`1` = 每天 |
| `updateTimeList` | string[] | 是 | 播放时间，`HH:mm` 数组，至少 1 个 |
| `mode` | number | 否 | `1` 顺序（默认）/ `2` 随机 |
| `imgUrls` | string[] | 否 | 图片组，最多 100 |
| `timeZone` | string | 是 | 见第二节 |

### 6.2 触发规则

- 当天符合「每 N 天」节奏（以保存日为锚点）时，在该日的每个 `updateTimeList` 时刻各触发一次
- 不符合节奏的日子不触发

## 七、高级卡片

三类卡片共用同一个对象结构，**按当前 `updateType` 取用对应的一组参数**：

| 卡片 | 数量 | 是否可多条 |
|---|---|---|
| 工作日 | 0 或 1 | 否 |
| 周末 | 0 或 1 | 否 |
| 纪念日 | 0 ~ N | 是，`monthDay` 不可重复 |

### 7.1 卡片对象字段

| 字段 | 类型 | 适用 | 说明 |
|---|---|---|---|
| `enabled` | boolean | 工作日 / 周末 | `false` 或省略 = 未启用 |
| `monthDay` | string | 纪念日必填 | `MM-dd`，如 `10-20` |
| `mode` | number | 全部 | `1` 顺序 / `2` 随机 |
| `imgUrls` | string[] | 全部 | 该卡片专属图片组，最多 100 |
| `beginTime` | string | 间隔模式 | 窗口开始 |
| `endTime` | string | 间隔模式 | 窗口结束 |
| `timingTime` | number | 间隔模式 | 间隔秒数，`600–86400` |
| `updateTimeList` | string[] | 固定模式 | 播放时间数组 |

> 一张卡片里同时带上两组参数也没关系，服务端只取当前模式需要的那一组，另一组忽略。

### 7.2 纪念日的特殊规则

| 项 | 规则 |
|---|---|
| 独占 | 纪念日当天**只有该纪念日卡片生效**，工作日 / 周末 / 基础配置全部不执行 |
| 刷新节奏 | 间隔模式按卡片的窗口 + 间隔；固定模式按卡片的 `updateTimeList`，默认 `["00:00"]` |
| 公历 | 只支持公历日期，`monthDay` 按 `timeZone` 解释 |
| 闰日 | `02-29` 只在闰年生效 |
| 离线 | 当天设备不在线则该次错过，不补发（与全局规则一致） |

## 八、播放规则

| 场景 | 行为 |
|---|---|
| 顺序播放 | 播放索引**按「设备 + 卡片」独立维护**，跨天不重置 |
| 索引算法 | 累计触发次数 % 图片数 |
| 图片数 < 时间点数 | 自然循环。例：3 个时间点、2 张图 → 图1 / 图2 / 图1，次日 图2 / 图1 / 图2 |
| 随机播放 | 每次随机取一张，且避开上一张 |
| 当天没有命中任何卡片 | 不触发，画面保持不动 |

**顶层字段说明**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deviceNo` | string | 是 | 设备编号 |
| `updateType` | number | 否 | `2` 间隔（默认）/ `1` 固定 |
| `timeZone` | string | **是** | IANA 时区名 |
| `timingTime` | number | 间隔必填 | 秒，`600–86400` |
| `beginTime` | string | 否 | 间隔窗口开始，默认 `00:00` |
| `endTime` | string | 否 | 间隔窗口结束，默认 `24:00` |
| `updateDays` | number | 固定必填 | `1–365` |
| `updateTimeList` | string[] | 固定必填 | `HH:mm` 数组 |
| `mode` | number | 否 | `1` 顺序（默认）/ `2` 随机 |
| `imgUrls` | string[] | 否 | 基础配置图片组，最多 100 |
| `weekday` | object | 否 | 工作日卡片，`null` 或不传 = 未启用 |
| `weekend` | object | 否 | 周末卡片 |
| `anniversaries` | object[] | 否 | 纪念日卡片数组 |
| `idle` | number | — | **已废弃**，传了忽略 |

**校验规则**

| # | 规则 | 违反时 |
|---|---|---|
| 1 | `timeZone` 必须是合法 IANA 名 | `4000` |
| 2 | 间隔模式：`600 ≤ timingTime ≤ 86400` | `4000` |
| 3 | 固定模式：`1 ≤ updateDays ≤ 365`，`updateTimeList` 至少 1 个 | `4000` |
| 4 | 时间格式 `HH:mm`，`endTime` 额外允许 `24:00` | `4000` |
| 5 | 纪念日 `monthDay` 格式 `MM-dd` 且不可重复 | `4000` |

## 十、离线与通知

### 10.1 离线不补发

设备离线期间错过的轮播触发，**上线后不补发**，从下一个触发点开始正常轮播。

理由：播放索引在离线期间不推进，上线后取到的本来就是本该在错过时刻出现的那张图；补发只提前几秒，却要多刷一次屏。

### 10.2 新通知类型 `CAROUSEL_NOT_SENT`

到点该推送但设备不在线（或下发失败）时生成通知并通过 WS 推送。

| 字段 | 值 |
|---|---|
| `category` | `BUSINESS` |
| `type` | `CAROUSEL_NOT_SENT` |
| 标题 | 轮播未发送成功 |
| 内容 | `18:00 的轮播图片未发送成功，请检查设备网络状态` |
| 节流 | 间隔模式：每 6 小时最多 1 条；固定模式：**每个时间点最多 1 条** |
