## 一、轮播选图上限：100 张

服务端已把轮播选择上限从 200 调整为 **100**。

- `POST /api/device/strategy` 的 `imgUrls` 超过 100 个返回 `4000`。
- 投屏时 `addToCarousel=true` 追加后超过 100 个，不再追加，投屏仍成功，返回 `carouselUpdated=false`。
- `GET /api/device/strategy` 返回的 `imgUrls` 不会超过 100 个。

前端要求：

1. 轮播设置页在选图区域显示 **“已选 X/100”**。
2. 选满 100 张后：
   - 未选中的图片置灰或点击时提示「最多选择 100 张，请先取消部分照片」；
   - 已选中的图片仍然可以取消。
3. 全选时如果相册超过 100 张，只选中前 100 张，并提示「最多选择 100 张」。

期望结果：

- [ ] 选到 100 张时计数显示 `100/100`，继续选择被拦截并提示。
- [ ] 取消一张后可以继续选择。
- [ ] 超过 100 张提交时接口返回 `4000`，前端有明确提示。

## 二、投屏“同时加入轮播”

### 2.1 背景

设备已经开启轮播时，用户在投屏预览页再投一张图，默认只显示这一张，**不会自动加入轮播名单**；下一个轮播周期会切回原名单。

### 2.2 接口参数

```
POST /api/device/play
Content-Type: multipart/form-data
Header: userToken

新增参数：
  addToCarousel  Boolean  选填  是否把本次上传的图片加入当前轮播选择，默认 false
```

- 与 `refresh` 独立：
  - `refresh=true&addToCarousel=true`：立即显示并加入轮播；
  - `refresh=false&addToCarousel=true`：只上传并加入轮播（批量上传时用）。
- 设备**未开启轮播**时，服务端忽略该参数，不报错。

### 2.3 返回字段

投屏返回新增：

```json
{
  "code": 0,
  "data": {
    "msgid": "1729384756123042",
    "binUrl": "https://.../a.bin",
    "binSize": 2457600,
    "status": "SENT",
    "carouselUpdated": true
  }
}
```

| 值 | 含义 |
|---|---|
| `null` | 没传 `addToCarousel`，不涉及轮播 |
| `true` | 已加入轮播；或轮播全部相册，已清缓存，App 写相册记录后生效 |
| `false` | 未加入：未开轮播、设备锁冲突、选择已满 100、选择数据异常等 |

### 2.4 前端交互

1. 进入投屏预览页时，调 `GET /api/device/strategy?deviceNo=`，判断 `running`。
2. `running=true` 时显示“同时加入轮播”开关/勾选项；`running=false` 不显示。
3. 默认关闭；用户打开后，投屏请求带 `addToCarousel=true`。
4. 投屏结果页：
   - 正常提示「设备即将刷新」；
   - 如果 `carouselUpdated=false`，在下方追加一行：
     **「未成功加入轮播，请前往轮播设置添加」**。
5. `carouselUpdated=true` 不需要额外提示。

### 2.5 服务端行为（上限 100）

| 轮播状态 | `addToCarousel` | 服务端动作 | `carouselUpdated` |
|---|---|---|---|
| 未开启 | `true` | 忽略，只按普通投屏处理 | `false` |
| 运行中，已配置 `imgUrls` | `true` | 把本次 `binUrl` 追加到末尾，去重，最多 100 | `true` |
| 运行中，`imgUrls=null`（全部相册） | `true` | 不改选择；清 playlist 缓存，App 写相册记录后生效 | `true` |
| 运行中，`imgUrls=[]` | `true` | 把本次图片加为第一个选择 | `true` |
| 运行中，该 URL 已在选择里 | `true` | 不重复追加，只清缓存 | `true` |
| 运行中，选择已满 100 | `true` | 忽略追加，投屏照常成功 | `false` |
| 锁冲突/数据库失败 | `true` | 忽略追加，投屏照常成功 | `false` |

补充：

- App 必须把这张图写进老服务相册记录，否则 `/device/playlist` 不会返回它，即使已经写进 `selected_images`。
- 追加成功后，设备下一次拉 `/device/playlist` 时包含新图；不会额外下发 `play` 之外的指令。

期望结果：

- [ ] 未开轮播时不显示开关。
- [ ] 开关开启后投屏，`GET /strategy` 的 `imgUrls` 末尾出现本次图片 URL。
- [ ] 重复投同一张并勾选，`imgUrls` 不重复。
- [ ] 选择已满 100 时勾选投屏，结果页显示「未成功加入轮播，请前往轮播设置添加」。
- [ ] 开关关闭时投屏，`imgUrls` 不变。

## 三、轮播中删除当前图

### 3.1 服务端做法

轮播中平台通过**设备下载记录反推当前图**：

- 设备从反代下载 `/oss/wififile/{deviceNo}/xxx.bin`，服务端记录最后一次成功下载的图。
- 删除时比较被删 URL 与反推的当前图：
  - 一致且传了 `nextImageUrl` → 自动 `play` 下一张；
  - 不一致 → 只删文件，不切图；
  - **获取不到当前图 → 不切图**，只删文件。

同时，删除后服务端会把该 URL 从轮播选择 `selected_images` 中移除，避免轮播时拉到已删除文件。

### 3.2 前端“我的上传”提示

因为反推可能拿不到当前图（设备批量下载、缓存、下载失败等），前端需要在“我的上传”删除流程里加一句友好提示，让用户知道可以自己处理：

建议文案（删除确认弹窗或删除成功提示）：

> **若相框未更新，请手动切换或重新设置轮播。**

也可以拆成两句：

- 删除前：「删除后相框可能需手动切换才会更新。」
- 删除后：「已删除；若相框未更新，请手动切换或重新设置轮播。」

前端不需要判断当前图，也不需要改变删除接口调用顺序（先删老服务记录，再调 `/api/device/photo/delete`）。

期望结果：

- [ ] 能反推当前图时，删除当前图后设备自动切下一张。
- [ ] 反推不到当前图时，删除成功但设备不切图，页面提示用户手动切换或重新保存轮播。
- [ ] 删除后 `GET /strategy` 的 `imgUrls` 不再包含被删 URL。

## 四、已知限制

- 轮播选择最多 100 张；`addToCarousel` 追加满 100 时返回 `false`。
- `carouselUpdated=false` 可能是未开轮播、锁冲突、选择已满或数据异常，前端统一提示「未成功加入轮播」即可。
- 下载反推依赖设备“每次切图下载一张、成功后才显示”；如果设备批量下载或使用缓存，反推会拿不到当前图，此时按“不切图 + 前端提示”处理。
- 设备是否在下一个周期立即拉列表，取决于固件；如果实际只在收到 `strategy_bin` 时拉一次，需要重新保存轮播才会生效。
